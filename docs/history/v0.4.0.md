Kikoto v0.4.0 makes Fetch publication safer with owned roots and a flatter
default layout, adds configurable visual styles, and refines creator browsing
and mobile navigation.

## Library And Work Detail

- Standardized Library, Favorites, Circle, and Voice actor work collections on
  one responsive grid with shared column settings. The previous Masonry mode
  has been removed so card ordering, loading height, and controls stay
  consistent across surfaces.
- Made mobile collection pagination and options more compact. Favorites,
  Circles, and Voice Actors move secondary filters, sorting, page size,
  columns, and selection controls into focused mobile menus while wide layouts
  retain inline controls.
- On narrow screens, audio-row lyrics are available from the More actions menu
  instead of occupying a separate fixed-width action button. Desktop keeps the
  direct Lyrics shortcut, and the existing lyrics selection and preview flow is
  unchanged.

## Creators And Mobile Navigation

- Simplified Circle detail around its available-work state and catalog. Common
  refresh actions stay in the summary, advanced refresh modes use an anchored
  popover, and mobile catalog options move into a dedicated sheet.
- Refined Voice actor detail with compact works, playable, local, and remote
  counts. Alias review and Remote Sources now sit beside Favorite and open in
  bounded anchored popovers.
- Treats mobile detail Back controls as Up navigation within the active bottom
  destination: Work, Circle, and Voice actor detail return to their last
  server-and-user-scoped list location instead of looping through another tab.
  Wide layouts retain source-aware history returns.
- Sized mobile search and modal layers against the visual viewport. During text
  entry, the Android shell resizes for the keyboard and the frontend hides the
  bottom navigation and player surfaces so focused controls remain visible.

## Appearance

- Added Anthropic-, OpenAI-, Apple-, and Google Material-inspired visual
  presets that tune typography, density, radius, elevation, icon weight, and
  motion through shared semantic tokens.
- Added independent Original, Graphite, Cobalt, and Iris color palettes. Light,
  dark, and system mode remain separate, while feedback and age-rating colors
  keep their semantic meaning across every combination.
- Unified Mode, Style, and Color controls under Appearance in the header and
  Settings, and refreshed the browser, PWA, and Android application icons.

## Sources And Remote Fetch

- Added ownership for source-separated Fetch roots: Kikoto writes a machine
  marker and multilingual `README.md`, excludes claimed roots from the native
  folder watcher, and registers Fetch publication directly.
- Non-empty unclaimed roots, roots claimed by another source, and invalid
  markers are blocked and shown in Fetch review instead of being adopted
  silently. If a destination changes during submission, the plan is refreshed
  for review.
- Markerless roots from older versions can be recognized read-only only when
  same-source managed-folder records or successful Fetch history explain the
  complete visible structure. Unexplained entries, stale targets, links, and
  reparse points remain blocked; the next Fetch claims the root without
  overwriting an existing README.
- Changed the default Fetch layout to
  `/data/<source_code>/<code_prefix>_<code_group>/<work_code>`.
- `<source_code>` resolves to the stable file-source code. The historical
  `<source_name>` token remains accepted as an alias and existing per-source or
  saved templates are not rewritten.
- Fetch does not move existing four-level folders automatically. Deployments
  that still need those folders to be discovered should keep local scan depth
  at 4 in Maintenance or set `KIKOTO_LOCAL_SCAN_DEPTH=4` before upgrading.

## Metadata And Scans

- Reconciled local presence when a unique work folder moves, disappears, or no
  longer contains its stored local paths: old locations become `missing`
  without deleting files, and the detailed media tree is rebuilt lazily when
  the work is opened. Duplicate-code folders remain in review, and Fetch
  ownership records are left unchanged.
- Set the default local scan depth to 3 across Compose, configuration examples,
  the backend fallback, and Maintenance so the default Fetch layout is found
  without an extra directory level.
- Existing saved scan-depth settings are preserved during upgrade. New
  deployments and databases without a saved value use 3; existing deployments
  adopt it only after setting Local scan depth to 3 in Maintenance.
- Aligned scanning, search, routes, and workflow inputs with the documented
  `RJ`, `BJ`, `VJ`, and `CC` work-code format of 5 to 8 digits, preventing
  shorter or partial numeric matches from being treated as work identities.
