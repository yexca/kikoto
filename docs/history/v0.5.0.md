> [!IMPORTANT]
> **Existing-library metadata refresh.** v0.5.0 changes how DLsite metadata is
> fetched and stored. The upgrade migration preserves existing snapshots and
> builds the new projection from data already present, but it does not
> re-fetch every older work in every language. When upgrading an existing
> database from a version older than v0.5.0, start the application and then
> run the complete **Sync work metadata** workflow from **Workflows**. This
> refresh is required for existing works to receive the new multilingual
> metadata. A local library scan alone is not sufficient.

Kikoto v0.5.0 improves localized metadata, library workflows, access
controls, and fresh-install database startup while preserving the immutable
numbered migration path for existing libraries.

## Library And Work Detail

- Favorites distinguish the system Marked list from ordinary user-created
  lists, preserving existing explicit favorites during the upgrade.
- Library, Favorites, Circle, and Voice surfaces now share responsive toolbar,
  page-size, filter, and mobile navigation patterns. Browse workspaces persist
  across navigation, and mobile detail Back actions return to the prior list
  context.
- Recommendation ordering adds a seeded discovery boost and result variation
  within the existing listening-state mix, while keeping each client session's
  ordering stable and explainable.

## Sources And Remote Fetch

- Remote browsing now keeps source-scoped workspaces, supports explicit bulk
  selection, and shows bounded unavailable states with retry actions.
- Source synchronization and tracking are separate actions: syncing refreshes
  the source snapshot and directory tree without implicitly marking a work as
  tracked, while Track explicitly persists the source relationship for the
  Tracked view. Untracking removes that relationship and its cache while
  preserving the unified work, metadata, user state, and local files.
- File cleanup targets concrete cache or local locations, while forgetting an
  unlinked work is a separate confirmed database cleanup action. Cleanup runs
  remain recoverable and retain their workflow association.

## Metadata And Localization

- DLsite metadata retains the provider-declared edition language separately
  from the request locale, with a queryable localized title and tag projection.
  Work detail now keeps metadata-language selection separate from
  directory-edition availability.

## Accounts And Access

- Accounts can store an interface-language preference independently from the
  browser default.
- Production now requires sign-in by default. Super administrators can enable
  audited, read-only anonymous Library and playback access under
  `Maintenance -> Access`.
- Demo remains isolated and server-state read-only, while browser-local
  appearance controls remain available.

## Workflows And Operations

- Local folder watching defaults to incremental scans that reconcile affected
  work folders after filesystem changes, with configurable full-scan mode and
  automatic full-scan fallback for watcher recovery cases. Startup and manual
  scans remain full scans and can optionally queue a separate metadata run.
- Availability Watch is now one instance-level workflow with a shared target
  pool and a safe migration path for prior per-user configurations.
- The notification center supports pagination and clearing completed
  remote-operation notifications. The About page can report a newer GitHub
  release.
- New installations use `baseline/032_v0.5.0.sql`; existing databases continue
  through numbered migrations `028` through `032` without reconstructing user
  data from the baseline.

## Known Issue

- Android 10 APK builds can leave a large system-rendered gap when the software
  keyboard opens because of an upstream Capacitor insets issue. Browser use is
  unaffected; use Kikoto in a browser on Android 10 until the upstream fix is
  available.
