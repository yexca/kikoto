Kikoto v0.3.1 strengthens remote-source security and Fetch recovery while
improving library, workflow, playback, and mobile-navigation reliability.

## Library And Work Detail

- Added file-source filtering to Favorites and aligned list actions across
  collection surfaces.
- Prioritized listening intent in recommendations and kept lyrics attachments
  folded into their corresponding audio rows.
- Improved progressive loading, creator collection stability, remote catalog
  behavior, and sparse language-edition handling.

## Sources And Remote Fetch

- Added shared outbound-request enforcement for origins, redirects, DNS-pinned
  connections, response bounds, and configurable per-source host policies.
- Added byte-level Fetch progress, bounded transfers, recoverable staging
  cleanup, and review paths for blocked remote origins.
- Consolidated compatible remote catalog and content handling without changing
  the boundary between metadata sources and file sources.

## Metadata And Scans

- Made metadata synchronization an independent workflow instead of part of the
  local library scan.
- Added an explicit disabled-by-default `Follow-up run` option for manual,
  Startup, and interval scans while keeping filesystem-triggered scans separate.
- Avoided rewriting unchanged party projections during metadata refreshes.

## Playback And Client State

- Preserved mobile tab routes, history, scroll state, and known work details
  across navigation and delayed media loading.
- Improved compact-player feedback, fixed-surface clearance, source fallback,
  and lyrics matching.
- Contained route-rendering failures inside the app shell so navigation and the
  global player remain available.

## Operations And Reliability

- Updated CI and release tooling to Node.js 24 and fixed audited frontend
  dependency advisories.
- Made the Demo Compose stack pull the published image by default and expanded
  synthetic-fixture guidance for public tests.
- Added migrations `023` through `025` for Fetch transfer state, remote-source
  outbound policy, and independent metadata-sync follow-ups.
- Stabilized workflow-canvas initialization and asynchronous player-layout
  coverage in Linux browser tests.
