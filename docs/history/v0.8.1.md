> [!IMPORTANT]
> **Upgrade notes.** Back up `config/` before upgrading. Keep the existing
> `data/` mount; the version upgrade does not require copying it.
> Existing v0.8.0 databases advance from schema 059 through numbered migrations
> 060–066; fresh installs use `baseline/066_v0.8.1.sql`. Do not replace an
> existing database with a fresh-install baseline.
>
> **User accounts lose remote actions.** Track, Fork, untracking, on-demand
> source checks, Fetch, and caching remote files now need the `remote:track`
> and `remote:fetch` permissions, which the User role does not have. Give
> accounts that should keep these actions the new Contributor role in
> Settings → Users. Admins and super admins are unaffected.
>
> **Source addresses are hidden by default.** Accounts without `sources:write`
> and signed-out readers no longer receive source addresses, work links on the
> source site, upstream file URLs, or addresses in workflow runs. Turn off
> **Hide addresses from accounts that do not manage sources** in Settings →
> Library if every account may see them.
>
> Migration 066 rebuilds the account table to accept the Contributor role;
> every account keeps its role, sessions, and personal data. Migration 062
> keeps existing playback progress and listening history and adds ordered
> cursors and per-day listening totals. Migration 063 queues a shared
> recommendation catalog instead of rebuilding scores during startup:
> browsing and playback work while it builds, and recommendation preparation
> offers Retry until the first catalog is published. Migration 064 removes the
> **Check source health** workflow and its triggers; past runs stay readable
> in Activity. Migrations 060, 061, and 065 add recommendation session data,
> library lyrics assignments, and Availability Watch family fields without
> rewriting existing rows.

> [!NOTE]
> Use `docker compose up -d --pull always` to upgrade the production stack;
> restarting a container reuses its installed image. Update `KIKOTO_IMAGE`
> first if it is pinned to an older release.

Kikoto v0.8.1 adds an iOS app, a Contributor role with separate remote
permissions, a library lyrics manager that can also download lyrics from a
remote source, durable playback reporting, and a listening dashboard.
Recommendations score remote works and explain themselves visually,
Availability Watch follows work families, and the Android and iOS apps gain
device privacy controls.

## Accounts And Remote Permissions

- Remote sources have their own permissions, and a Contributor role sits
  between User and Admin. `remote:track` covers Track, Fork, untracking, an
  on-demand source check, and a mark or list on a remote work that is not in
  the Library yet, which adds it there. `remote:fetch` covers Fetch and
  caching remote files, including caching while playing.
- Users keep browsing and playing remote sources and managing their own
  marks, lists, tags, progress, and history. The remote actions they lost stay
  visible and explain the missing permission before any dialog opens, and
  playback no longer asks the server to cache for them.
- Contributors have the User permissions plus `remote:track`,
  `remote:fetch`, and `workflows:run`. They can follow every run in Workflows
  and start, configure, and schedule only the workflows whose steps they are
  allowed to run: Fetch, the remote popular collection, bulk Track and Fetch,
  and Availability Watch.
- In Workflows, editing, switching off, or deleting a trigger needs the
  permissions that creating it needs. Only the account that started a run, or
  an administrator, can cancel or retry it or review its items; items that
  change local files need `downloads:manage`, and recovering stale runs needs
  `sources:write`.
- **Hide addresses from accounts that do not manage sources** in Settings →
  Library is on by default; covers and image previews for those accounts come
  through Kikoto.

## Lyrics

- **Manage lyrics** on a work's local source lists every local audio file
  with its lyrics choice. A user with library write access can assign any
  local lyrics file of the work, including translated lyrics whose names do
  not match the audio, or align a lyrics folder to the tracks by track number
  or position. Each row previews the first lines and warns when timed lyrics
  run past the end of the track.
- A saved assignment is shared by every listener and becomes the Auto choice
  in directory rows, the player, and the lyrics popover. A listener's own
  choice still takes priority, and name matching applies when neither exists.
- With a compatible remote source, **Manage lyrics** has a **From remote**
  tab for users who can download files. It lists the lyrics of one edition of
  the work's family, translations first, downloads the chosen `.lrc`, `.vtt`,
  `.srt`, `.ass`, and `.txt` files into a new folder inside the work folder
  without replacing anything, and assigns them to the chosen tracks.
- The lyrics icon on work cards is the captions icon used by the lyrics
  manager. It appears only when a track of the work has lyrics: a file
  assigned in **Manage lyrics**, or one that playback matches to the track by
  name. A readme, a script, or another text file that matches no track no
  longer shows it.
- LRC lyrics keep their timing past 99 minutes and accept an hour field.

## Work Detail And Library

- The metadata language menu on work detail offers one choice per display
  language instead of one per DLsite edition, and the metadata editor's source
  section lists the work family: each language edition with its kind, title,
  and library state, and the purchase bonuses linked to the family.
- A lone source is named in the directory header instead of a one-tab strip.
  The empty Tracked placeholder and disabled remote sources are hidden by
  default, several local file sources are told apart by name, and each viewer
  can set a source tab to auto, always, or never.
- Cover source marks show only exceptions by default, such as a warning or
  the other Library scope also holding the work. **Cover source marks** in
  Display options switches them between auto, always, and never in this
  browser.
- Narrow work cards, such as two mobile columns or six or more desktop
  columns, use tighter type and spacing. Personal tags lead a single tag row
  shared with DLsite tags, and the cover names only the first file source and
  counts the rest. A two-column phone card is about a fifth shorter.
- The add-to-list menu on every work card can create a list in place, as on
  work detail. Work detail can hide the folder column beside the directory
  and remembers the choice on the device.
- Fields that take several values, such as personal tags, metadata tags, the
  Availability Watch work list, extension exclusions, and folder routing
  keywords, turn typed or pasted lists into removable tokens.
- Age badges are searchable, the query editor offers rating categories, and
  Library search excludes with `-circle:` and `-va:` as it does with `-tag:`.
  A quoted phrase matches as a whole.
- Local lists and work links opened directly load with fewer waits.

## Playback And Listening History

- Playback progress and listening history share one 30-second report. An
  on-device outbox keeps unconfirmed reports across reloads and temporary
  failures without inflating listening time or play counts, and offline
  listening is recorded on the dates it happened.
- A personal-progress import protects its position from earlier offline
  reports, while later playback and backward seeks still update it.
- Settings → History becomes a listening dashboard: totals with derived
  figures, the activity chart, a ranked list of the most listened works with
  their share of the time, and a Rhythm panel with the current and longest
  listening streaks and the average per weekday. The full history lists works
  as compact rows with plays and the last listening date.

## Recommendations

- Recommendation badges show every scored work's score in the Library and on
  remote sources, including remote works that are not in the Library. Remote
  badges score the displayed page in one batch and appear progressively; a
  scoring failure keeps the cards available and offers a retry.
- The badge threshold setting becomes the highlight threshold: scores at or
  above it keep the emphasized badge, and lower scores appear muted.
- The score explanation shows the score on a gauge with the threshold marked,
  the score composition as one stacked bar, and ranking adjustments on a
  centered scale, and suggests favoriting or marking Relisten when no
  preference evidence exists yet.
- Recommendation settings preview an adjustable example work's score live and
  replace the advanced number fields with a proportional mix bar, a possible
  score range, and per-match step meters with sliders.
- Each listening lane shows candidates first, followed by every remaining
  matching work in a stable exploration order, and scores come from a shared
  catalog that updates in the background.

## Workflows

- Availability Watch treats a watched code as a work family. A run refreshes
  the family's DLsite metadata at most once a day, and the work becomes
  available when a remote source offers any of its language editions; Track,
  Fetch, and Open use the edition that was found. The Monitoring and Ready
  pools become one watch pool with a summary, quick entry of pasted codes,
  Not available and Available sides, two-step removal, and a view of each
  work's family.
- **Check works on a source** in Workflows → Remote asks one remote source
  whether library works exist there and records the result on each work. It
  checks the source's health first, runs manually or from Startup and
  interval triggers, and replaces **Check source health**; **Check health** in
  source settings is unchanged.
- Metadata sync Run options choose the works (all works, one circle, one
  voice actor, or selected codes), the metadata source, and whether to
  refresh everything or only missing and outdated metadata. Remote metadata
  fallback and purchase bonus linking are chosen per run and stored with each
  trigger.
- Bulk Fetch and Fork report how many works were queued, then the result when
  the run finishes. A trigger whose source is disabled can be switched off,
  and a cancelled workflow step reads Cancelled.

## Settings And Interface

- Settings → Library opens with a Libraries list of the local library and
  the remote sources, followed by the library settings.
- Settings on wide screens can show its tabs as a row above the content
  instead of the side column, and the Settings and Metadata rails name their
  tabs by default.
- Demo visitors can choose the preferred metadata language in the account
  menu. The choice stays in that browser.
- On phones, bottom sheets and tall dialogs stay below the status bar and
  notch, horizontal strips no longer swallow page swipes, text fields no
  longer zoom the page on focus, and a Library page change returns to the top
  reliably.
- Password managers no longer fill the administrator's sign-in into the
  create-user dialog or offer to save another user's or a proxy's
  credentials, and they stop prompting while a password is being typed.
- About groups its reference projects by what they informed and lists the
  iOS app's technologies.

## Android And iOS Apps

- Kikoto has an iOS app. Each GitHub Release attaches an unsigned
  `kikoto-<version>-unsigned.ipa` beside the signed APK; a sideloading tool
  re-signs it at install time. The app plays through the configured server
  with covers, seeking, and resume, goes back with a swipe from the left
  screen edge, keeps its session in the Keychain, and shows screen lyrics in
  a themed Picture-in-Picture window with progress and skip controls.
- **Privacy on this device** in Settings → Playback is stored for the device
  across every server and account. Recent apps and the iOS app switcher show a
  cover instead of the current page, the system media controls hide the
  cover, and playback through the device speaker waits for a confirmation
  when no headphones are connected. All three are on by default.
- An opt-in choice blocks screenshots, recording, and casting of the Android
  app and its floating lyrics; on iOS it covers the app and closes screen
  lyrics while the screen is recorded or mirrored. Android also offers an
  opt-in app lock that unlocks with a biometric or the device screen lock.
- Both apps pause when headphones or another external audio output
  disconnect. Disconnecting also closes the Android floating lyrics, and
  signing out or switching servers clears the Android app's web cache.
- The account panel and diagnostics name the platform the app runs on.

## Fixes

- A work with a `CC` code opens from its address, a refresh, or a bookmark,
  and a work that cannot be loaded shows a not-found or retry state instead of
  loading forever.
- Text files of a tracked remote work and of cached files open in the
  preview, and cached images display.
- Fetch treats two file names that differ only by letter case as a target
  conflict and refuses to publish fewer files than planned. A remote track
  title with path components such as `../` fetches under its normalized name.
- Requests for something that does not exist answer with 404 instead of a
  server or upstream error, and a remote source that reports "no such work"
  keeps its health status.
- Saving a settings section sends only that section, and whole-number
  settings no longer accept a fraction.
- A Kikoeru account import runs for its full three minutes, and a database
  upload has 15 minutes to arrive.
- The Favorites page lists every favorite circle and voice actor, the
  collapsed Workflows rail no longer flickers a scrollbar while a workflow
  runs, and several interface labels that showed their internal names are
  translated.

## Security And Reliability

- Outbound requests judge a NAT64 destination by the IPv4 address it embeds,
  so a hostname that resolves through the `64:ff9b::/96` prefix to a loopback
  or private address is rejected, and the IPv4-compatible and
  IPv4-translated IPv6 ranges are treated as non-public.
- The Go toolchain, `golang.org/x/net`, and the SQLite driver are updated.

## Development And Docs

- The user guide and READMEs are translated in full, and reference docs
  describe only the current system.
- Development baselines of the unreleased schema live in
  `migrations/compat/` and are read only with `KIKOTO_MODE=development`. A
  development database created from one is recreated after this release.
- The release workflow builds the image, the signed APK, and the unsigned
  IPA, and publishes the draft only after all three succeed. CI splits
  validation into pull request and full tiers and runs only the jobs a changed
  path reaches.
