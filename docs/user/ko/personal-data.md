# 개인 데이터

[English](../en/personal-data.md) · [简体中文](../zh-Hans/personal-data.md) · [繁體中文](../zh-Hant/personal-data.md) · [日本語](../ja/personal-data.md) · [한국어](../ko/personal-data.md)

로그인한 뒤 **설정**을 엽니다. 청취 기록은 **기록** 탭에, 개인 태그는 **태그**에 있으며, **내 데이터**는 **계정**의 마지막 섹션입니다. 아바타 뒤의 계정 메뉴와 빠른 작업에서 각각을 바로 열 수 있습니다. 이 화면들에는 사용자 계정의 데이터만 표시됩니다.

## 개인 태그

사용되지 않는 태그를 포함하여 작품, 서클, 성우 태그를 검색합니다. 이름 변경은 모든 지정에 반영됩니다. 병합은 지정을 기존 태그로 옮기고 중복을 제거한 뒤 이전 태그를 삭제합니다. 삭제는 작품이나 제공처 메타데이터를 삭제하지 않고 태그와 그 지정만 제거합니다.

새 워크플로 태그 기본값에는 날짜가 없으므로 반복 실행이 같은 태그를 재사용합니다. 이미 저장된 템플릿은 보존됩니다. 오래된 일정이 날짜가 붙은 태그를 더 이상 만들지 않게 하려면 워크플로에서 `{date}`를 제거하세요. 명시적인 날짜 템플릿은 계속 지원됩니다.

## 청취 기록

청취 보고서는 최근 30일, 최근 12개월 또는 전체 기간을 다룹니다. 선택한 범위에 대해 다음을 보여 줍니다.

- 청취 시간, 재생 횟수, 작품 수, 활동한 일수와 함께 활동한 날당 시간, 재생당 시간, 가장 많이 들은 작품이 차지하는 시간 비율, 범위 안에서 청취한 날의 비율.
- UTC 기준 일, 월 또는 연 단위 차트(전체 기간은 3년이 넘으면 연 단위로 전환)와 평균 및 가장 활발했던 기간.
- 가장 많이 들은 작품 5개(10개까지 펼칠 수 있음). 각 작품에 청취 시간과 해당 범위의 청취에서 차지하는 비율이 표시됩니다.
- 리듬: 청취한 날, 월 또는 연이 이어진 현재 기록과 가장 긴 기록, 그리고 요일별 평균 청취 시간(30일) 또는 청취가 있었던 월 수나 연 수.

가져온 합계에는 날짜가 없으므로 전체 기간에서만 집계됩니다. 전체 기록은 마지막 청취 시간 순으로 정렬되고 각 작품의 청취 시간, 재생 횟수, 마지막 청취 날짜가 표시되며, 보고서 아래에 접혀 있다가 열 때 불러옵니다. 시간은 일시정지, 버퍼링, 탐색 시간을 제외한 실제 청취를 측정하며, 속도 변경은 시간을 배로 계산하지 않습니다. 동시에 실행되는 플레이어는 각각 독립적으로 집계됩니다. 클라이언트 중단이나 연결 끊김으로 일부 시간이 보고되지 않을 수 있습니다.

기록은 지우거나 해당 계정/작품을 삭제하기 전까지 서버에 남습니다. 90일 후의 추천 이벤트 정리는 기록을 삭제하지 않습니다. 업그레이드해도 남아 있는 이전 재생 이벤트와 이어듣기 타임스탬프는 길이를 임의로 만들지 않고 보존되며, 이전에 삭제된 이벤트는 복구할 수 없습니다. 기록을 지워도 표시, 재생 목록, 이어듣기 진행 상황은 유지됩니다. 계정 카운터는 지우기 이전의 지연된 보고를 거부합니다.

## 내보내기 및 가져오기

Kikoto 개인 JSON 버전 1에는 작품별 청취 표시, 개인 평점/메모, 이어듣기 정보, 누적 청취 합계, 작품 태그 지정, 사용자 지정 태그 정의, 아이콘을 포함한 순서 있는 즐겨찾기 재생 목록이 들어 있습니다. 시스템의 표시됨 구성원은 표시에서 파생됩니다. 서클/성우 태그 정의는 포함되며, 그 엔티티 지정과 그 밖의 상태는 이 형식에 포함되지 않습니다.

미디어, 소스 설정, 엔드포인트, 인증 정보, 제공처 메타데이터, 원시 세션, 일별 통계는 제외됩니다. 트랙 제목과 트랙/디스크 번호가 이어듣기 대상을 식별하며, 로컬 경로와 소스 로컬 ID는 내보내지 않습니다.

소스(JSON 파일, Kikoeru 계정, Kikoeru 데이터베이스)를 선택한 뒤, 가져오기 전에 미리 보기를 실행합니다. 기존 데이터 유지는 개인 상태가 있는 작품을 건너뛰고 기존 재생 목록을 보존합니다. 덮어쓰기는 파일의 표시, 메모, 작품 태그, 일치하는 진행 상황, 같은 이름의 재생 목록으로 바꿉니다. 청취 합계는 최댓값으로 병합되므로 반복해서 가져와도 이중 집계되거나 측정된 청취가 줄어들지 않습니다.

기존 작품과 명확하게 알려진 별칭만 기본 코드로 일치합니다. 없는 코드는 목록으로 표시되며, 가져오기는 메타데이터를 가져오거나 작품을 만들지 않습니다. 없거나 모호한 트랙은 기존 진행 상황을 그대로 둡니다. 가져오기는 원자적으로 커밋됩니다. 한도: 10 MiB, 작품 20,000개, 태그 정의 5,000개, 재생 목록 1,000개, 재생 목록 항목 또는 작품 태그 지정 50,000개.

## Kikoeru

Kikoeru JSON 파일은 리뷰 배열, `reviews` 배열 또는 API `works` 배열을 받습니다. 한 계정의 데이터를 사용하고 원하는 모든 페이지를 포함하세요. 코드는 `primaryCode` 또는 `source_id`를 사용하며, 숫자 `work_id`/`id`는 상품 번호입니다. ID에 상품 유형을 인코딩하는 포크(유형 × 10¹² + 숫자이며, RJ, BJ, VJ, CC가 유형 0~3)는 디코딩됩니다. 상품 코드와 관련 없는 ID는 먼저 변환해야 합니다. 개인 `userRating`/`user_rating`과 `review_text`는 지원하며, 제공처 평점은 가져오지 않습니다.

**Kikoeru 계정**은 데이터를 대신 읽어 줍니다. 구성된 Kikoeru 호환 소스를 고르거나 서버의 API 주소를 입력한 다음, 없음(로그인을 끈 서버), 토큰, 또는 이름과 비밀번호로 로그인합니다. 서버는 `POST /api/auth/me`로 로그인하고 `GET /api/review`를 페이지 단위로 읽으며, Kikoeru 서버가 제공하는 경우 좋아요 및 표시 목록을 포함하여 사용자가 소유한 재생 목록도 읽습니다. 재생 목록이 없는 서버는 리뷰만 가져옵니다. 결과는 파일과 같은 미리 보기 및 가져오기 과정을 거칩니다.

**Kikoeru 데이터베이스 파일**은 오픈 소스 Kikoeru의 SQLite 데이터베이스를 최대 512 MiB까지 업로드하며, 지정한 계정의 리뷰만 읽습니다. 업로드는 최대 15분까지 걸릴 수 있습니다. 최근 쓰기가 포함되도록 Kikoeru가 멈췄거나 유휴 상태일 때 파일을 복사하세요. 이 데이터베이스에는 재생 목록이 없습니다.

토큰, 비밀번호, 직접 입력한 주소, 데이터베이스가 브라우저를 떠나기 전에 Kikoto는 위험을 설명하고 확인을 요청합니다.

- 인증 정보는 Kikoto 서버를 거칩니다. 해당 요청에만 사용되며 저장되거나 로그에 남지 않지만, 서버를 운영하는 사람은 이를 가로챌 수 있습니다.
- Kikoeru 서버에는 Kikoto 서버의 네트워크 주소에서 로그인한 것으로 보입니다. 제3자 사이트에서는 계정에 경고나 제한이 걸릴 수 있습니다.
- 토큰은 계정처럼 동작하며 오랫동안 유효할 수 있습니다.
- Kikoeru 데이터베이스에는 비밀번호 해시를 포함하여 그 서버의 모든 계정이 들어 있습니다. 업로드한 파일은 읽는 동안 임시 파일에 남아 있다가 읽은 직후 삭제됩니다.

이 요청은 리디렉션을 절대 따라가지 않으므로 인증 정보는 사용자가 선택한 주소에만 전달됩니다. 직접 입력한 주소는 관리자이거나 관리자가 **설정 → 라이브러리 → Kikoeru 계정 가져오기 → 모든 계정에 LAN 주소 허용**을 켜지 않는 한 공개 주소여야 합니다. 이 스위치는 로그인한 모든 계정이 서버가 로컬 네트워크의 기기에 연결하게 만들 수 있게 합니다. 사용할 수 있는 상품 코드가 없는 행은 건너뛰고 개수를 집계하며, 계정 또는 데이터베이스 읽기는 동시에 최대 두 개까지 실행됩니다.

| Kikoeru 진행 상태 | Kikoto 표시 |
| --- | --- |
| `marked` | 듣고 싶음 |
| `listening` | 듣는 중 |
| `listened` | 완료 |
| `replay` | 다시 듣기 |
| `postponed` | 보류 |
| 비어 있음 / null | 표시 없음 |

이 매핑은 업스트림 [Kikoeru review API](https://github.com/kikoeru-project/kikoeru-express/blob/unstable/routes/review.js)를 따릅니다.
