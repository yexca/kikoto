# 워크플로
[English](../en/workflows.md) · [简体中文](../zh-Hans/workflows.md) · [繁體中文](../zh-Hant/workflows.md) · [日本語](../ja/workflows.md) · [한국어](../ko/workflows.md)

워크플로는 백엔드 동작을 확인할 수 있게 합니다.

## 사용자 화면

- 워크플로: 프리셋 팔로우 워크플로를 포함한 기본 제공 정의이며, 트리거는 선택한 정의에서 관리합니다. 사용자 지정 워크플로 편집기는 없습니다.
- 맨 위의 상태 줄은 현재 실행 중인 작업과 진행 상황, 처리가 필요한 실행 수, 다음 예약 실행을 보여 줍니다. 처음 두 칸과 오른쪽 끝의 **활동**은 모든 워크플로를 다루는 데스크톱 패널 또는 모바일 시트를 열며, 다음 예약 칸은 해당 워크플로를 선택합니다. 활성 실행은 **처리 필요**와 **기록** 위에 나타납니다. 각 행은 상태, 실행 번호, 트리거, 경과 시간을 보여 줍니다. 목록 행과 **최근 실행**은 같은 패널 안에서 세부 정보를 엽니다. 시작 및 종료 시각, 소요 시간, 트리거, 단계, 후보, 실행 동작, 그리고 실행 이벤트의 접힌 **진단 로그**가 있습니다. **실행 기록으로 돌아가기**는 목록으로 돌아갑니다. 활동에는 자체 페이지가 없습니다. `/activity` 및 `/runs` 링크는 활동 패널이 열린 워크플로를 열고 링크된 실행을 선택합니다.

## 현재 동작

- **가져오기**에는 작품 코드 하나와 활성화된 호환 원격 소스를 위한 실행 옵션이 있습니다. **필터**에서 제외할 파일 확장자를 선택하거나 쉼표로 구분해 추가 확장자를 입력하세요. 기본적으로 제외되는 항목은 없습니다. **실행**은 가져오기 미리보기를 열며, 파일과 대상을 검토한 뒤 **Fetch 게시**를 누르면 실행이 대기열에 들어갑니다. 제외 설정은 언어 에디션을 전환할 때도 적용됩니다. 가져오기는 수동으로 실행되며 자동화 트리거가 없습니다.
- 로컬 스캔은 메타데이터 제공처를 기다리지 않고 폴더 탐색과 로컬 소스 존재 여부를 기록합니다. 메타데이터 동기화, 소스 사용 가능 여부, 원격 동기화, 캐시, 가져오기, 정리, 서클 새로 고침, 대량 원격 동작은 각각 별도의 워크플로 실행으로 기록됩니다.
- 모호하지 않은 로컬 작품 하나에 대해, 스캔은 폴더가 사라졌거나 저장된 경로가 더 이상 감지된 폴더에 속하지 않으면 이전 로컬 파일 위치를 누락으로 표시합니다. 파일을 삭제하거나 가져오기 소유권을 바꾸지는 않습니다. 이동된 폴더는 열 때 지연 색인되며, 코드가 중복된 폴더는 처리 필요에 남습니다.
- 노드 실행은 단계 수준의 진행 상황을 보여 줍니다.
- 후보는 검토할 수 있는 결과를 보여 줍니다.
- 처리 필요에는 사용자의 결정이 필요한, 해결되지 않은 후보가 있는 종료된 실행이 들어 있습니다. 일상적인 부분 완료나 건너뛴 결과는 기록에 남아 경고 상태, 요약, 이벤트를 확인할 수 있습니다.
- 헤더의 알림 센터는 **업데이트**(가져오기 같은 사용자의 완료 또는 실패한 워크플로 결과)와, 워크플로 운영자에게는 **처리 필요**한 실행을 보여 주며, 실행 중인 최신 작업이 둘 위에 표시됩니다. 가져오기 알림은 로컬 작품 상세를 열며 로그인한 사용자에 대해 독립적으로 닫을 수 있습니다. **활동 열기**는 전체 패널을 엽니다.
- 워크플로 목록은 모든 워크플로를 카테고리별로 묶어 고정된 순서로 보여 줍니다. 기본(로컬 스캔, 로컬 파일, 메타데이터 동기화), 수집(인기 컬렉션), 팔로우(프리셋 팔로우 워크플로), 원격(가용성 모니터링, 가져오기, 소스 상태 확인)입니다. 각 항목은 최근 실행의 상태와 시간을 보여 주며, 작은 아이콘이 활성화된 시작 시 트리거, 일정, 폴더 감시기를 표시합니다. 넓은 레이아웃에서는 선택한 워크플로 옆에 목록을 유지하며, 그 아래의 **탭 이름 숨기기**는 목록을 최근 실행의 점이 남는 아이콘으로 접고 **탭 이름 표시**는 다시 펼칩니다. 페이지는 이 선택을 기억합니다. 휴대폰에서는 목록이 첫 화면이며, 워크플로를 누르면 열리고 헤더의 뒤로 버튼이나 브라우저의 뒤로 가기로 목록에 돌아갑니다. 정의는 이 페이지에서 만들거나 편집하거나 삭제할 수 없습니다.
- 선택한 워크플로는 최근 20번의 실행을 요약합니다. 마지막 실행, 종료된 실행 중 성공한 비율, 일반적인(중앙값) 소요 시간, 다음에 자동으로 시작되는 시점(일정, 다음 서비스 시작, 폴더 변경, 또는 수동 전용)입니다. 이 실행들의 소요 시간을 오래된 것부터 보여 주는 막대 차트는 일반적인 성공을 중립적으로 두어 실패와 부분 실행이 눈에 띄게 하며, 막대에 마우스를 올리면 세부 정보가 나타나고 선택하면 실행이 열립니다.
- 처리 필요는 해결되지 않은 후보, 메타데이터 문제, 확인되지 않은 실패를 모읍니다. 기록된 문제를 해결하면 해당하는 전용 메타데이터 실행 안내가 사라집니다. 다른 실패는 남은 문제가 해결된 뒤 검토됨으로 표시할 수 있습니다. 이 확인은 사용자별입니다. 기록은 실패, 부분 완료, 취소된 실행을 포함하여 원래의 결과를 유지합니다.
- 메타데이터는 보류 중인 작품의 복구와 DLsite 프록시 바로가기를 담당합니다. 그곳의 메타데이터 동기화 바로가기는 여기의 기존 워크플로를 선택합니다.
- 기본 제공 로컬 스캔, 메타데이터 동기화, 원격 인기, DLsite 인기 워크플로는 편집 가능한 간격 트리거를 지원하며, 로컬 스캔과 두 인기 수집기는 시작 시 트리거도 지원합니다. 로컬 스캔은 원격 사용 가능 여부를 확인하거나 메타데이터를 동기화하지 않습니다. 수동, 시작 시, 간격 스캔에는 기본적으로 꺼져 있는 `후속 실행`이 있으며, 이를 켜면 스캔이 끝난 뒤 독립적인 메타데이터 실행이 대기열에 들어갑니다. 메타데이터 동기화에는 시작 시 트리거가 없으므로 스캔 후속 실행과 경쟁할 수 없습니다.
- 로컬 스캔에는 시작 시 트리거 하나와 고정된 폴더 감시기 하나가 있습니다. 새로 설치하면 둘 다 꺼진 상태로 시작하며, 라이브러리 설정에서 이를 켜도록 안내합니다. 감시기는 일시 중지하거나, 재개하거나, 증분과 전체 사이에서 전환할 수 있지만, 만들거나, 복제하거나, 변환하거나, 이름을 바꾸거나, 삭제할 수는 없습니다. 증분이 기본값입니다. 감시기는 탐색 디렉터리와 인식된 작품 루트 아래의 모든 하위 디렉터리를 등록한 뒤 새 디렉터리 트리를 동적으로 등록합니다. 마지막으로 관찰한 이벤트 후 5초를 기다리며, Kikoto의 스테이징, 백업, 휴지통, 선점된 소스별 가져오기 트리는 무시하고, 영향을 받은 작품 루트를 조정합니다. 삭제된 파일과 폴더는 `missing`이 되며 데이터베이스 레코드는 유지됩니다. 감시기 오류, 너무 큰 이벤트 배치, 루트 무효화, 중복 루트에는 자동으로 전체 스캔을 사용합니다. 가져오기는 자체 게시 위치를 직접 등록하며, 수동, 시작 시, 간격 스캔은 항상 전체 데이터 트리를 검사합니다. 활성 실행 중의 변경은 후속 스캔을 최대 하나만 만듭니다. 일시 중지된 동안의 이벤트는 버려지며, 오프라인 중의 변경은 시작 시 스캔에 의존합니다.
- **로컬 작품 파일 새로 고침**은 로컬 스캔 다음 두 번째에 있습니다. 스캔이 이미 찾아낸 로컬 작품 폴더 안의 미디어 파일을 색인하므로, 작품을 열 때 큰 폴더를 필요에 따라 색인하지 않아도 됩니다. **증분**(기본값)은 파일이 한 번도 색인되지 않은 폴더만 다루고, **전체**는 사용 가능한 모든 로컬 작품을 다시 색인합니다. 한 번에 하나의 실행만 대기하거나 실행되며, 다른 실행을 시작하면 활성 실행을 반환합니다. 모드를 저장하는 시작 시 및 간격 트리거를 지원하며 기본 트리거 없이 제공됩니다.
- **소스 상태 확인**은 원격 아래, 가져오기 다음에 있습니다. API 엔드포인트가 있는 활성화된 각 원격 소스를 소스 설정의 **상태 확인**과 같은 방식으로 확인하고 정상인지 사용할 수 없는지 기록합니다. 결과는 설정 > 라이브러리의 소스 목록에 표시되며, 사용할 수 없는 소스가 하나라도 있으면 실행은 부분 완료가 됩니다. 실행 옵션이 없으므로 헤더에 `실행`이 표시됩니다. 시작 시 및 간격 트리거를 지원하며 기본 트리거 없이 제공됩니다. 실행하려면 소스를 관리할 권한이 필요합니다.
- 원격 및 DLsite 인기 수집 화면에서는 태그 템플릿을 현재 값 미리보기, 워크플로별 변수 전체 목록, 렌더링된 태그가 40자를 넘을 때의 명시적 경고와 함께 편집합니다. 수동 실행은 요청 시 템플릿을 확장하고, 자동 트리거는 템플릿을 그대로 저장하여 디스패치할 때 확장합니다. 수동 실행은 태그 지정을 끌 수 있으며, 그러면 태그 단계는 건너뛴 것으로 기록됩니다. 원격 자동 수집은 가져오기 크기와 디스크 예약 보호 장치를 우회할 수 없도록 추적 전용입니다.
- 실행 매개변수가 있는 워크플로는 요약 아래의 **실행 옵션** 양식에 이를 표시합니다. 양식은 `실행`이 있는 막대로 끝나며, `실행`을 사용할 수 없을 때는 필수 입력 누락 같은 이유를 표시합니다. 긴 양식을 스크롤하는 동안 이 막대는 휴대폰 탐색과 플레이어 위, 화면 맨 아래에 머뭅니다. 옵션은 다음 수동 실행에만 적용되며 다른 워크플로를 선택하면 초기화됩니다. 로컬 스캔은 그곳에 후속 실행 옵션을 표시하며, 실행 매개변수가 없는 기본 제공 워크플로는 대신 헤더에 `실행`을 표시합니다.
- 실행 모니터는 양식 다음에 트리거와 최근 실행이 이어집니다. 최근 실행의 단계와 로그를 보여 주며, 공간이 있으면 나란히 표시합니다. 실행이 활성인 동안 새 로그 줄이 스트리밍되고, 위로 스크롤하지 않는 한 로그는 최신 출력을 따라갑니다. 단계를 선택하면 그 줄만 표시하고, 실행 요약을 선택하면 해당 실행이 활동에서 열립니다.
- 가용성 모니터링은 저장된 구성을 유지합니다. **구성** 양식은 `실행`이 사용하는 저장된 값을 요약하며, `실행` 옆의 `구성`은 원격 소스, 사용 가능해졌을 때의 동작, 선택적인 가져오기 확장자 제외(활성화하기 전에는 꺼져 있음)를 위한 패널을 엽니다.
- 서클 팔로우, 시리즈 팔로우, 성우 팔로우(탭 **성우 팔로우**)는 프리셋 워크플로입니다. 실행 옵션은 세 섹션으로 구성됩니다. **입력**(대상과 카탈로그 새로 고침, 증분 또는 전체), **필터**(발매일 범위와 작품 수 제한), **작업**(메타데이터 동기화, 태그 템플릿, 서클의 경우 원격 소스 확인)입니다. 넓은 화면에서는 세 섹션이 열로 나란히 놓입니다. 트리거 팝오버는 기본적으로 이 값을 사용하며, 실행 옵션 사용자 지정을 켜면 재정의할 수 있습니다. 서클과 시리즈 대상은 쉼표로 구분된 ID를 최대 20개까지 받으며, 필터링 전에 그 카탈로그를 합칩니다. 성우 대상은 선택한 성우 한 명이며, 표시 이름과 확인된 별칭으로 확인한 원격 소스에서 해당 카탈로그를 새로 고칩니다. 시리즈는 저장된 작품을 읽으며 카탈로그 새로 고침이 없습니다. 메타데이터 동기화는 라이브러리에 아직 없는 작품을 포함하여 메타데이터가 없는 카탈로그 작품을 대상으로 하며, 필터와 태그는 그 작품들에 적용됩니다. 모든 필터는 기본적으로 꺼져 있습니다. 발매 범위나 작품 수 제한이 없으면 실행은 메타데이터가 없는 모든 카탈로그 작품을 동기화합니다. 태그 템플릿도 기본적으로 꺼져 있으며, 켜면 동기화된 작품에 태그를 붙입니다. 자동화된 팔로우에 필터가 없으면 트리거 팝오버가 경고하고 필터를 켜도록 권장합니다. 메타데이터 동기화를 끄면 서클 또는 성우 팔로우는 카탈로그만 새로 고칩니다(소스도 확인). 팔로우 워크플로는 추적하거나 가져오지 않으므로, 이를 위해서는 원격 인기, 가용성 모니터링 또는 작품의 상세 페이지를 사용하세요. 자동 실행은 증분 카탈로그 새로 고침을 사용하며, 전체 새로 고침은 수동 전용입니다.
- 재구성이 필요하다고 표시된 팔로우 트리거는 꺼진 상태로 유지됩니다. 이를 열어 실행 옵션을 확인하고 저장한 뒤 다시 켜세요.
- 메타데이터 동기화는 이미 라이브러리에 있는 작품을 새로 고칩니다. 실행 옵션에서 **작품**(모든 작품, 서클 하나, 성우 한 명, 또는 지정 작품), **메타데이터 소스** 탭, **새로 고침 대상**(누락되었거나 오래된 항목 또는 모든 메타데이터)을 선택합니다. 모든 작품과 지정 작품은 기본적으로 DLsite이며 메타데이터를 지원하는 활성화된 원격 소스를 선택할 수 있습니다. 서클은 DLsite만 보여 줍니다. 성우는 원격 소스만 보여 주며, 하나가 구성되어 활성화되기 전에는 사용할 수 없습니다. 지정 작품은 공백, 쉼표, 줄바꿈으로 구분된 기존 코드를 최대 100개까지 받으며 기본값은 모든 메타데이터입니다. DLsite를 선택하면 실행 옵션에 [원격 메타데이터 보완](settings.md#원격-메타데이터-보완)과 [구매 특전 연결](settings.md#구매-특전)도 표시됩니다. 이 선택은 해당 실행에 적용됩니다. 간격 트리거는 같은 옵션을 저장하고 재시도도 이를 유지합니다. 원격 새로 고침은 수동 편집과 DLsite 우선순위를 보존하며, 누락되었거나 오래된 항목은 선택한 소스의 메타데이터를 확인합니다. 지원되는 활성화된 원격 소스가 구성되어 있지 않으면 소스 선택기와 보완 컨트롤은 숨겨집니다.
- 워크플로는 기본 제공이며 사용자가 직접 만들 수 없습니다. 이전 설치에서 보존된 사용자 지정 워크플로는 라이브러리 설정 중에 검토하며, 프리셋과 정확히 일치하는 항목은 비활성 트리거가 될 수 있고 나머지는 내보낼 수 있습니다. [시작하기](getting-started.md)를 참고하세요. 이전 실행은 활동 기록에 남습니다.
- DLsite 인기 수집은 24시간, 7일, 30일, 연간 성우 순위를 지원합니다. 최근 기간은 30일 이내에 발매된 작품으로 제한할 수 있으며, 연간 실행은 연도를 명시적으로 선택하고 기본적으로 `{year}`가 들어 있는 템플릿을 사용합니다. 실행은 메타데이터를 동기화하고, 미리 본 사용자 태그를 기존 사용자 태그를 대체하지 않고 덧붙입니다.
- 대기 중이거나 실행 중인 가져오기는 표준 작품마다 하나뿐입니다. 반복된 가져오기 요청은 같은 작품을 두 번 내려받지 않고 해당 실행을 재사용하며, 요청한 모든 사용자는 공유된 실행의 종료 알림을 받습니다.
- 가져오기 활동은 바이트 단위의 원격 전송 진행 상황, 관찰된 전송 속도, 예상 남은 시간을 보고합니다. 크기를 알 수 없는 파일은 명시적으로 표시되며, 실제 크기를 알 때까지 백분율과 남은 시간 표시를 하지 않습니다.
- 가져오기 실행의 상세는 파일을 나열합니다. 내려받는 중인 파일은 자체 진행 막대와 함께 맨 위에 머물며, 전체 목록은 각 파일이 완료되었는지, 대기 중인지, 실행이 실패하거나 일시 중지된 지점인지 표시합니다.
- 각 가져오기 실행에는 `Fetch RJ00000001`처럼 작품의 이름이 붙으며, 활동 검색에서는 작품 코드로 가져오기를 찾을 수 있습니다. **가져오기** 탭은 가져오기 기록과 단계를 나열하지만 실행 양식은 없습니다. 가져오기는 항상 작품에서 시작합니다. 가용성 모니터링, 대량 동작, 인기 수집, 프리셋 워크플로가 대기열에 넣은 가져오기는 그 출처를 트리거 사유로 기록합니다.
- 스캔은 볼 수 없는 곳의 작품을 절대 누락으로 표시하지 않습니다. 마운트되지 않은 데이터 폴더나 오프라인 스토리지 풀, 또는 스캔 깊이보다 깊은 폴더가 해당합니다. 마운트되지 않은 표준 라이브러리의 스캔은 실패하고 아무것도 바꾸지 않으며, 오프라인 풀을 건너뛰는 스캔은 부분 완료로 끝나고 해당 풀의 이름을 알려 줍니다.

## 제한

- 재시도와 체크포인트 복구는 작업을 복구 가능하다고 명시적으로 선언한 워크플로 계열에만 적용되며, 임의의 실패한 노드를 단독으로 재개할 수는 없습니다.
- 워커는 Kikoto 프로세스 안에서 실행되므로, 대기 중인 작업은 해당 프로세스가 실행 중일 때만 진행됩니다. 분산 또는 다중 인스턴스 실행은 지원되지 않습니다.
- 정상적인 서비스 중지는 실행 중이던 복구 가능한 작업을 재시도 횟수를 소모하지 않고 대기열로 되돌립니다. 충돌, 강제 종료, 만료된 임대 이후의 복구는 각 작업의 재시도 횟수로 제한됩니다. 수동 오래된 실행 복구는 중단된 복구 불가능 작업을 확인할 수 있도록 실패로 표시합니다.
