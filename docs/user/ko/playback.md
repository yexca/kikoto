# 재생

[English](../en/playback.md)

재생은 전역 브라우저 오디오 플레이어가 처리합니다.

## 현재 동작

- 로컬 및 캐시 오디오는 HTTP range를 지원하여 브라우저의 기본 미디어 경로로 직접 제공합니다.
- 직접 디코딩에 실패하면 현재 트랙, 현재 큐 또는 이후 모든 로컬·캐시 재생에 대해 호환 재생을 선택할 수 있습니다. FFmpeg가 길이와 탐색 정보를 포함한 완전한 MP3 캐시 파일을 생성합니다.
- 첫 재생은 준비 완료를 기다리고 이후에는 캐시를 재사용합니다. 원본은 변경하지 않습니다. `/cache/transcodes/audio`는 비디오와 할당량을 공유하며 준비는 4분, 파일은 512 MiB로 제한됩니다.
- 호환되지 않는 로컬·캐시 비디오는 먼저 전체 길이와 HLS VOD 재생 목록을 생성합니다. 6초 H.264/AAC 세그먼트는 필요할 때 독립적으로 생성됩니다.
- 생성된 비디오 세그먼트는 `/cache/transcodes/hls`의 재생성 가능한 캐시이며 기본 LRU 할당량은 5 GiB입니다. 세그먼트는 16 MiB, 생성 시도는 2분으로 제한됩니다.
- Tracked 원격 및 미리보기 미디어는 설정된 소스 정책을 거쳐 backend가 기본적으로 변경 없이 프록시합니다. 원격 URL은 노출하지 않습니다.
- 준비된 오디오는 전체 길이, HTTP Range 탐색, 이어 듣기와 종료 후 다음 트랙 재생을 지원합니다. HLS 세그먼트는 불변이고 전체 VOD 타임라인에서 탐색할 수 있습니다.
- Docker 이미지에는 `ffmpeg`와 `ffprobe`가 포함됩니다. 다른 배포에서는 backend `PATH`에 두 바이너리를 제공해야 합니다.
- 재생 가능한 파일을 클릭하면 같은 폴더의 파일을 자연 정렬 순서로 큐에 넣고 선택한 파일을 처음부터 시작합니다.
- 작품 상세에는 Resume 동작이 있으며 완료되지 않은 양수 커서가 없으면 비활성화됩니다.
- 탐색 중에도 재생이 계속됩니다.
- 사용자별·서버별 브라우저 큐를 보존합니다. 저장된 작품 커서는 명시적인 Resume에서 적용되며, 새로고침 후 복원된 현재 트랙이 커서의 미디어 항목이고 완료되지 않았다면 그 위치에서 이어집니다.
- 트랙은 재생을 시작했거나 탐색한 뒤에만 진행 상황을 저장합니다. 그 전에 페이지를 숨기거나 화면을 잠그거나 트랙을 바꿔도 저장된 커서는 바뀌지 않습니다.
- 화면 가사는 페이지 밖에서도 현재 가사를 계속 보여 줍니다. 데스크톱 브라우저는 항상 위에 표시되는 PIP 창(브라우저를 최소화해도 표시)을, Android 앱은 Kikoto가 백그라운드일 때 떠 있는 가사를 표시합니다("다른 앱 위에 표시" 권한 필요).
- 플레이어 도크는 Mini, Compact, 전체 화면 상태와 큐, 탐색, 이전/다음, 건너뛰기, 재생 모드를 지원합니다. 속도·호환성 설정은 제목 옆 More 메뉴에 있습니다.
- 큐 행은 핸들을 드래그하거나 핸들에 포커스한 뒤 위/아래 화살표 키로 순서를 바꿀 수 있습니다.
- 재생 중인 곡이 끝나기 45초 전이거나 완전히 버퍼링되면 다음 곡을 미리 불러옵니다.
- 뒤로/앞으로 탐색 기본값은 10초와 30초이며 설정에서 1~300초의 정수로 변경할 수 있습니다.
- 모바일과 데스크톱에서 하단 공간을 확보하여 마지막 동작이 가려지지 않게 합니다. 모바일 컨트롤의 터치 높이는 최소 44px입니다.
- 브라우저 및 Android Media Session을 사용하며 접근성, reduced-motion, 안전 영역을 지원합니다.
