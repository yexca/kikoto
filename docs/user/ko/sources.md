# 소스
[English](../en/sources.md) · [简体中文](../zh-Hans/sources.md) · [繁體中文](../zh-Hant/sources.md) · [日本語](../ja/sources.md) · [한국어](../ko/sources.md)

소스는 파일이 어디에서 오는지를 설명합니다.

## 소스 유형

- 로컬 폴더 소스.
- Kikoeru 호환 원격 소스.
- 이전된 기존 레코드에만 사용하는 레거시 Number178 호환 원격 소스.

## 현재 동작

- 로컬 스캔은 구성된 데이터 루트 아래에서 지원되는 작품 코드 폴더를 감지합니다.
- 원격 소스 탭은 모든 결과를 가져오지 않고도 구성된 소스를 탐색합니다.
- 작품 상세는 백엔드의 통합 사용 가능 여부 확인을 사용합니다.
- 원격 동기화는 메타데이터와 소스 파일 트리를 통합 데이터베이스로 가져옵니다.
- 원격 캐시는 선택한 원격 파일을 캐시 루트 아래에 구체화합니다.
- 원격 가져오기(fetch)는 선택한 원격 파일을 로컬 데이터 트리로 옮겨 정식으로 보관합니다. 기본 레이아웃은 `/data/<source_code>/<code_prefix>_<code_group>/<work_code>`이며, 레거시 `<source_name>` 템플릿 토큰은 안정적인 소스 코드의 별칭으로 계속 허용됩니다.
- 소스별로 분리된 저장 템플릿을 사용하는 호환 소스는 기계용 마커와 다국어 `README.md`로 자신의 가져오기 루트를 선점합니다. 가져오기가 게시를 직접 등록하므로 이 루트의 파일 변경은 로컬 폴더 감시기를 작동시키지 않습니다. 일치하는 마커가 없고 이미 비어 있지 않은 루트는 가져오기 검토를 가로막는 충돌로 표시되며 자동으로 채택되지 않습니다.
- 이전 Kikoto 버전이 만든, 마커가 없는 루트는 같은 원본 소스의 활성 `managed_fetch` 폴더 위치, 또는 성공한 계획이 같은 소스와 대상 루트를 기록한 성공한 `remote_work_fetch` 실행으로 인식할 수 있습니다. Kikoto는 입증된 작품 하위 트리를 탐색하지 않고, 해당 과거 대상과 그 상위 경로에 대해 루트 전체를 검증합니다. 루트 수준의 일반 `README.md`는 허용되지만, 설명되지 않는 항목, 링크, 재해석 지점(reparse point), 대상이 없는 오래된 레코드는 루트를 계속 차단 검토 상태로 둡니다. 인식은 읽기 전용이며, 다음 가져오기가 마커를 쓰고 다국어 README가 아직 없는 경우에만 추가합니다.
- 캐시 및 로컬 삭제는 통합 작품이 아니라 구체적인 파일 위치를 대상으로 합니다. 혼합 선택은 복구 가능한 하나의 워크플로로 제출되며, 로컬 삭제는 작품 진행 상황과 청취 표시를 보존합니다.
- 원격 소스 목록 및 상세 페이지는 소스 범위의 보기로 유지되어야 하며, 통합 로컬 작품 상세 모델을 대체하지 않습니다.
- 호환되는 원격 작품 응답은 소스의 현재 `price`를 매핑합니다. 이 값은 가격 이력으로 저장되지 않으며 권위 있는 정가로 취급되지도 않습니다.
- 데모 모드는 원격 서버에 접속하지 않습니다. 유일한 원격 소스인 Remote Kikoeru는 허용된 로컬 작품 중 무작위로 선택한 것으로 프로세스 내에서 시뮬레이션되며, 라이브러리는 그 위에 이를 알리는 안내를 표시합니다.
- `kikoeru_compatible_number178`은 이전된 소스를 위해 어댑터를 유지하지만 새 소스 및 구성 시드 입력에서는 거부됩니다. 과거의 `kikoeru_compilable_number178` 철자는 자동으로 이전됩니다.

## 사용 가능 여부 확인

시작 시와 소스 변경 시의 일괄 확인은 먼저 관련 소스의 상태를 검증합니다. 프로브는 `/api/health`를 우선 사용하며, 상태 엔드포인트를 제공하지 않는 호환 소스에는 항목 하나를 요청하는 목록 요청으로 대체합니다.

관리자는 설정 -> 라이브러리에서 `POST /api/file-sources/{id}/health-check`로 같은 제한된 프로브를 수동으로 실행할 수 있습니다. 응답은 상태, 확인 시각, 소요 시간을 보고하며 구성된 업스트림 주소나 원시 업스트림 오류는 반환하지 않습니다.

소스에 연결할 수 없으면 Kikoto는 해당 일괄 확인 동안 그 소스를 사용 불가로 표시하고 작품별 확인을 건너뜁니다. 모든 후보 작품을 누락으로 표시하지는 않습니다.

## 다운로드 속도 조절

원격 다운로드는 구성된 지연 시간만큼 기다리고 일시적인 오류는 백오프와 함께 재시도합니다. 설정 -> 캐시 및 가져오기에서는 파일당 미디어 다운로드 크기 한도도 구성합니다. 기본값은 100 GB이고 허용 범위는 1~2048 GB입니다. 이 한도는 소스가 응답 크기를 선언하지 않더라도 가져오기와 재생 캐시 구체화에 적용됩니다. 원격 및 DLsite 표지에는 별도의 고정된 20 MiB 한도가 적용됩니다. DLsite 메타데이터 동기화도 제공처 상품 및 표지 요청에 구성된 기본 지연 시간과 백오프를 사용합니다.

소스가 속도 제한 또는 일시적 사용 불가 응답을 반환하면 Kikoto는 그 소스가 요구한 시간 동안 해당 소스로의 요청을 일시 중지하되, 설정 -> 캐시 및 가져오기의 **최대 백오프**를 넘지 않습니다. 해당 소스의 대기 중인 작업은 재시도 횟수를 소모하지 않고 일시 중지가 끝나기를 기다리며, 다른 소스의 작업은 계속됩니다.

가져오기 계획은 이미 완전하게 저장된 메타데이터와 캐시된 소스 사용 가능 여부를 사용합니다. 요청한 코드에 DLsite 스냅숏이나 에디션 관계가 없으면, 준비 단계에서 검토를 만들기 전에 제한된 범위의 대상 계열 동기화를 수행합니다. 대기 중인 가져오기는 제출 시 승인된 원격 트리를 재사용하며 같은 트리를 곧바로 다시 요청하지 않습니다. 로컬 등록에 성공하면 그 가져오기로 승격된 캐시 객체는 제거되고, 선택하지 않은 캐시 객체는 계속 사용할 수 있습니다.
