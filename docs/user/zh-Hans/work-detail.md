# 作品详情
[English](../en/work-detail.md) · [简体中文](../zh-Hans/work-detail.md) · [繁體中文](../zh-Hant/work-detail.md) · [日本語](../ja/work-detail.md) · [한국어](../ko/work-detail.md)

作品详情呈现一部作品的元数据、版本、文件树、来源可用性和播放操作。

## 多语言标题

编辑器的“标题”部分首先列出日语、简体中文、繁体中文、英语和韩语，每种语言各占一整行。原始语言带有 `origin` 徽章，当前显示的元数据语言带有 `current` 徽章；两者可以出现在同一行。**跨语言通用标题**位于它们下方的**高级标题选项**中，默认折叠。已存在通用标题时，这些选项会自动展开，以便编辑或清除。提示说明了通用标题会在所有语言中覆盖提供方标题，而各语言的手动标题优先于它；版本和简介保持不变。某一行自己的手动标题是可编辑的文本；提供方标题和继承来的标题则显示为灰色提示，并且绝不会原样保存。每一行都会标明其当前来源，并标出手动标题或已编辑的标题。保存只会发送改动过的字段和标题语言；清除已有的手动标题，或在该行选择“还原”，会在保存时移除该范围的标题，而清除继承来的提示则不会产生任何改动。同一个编辑器也可以从“元数据 → 作品”打开。

元数据语言菜单包含已知版本、按语言设置的人工标题，以及标为 **LLM** 的已接受翻译。LLM 选项只改变同一作品的元数据展示，不增加官方版本或媒体版本。原文回退保留提供方声明的原始语言，包括未知语言。优先级见[标题与描述规则](../../architecture/data-model.md#manual-overrides-and-titles)。

当 DLsite 没有某部作品的记录而由远程来源补全时，详情提示会显示**已由远程来源补全**，并列出每个来源补全了哪些值。远程标题在标题顺序中排在 DLsite 之后、作品自己的标题之前。它不声明语言，因此不会增加语言选项，其文字也保持不变；标题编辑器会标明它的来源。

在提供方的显示中，作品族里任何非原始的版本都是翻译，包括第三方翻译。只有开头的一个 DLsite 语言版本标签（例如 `【简体中文版】` 或 `【ドイツ語版】`）会按其格式被移除。诸如 `【ASMR】` 这样的标签、位于中间的标签和手动标题都保持原样。每个版本条目都保留自己的标题，包括不受支持的语言。提供方的原始标题和快照保持不变。卡片、详情、语言选项、搜索结果和新的播放队列共用这一显示规则；所有手动标题都仍可被搜索。简介会作为纯文本原样渲染，并跟随所选版本。没有对应版本的手动语言会使用原始简介。

## 编辑元数据

预览还可以按稳定的标签 ID 合并当前标签和拉取标签；接受 DLsite family 需要单独操作，普通字段保存不会把同族版本加入媒体库。

这次拉取仅作为比较预览，不会立刻写入提供方快照。点击**编辑拉取**会显示当前值、拉取值和预计保存三列；语言范围按实际版本显示，原始版本标记为 Original。直接使用拉取值会接受提供方元数据并清除旧的手动覆盖；修改预计保存值才会保存为手动覆盖。预览过期或作品在此期间发生变化时，保存会被拒绝。

顶部信息区（Hero）的**元数据**按钮会直接打开编辑器。**刷新元数据**位于左下角，执行常规的 DLsite 刷新。当某个已启用的远程来源支持元数据时，旁边的箭头会打开 `来自 <来源名称>` 的选项。选择其中一项，会向该来源为这部作品请求最新的元数据；手动编辑和 DLsite 的值保持其优先级，未保存的编辑器草稿也保持不变。这种显式刷新不要求开启自动的远程回退。

Admin 和 super_admin 可以凭 `library:write` 编辑作品元数据。保存只会发送相对于编辑器初始值改动过的字段；仅选择封面会保留自动得到的标题、社团、系列和声优信息。清除某个字段只会重置它自己的覆盖设置。升级时，已存在的、与同一作品族中某个去除首尾空白的 DLsite 标题完全一致的冻结标题覆盖会被移除；社团、系列和声优的覆盖则会保留。

编辑器把字段分为标题、封面、标签、制作信息和元数据来源几个部分；带圆点的部分表示有未保存的改动，页脚会列出它们。所有改动在保存之前都只是草稿，包括对手动设置的社团、系列、声优列表或封面执行“还原”，以及新增或移除的元数据链接，因此在各部分之间切换绝不会丢失编辑。取消时会先询问是否放弃草稿。社团、系列和声优会提供关联已知条目的建议；它们的标识符会显示在名称下方，并可在“编辑 ID”下继续编辑。封面从该作品本地图片的缩略图网格中挑选。Ctrl+Enter 可保存。

各部分上方的**元数据语言**标签栏用于选择编辑器显示的语言：**所有语言**，然后是日语、简体中文、繁体中文、英语和韩语，无论作品是否有对应语言的版本。**更多**会展开作品在其他语言中的版本，包括未声明语言的原始版本；选择其中一项后，该标签页被选中并显示所选语言，例如 `更多 - 德语`。标题和标签名称只能保存为上述五种语言，因此“更多”下的版本显示来源提供的标题和各标签的默认名称。在五种语言之一下，标题部分只显示该语言的一行，标签部分用该语言的名称显示每个标签；没有该语言名称的标签会以灰色显示回退后的名称，其语言按钮只打开该语言的名称和所有语言通用的名称。作品族列表显示所选语言的版本。作品拥有哪些标签、封面和制作信息在所有语言中都相同。

“标签”部分可以搜索共享的元数据标签，为这部作品添加或移除它们，并且即使作品没有 DLsite 元数据，也可以创建自定义标签。“恢复 DLsite 标签”会清除该作品的标签添加/移除。共享名称跟随你的优先元数据语言，使用手动名称和已学习的类型名称；仅有日语的作品可以显示已知的中文标签名称。后台更新完成后，被隐藏的标签在任何地方都不会出现。个人的“我的标签”是单独的、归账户所有的标签。演示模式下，编辑器为只读。

作品的标签以列表形式显示在“添加标签”输入框下方，每个标签占一行，下方列出它在其他语言中的名称；添加到本作品的标签带有**已添加**标记。每个标签的语言按钮会在该行内打开它在所有语言下的名称，其中全语言名称和每种受支持的语言各占一行：手动名称是可编辑的文本，提供方名称或已学习的名称则保持为灰色提示。标签名称是共享的，因此重命名的标签会在所有拥有它的作品上改变；面板会显示有多少部作品共用它。新的自定义标签会把输入的名称保留为其全语言名称，并且可以在创建之前为其他语言添加名称。名称编辑与其他改动一样都是草稿，会在你保存时写入。

新的自定义名称在“保存”创建或复用共享标签并在同一个事务中将其附加到这部作品之前，一直只是草稿。取消不会留下任何共享条目。去除首尾空白并忽略大小写后与任一已知语言的名称匹配时，会复用该标签，因此重复点击和重名不会产生重复的概念。

切换元数据语言时，会在可用的情况下使用该版本的手动标签名称或词典标签名称，否则回退到你的优先语言。每个版本显示的标签都相同，均取自原始版本，因此切换只会重命名标签，而不会增加或减少任何标签。添加、移除、按最终目标隐藏和合并映射仍然适用。仅存在于快照中的标签会保持可见，直到它们自己的投影完成；移除所有标签会得到有意为之的空显示。

仅有日语的作品，在后台**学习标签名称**工作流学到这些名称之后，会以优先语言显示其标签；在此之前，标签会回退为日语名称。它的标题仍是日语。

自动补全会把已合并的名称显示为其最终标签。被隐藏的匹配项（包括合并到被隐藏的目标）会带有标注且无法添加；请先在“元数据”中取消隐藏它。名称遵循[设置](settings.md)中所述的语言优先顺序。

在后台更新完成之前，作品会保留其最后保存的标签集合（包括空集合），即使元数据已刷新。声优页面的远程作品列表，会在手动添加的共享标签旁边显示远程标签。

## LLM 翻译

评估同时检查人工标题和描述；人工年龄分级不能降低原始限制。

拥有元数据同步和作品写入权限的编辑者可从元数据编辑器打开 **LLM 翻译**，选择已配置模型、目标语言和发送字段。**仅预检，不发送内容**检查原始标题、描述及保留的标签风险证据。结果显示分级、命中字段和规则身份，不联系 LLM。规则及端点边界在 [Settings → LLM](settings.md#llm) 配置。

同步预览有效期为 15 分钟，后台预览为 24 小时；预览跨重启保留，并绑定发起用户和作品。接受时重新检查源内容、当前权限、策略版本及模型配置；发生变化时预览失效。审核列表显示待确认、已接受、已拒绝和已过期状态。已确认的标题和描述独立保留 LLM 来源，不覆盖提供方快照或人工覆盖。普通同步保留译文；原始字段变化时仅使对应译文失效。**撤销**从展示中移除译文，**恢复**仅在源输入仍一致时复用记录。

**共享标签名称**只翻译已有共享标签概念缺少的语言名称，跳过已有人工名称、提供方名称和可复用的已接受译名。确认会影响其他作品中的共享名称，但不改变标签 ID 或作品成员关系。人工和提供方名称优先；名称修改、隐藏和合并不会抹去保留的风险证据。

歌词在[管理歌词 → 翻译](#翻译)中翻译。

**提交后台翻译**接受 1–100 个明确填写的已有作品。相同提交复用持久化任务，Activity 展示进度、取消、重启恢复和失败。执行时重新检查权限、输入、策略及选定端点，并保留已完成分块。明确拒绝及发送前失败可显式重试同一端点。上游结果不确定时停止自动发送；**重新发送结果不确定的请求**要求明确接受可能重复计费。端点、模型、策略或内容改变后禁止这种重新发送。结果始终等待人工审核。

## 转写

**管理歌词 → 转写**用已配置的[语音识别服务](settings.md#语音识别)，把本地音轨中的语音转为带时间轴的歌词。选择音轨、服务和语音语言，然后点击**转写**。语言会作为提示发送给服务，结果以该语言保存并指定；**自动检测**由服务自行判断，结果保存为适用于所有语言的歌词。内容安全策略与 LLM 翻译相同：敏感作品只能发往明确允许接收的私有服务，分级未知或命中禁止规则的作品会被拒绝。**检测分级**不发送任何内容，显示作品的分级，并标出不能接收的服务；只有点击时才会检测。正在转写的音轨不会被重复加入队列。

转写是 Activity 工作流。Kikoto 自行解码音轨，并把 16 kHz 单声道音频分成每段最长五分钟发送；每段在其最后一分钟内最安静的位置切开，使切点落在词与词之间。每个完成的部分都会保留，工作流会在各部分之间把队列让给其他等待的工作，因此长音轨不会阻塞扫描或获取。发送每个部分之前，Kikoto 都会再次检查服务设置、内容策略、你的权限和音频文件是否未变化。重启中断的请求，或服务拒绝的部分，会使转写停止；在 Activity 中点击**重试**会从最后完成的部分之后继续，并重新发送被中断的部分。取消运行会使其停止。

完成的转写在标签页的列表中等待审核。**预览**用与其他歌词相同的时间检查显示开头几行。**添加到歌词**把它保存为 WebVTT 文件，放在音轨所在作品文件夹内该语言的歌词文件夹中，沿用音轨自身的路径，例如 `lyrics_ja/mp3/Track 01.vtt`，并指定给该音轨。同名位置已有不同的文件时，该文件会保留，转写则以带编号的名称保存在旁边。**丢弃**会放弃不需要的转写。如果添加到歌词未能完成，结果会保留，再次点击**添加到歌词**即可重试。

## 翻译

**管理歌词 → 翻译**用已配置的 [LLM 提供方](settings.md#llm)翻译作品的歌词文件。选择歌词文件、它所属的音轨、提供方和目标语言，然后点击**翻译**。选择文件时会选中它已指定的音轨，或名称匹配的音轨；不属于任何音轨的文件需要自行选择音轨。该音轨必须在作品文件夹中有本地文件，译文保存到该作品文件夹。远程歌词文件同样可选；翻译远程文件要求管理员启用并具备远程获取权限。内容安全策略与 [LLM 翻译](#llm-翻译)相同，并在发送任何内容之前检查完整歌词。**检测分级**不发送任何内容，对所选歌词文件执行这项检查，并标出不能接收的提供方；只有点击时才会检测。

翻译是 Activity 工作流，把歌词分成有大小限制的部分发送，并保留每个完成的部分。LRC、WebVTT、SRT、标准 ASS 对话和纯文本保留时间轴与字幕顺序，只翻译每行文本。输入和输出各限 128 KiB，源文件最多 4,000 行，每个文本行最多 4,096 字节。提供方拒绝的部分，或暂时不可用的作品文件夹，可在 Activity 中重试。重启中断的请求结果未知；确认可能重复计费后，**重新发送**会再次发送。歌词、提供方设置、内容策略或你的权限发生变化会使翻译停止，需要重新开始。

完成的翻译在标签页的列表中等待 24 小时，归发起人所有。**预览**用与其他歌词相同的时间检查显示开头几行。**添加到歌词**会再次检查歌词文件、策略和提供方，然后把译文保存到音轨所在作品文件夹内目标语言的歌词文件夹中，沿用音轨自身的路径和原文件的扩展名，例如 `lyrics_zh_hans/mp3/Track 01.lrc`，并以该语言指定给该音轨。原歌词文件不会被修改。同名位置已有不同的文件时，该文件会保留，译文则以带编号的名称保存在旁边。**丢弃**会放弃不需要的译文。如果添加到歌词未能完成，结果会保留，再次点击**添加到歌词**即可重试，且不会联系提供方。

## 购买特典

购买特典，例如早期购买特典（`【早期購入特典】`），是拥有自己文件的独立 DLsite 商品，但 DLsite 不会说明它属于哪部作品。元数据同步可以把它关联到其原作品（参见[购买特典](settings.md#购买特典)），媒体库编辑者也可以在编辑器“元数据来源”部分的**购买特典**下输入或移除原作品的编号。已关联的特典仍是一部独立的作品：它保留自己的标题、封面、文件、播放进度和媒体库卡片，并从原作品那里获得它所缺少的标签、声优和系列。它的详情会显示**特典所属**以及原作品，若原作品不在媒体库中，则显示原作品编号并附上 DLsite 链接；原作品的详情会列出媒体库中属于它的**购买特典**，包括关联到其作品族另一个版本的特典。原作品编号绝不会变成媒体库中的作品。移除关联还会停止对该作品的自动检测，下一次刷新会丢弃继承来的值。

## 当前行为

- 按作品编号加载，并解析已翻译的 DLsite 作品族路由。
- 显示封面、标题、编号、社团、标签、评分、声优元数据和 DLsite 链接。
- 显示一个逻辑作品族已知的语言版本。
- 将元数据语言选择器和目录版本选择器保持为作品编号旁两个独立的紧凑芯片。每个芯片显示其当前选择并打开各自的列表；原始目录版本显示为 `原版 · <语言>`。只有一个变体时，元数据芯片会变成只读标签。对于本地作品，元数据默认使用你的优先元数据语言；对于仅限远程的作品，则默认使用来源所描述的你的语言中的第一个，然后是该来源的回退语言。临时切换会改变显示的标题和标签名称，但不会被持久化。在配置的默认值保持选中时，原始变体始终排在第一位。
- 将目录版本视为文件可用性，而不是元数据可用性。在持久化的本地上下文中，折叠的选择器只显示拥有本地文件夹或本地媒体的版本；展开后则显示所有已知版本。只有当某个来源在其自己的数据库中报告了某个远程同级版本时，才能选择它；即使所选远程来源不包含该版本，本地可用的同级版本仍可通过其本地目录选择。远程上下文则默认采用来源报告的可用性。
- 显示仅有元数据、仅限远程以及不可用的版本，而不暗示可以本地播放。
- 先渲染由卡片提供或由编号解析出的预览，然后将基础详情和媒体树作为独立的阶段加载。
- 在卡片/历史记录的预览中保留已知的作品 ID，这样收藏和其他合集路由就不会让媒体库加载与多余的编号解析发生竞争。
- 对持久化的和仅限远程的身份控制器使用同一个响应式页面编排器。两者共用返回、顶部信息区、移动端的信息/目录、桌面端的目录以及模态框的位置，而不会让仅限远程的预览获得持久化状态。
- 在移动端，将返回控件视为“上一级”，指向最近一次按服务器和用户记录的媒体库列表位置，而宽屏布局保留可识别来源的历史返回。
- 仅在媒体阶段需要具体的文件树时，才惰性地索引本地媒体文件。已完成的空扫描会被记住，直到媒体库扫描使该状态失效。
- 合并对同一部含媒体作品的并发索引，并减少首次索引时每个文件的数据库语句数。较慢的收集和写入阶段会分别记入日志，以便诊断。
- 通过后端汇总检查来加载来源可用性。
- 在得知可用性之后，才惰性地打开远程来源的文件树。显式的、持久化的远程来源路由，可以在汇总检查之前加载其指定的来源，并在当前详情中把加载成功标记为可用。
- 在高度可变的目录行中完整换行显示文件夹和文件名，包括没有空格的长名称，而不会造成页面水平溢出。
- 将目录面包屑保持在一行。移动端把中间的上级目录折叠进菜单，桌面端则限制每个可见段的宽度，并让当前文件夹滚动到可见位置；完整名称仍可通过行、上级目录命令、标题和无障碍标签获得。
- 在顶部信息区的操作栏中保留一个“来源”菜单。它的图标会随本地、已跟踪和远程上下文而变化，标题会显示所选来源的名称，并会在外部交互、按 Escape 或切换来源时关闭。
- 把已跟踪的存在信息汇总为一个“已跟踪”标签页。当一部作品被多个文件来源跟踪时，该标签页会提供一个下拉菜单，用来切换当前的已跟踪目录，而无需在标签行中加入来源名称。
- 在目录说明中使用所选的已跟踪来源名称，并在详情 URL 中保留该选择。
- 以根据封面着色的顶部信息区打开。封面旁边依次显示：带 DLsite 链接和语言芯片的作品编号、标题、社团和系列、一行声优（CV）信息、一行标签、紧凑的统计条（评分、年龄分级、销量、发售日期和可播放时长；手机上为一行）、任何元数据提示，以及底部对齐的顶部信息区操作。标签行先列出提供方标签，再以独特的强调样式列出用户的个人标签，并以添加或编辑图标结尾；过长的提供方标签列表会折叠到 `+N` 控件之后。选择提供方标签或个人标签，会向打开详情时所用的媒体库搜索中添加一个 `tag:` 或 `mytag:` 子句；如果是从其他页面打开详情之后选择个人标签，则会开始一次新的本地媒体库搜索。目录占据下方的主栏。来源信息和元数据更新时间共用一个面板，在宽页面上位于目录旁边，在较窄的页面上则跟随在目录之后。来源信息会报告文件/音频数量、大小和时长的覆盖情况，并标明使用了元数据时长作为回退，而不是悄悄替换来源时长。在紧凑屏幕上，顶部信息区仍把相同的声优信息行、标签行、统计条和操作放在“信息”和“目录”标签页之上，“信息”显示来源面板，而标记、列表、DLsite、元数据和来源会折叠为图标。
- 将目录呈现为一个面板：标题栏包含文件摘要和来源检查，带状态圆点的下划线来源标签页，以及一个文件夹浏览器。当目录足够宽且作品有文件夹时，所选文件夹内容旁边会有一个固定的文件夹栏；否则，“文件夹”按钮会在手机上以底部面板、在其他设备上以弹出层打开同一个导航器。该栏标题中的**隐藏文件夹面板**会让内容占满整个宽度，并在“文件夹”按钮旁留下**显示文件夹面板**；此选择会记在该设备上。导航器按自然顺序列出文件夹及其可播放文件数或图片数，完整展开较小的树，对较大的树则朝所选、推荐和正在播放的文件夹展开，把只包含一个子文件夹的文件夹合并为一行，并标出推荐的文件夹和正在播放的文件夹。
- 打开时定位到文件夹路由规则所推荐的文件夹。内容工具栏显示上移控件和面包屑、该文件夹的音轨数和时长、“推荐”徽章（或返回推荐文件夹的命令）、被折叠的歌词数量，以及针对当前文件夹中可播放文件的“全部播放”命令。
- 把文件夹的内容分为子文件夹磁贴、专辑风格的音轨列表、图片画廊、文档和其他文件，并在存在多个分组时为分组加上标签。子文件夹磁贴会概括其内容，并在其中含有可播放文件时提供直接播放命令。音轨按文件夹播放顺序编号，完整名称位于大小和该作品续播位置之上，精确时长位于末尾一列；悬停时显示播放提示，并用强调色的行和动态图标标出当前音轨。续播标记会随播放保存而更新，无需重新加载。本地和缓存的图片显示惰性加载的缩略图；远程图片只在预览时加载。
- 将匹配的同文件夹歌词伴随文件从默认目录行中折叠起来，同时保持未匹配的文本可见。音频行提供歌词选择、预览和定位操作，目录控件可以显示所有被折叠的歌词。文件管理和 Fetch 选择不会折叠歌词。
- 本地来源的**管理歌词**选项会列出每个带有歌词选择的本地音频文件。拥有媒体库写入权限的用户可以指定该作品的任何本地歌词文件，包括名称与音频不匹配的翻译歌词，也可以按音轨编号（当两个文件夹中的文件数相同时则按位置）把一个歌词文件夹与音轨对齐。每一行都会预览前几行，并在最后一条带时间的行晚于音轨结束时给出警告。指定对所有听众共享，并成为“自动”选择；听众自己的选择仍然优先。
- 每个音轨在每种语言下各保留一个指定的歌词文件。**歌词语言**栏可在**所有语言通用**与日语、简体中文、繁体中文、英语和韩语之间切换，并显示每种语言下有歌词的音轨数。**所有语言通用**下的歌词适用于每种语言，只有在这里，没有指定的音轨才会回退为按文件名匹配。播放时使用听众的元数据语言中第一个有歌词的语言，其次是所有语言通用的歌词，最后是其他语言。文件的语言由你自行声明；Kikoto 不会根据文件去猜测。
- **管理歌词**为管理本地文件的用户提供**歌词文件**标签页。Kikoto 管理作品文件夹中以语言命名的文件夹里的歌词：`lyrics_ja`、`lyrics_en`、`lyrics_zh_hans`、`lyrics_zh_hant`、`lyrics_ko`，以及适用于所有语言的 `lyrics`。该标签页像**编辑文件**一样分三栏编辑这些歌词：左栏是歌词可以来自的位置，中栏是所选位置的歌词文件，右栏是编辑后的受管理歌词。作品有多个本地文件夹时，在右栏选择要编辑的文件夹。
- 位置包括：**受管理的歌词**，取消勾选文件即删除它；**此文件夹中的其他歌词**，选中的文件会移入歌词文件夹；作品的其他本地文件夹（包括媒体库中的其他版本），其文件会被复制；以及已配置的远程源提供的版本，其文件会被下载。选中的文件会放入为其所在位置在**这些歌词的语言**中选择的语言的歌词文件夹。其他版本的歌词默认使用该版本的语言；Kikoto 不会猜测作品自身文件的语言，因此需要先选择语言才会生成预览。要更改受管理歌词的语言，在**此文件夹中的其他歌词**中打开**同时列出受管理的歌词，以更改其语言**，然后在那里选中它们。文件保留其在所在位置下的路径，但去掉它可能已在的歌词文件夹。
- 右栏预览结果。内容相同的文件已在那里时保持不变。同名的不同文件是一个冲突，在右栏直接处理：保留现有文件、替换它、两者都保留，或重命名新文件；不需要先删除。**应用更改**在删除文件前会请求确认。拥有媒体库写入权限时，**将新增的歌词分配给匹配的音轨**会按文件名、再按音轨顺序，把每个新增文件以其语言分配给匹配的音轨；已有该语言歌词的音轨保持不变。已使用被移动文件的分配会随文件一起转到其语言。读取过的远程版本不会被加入媒体库。
- 本地作品的**管理文件**中有**作为歌词管理**，用于作品文件夹中其他位置的歌词。选中 `.lrc`、`.vtt`、`.srt`、`.ass` 或 `.txt` 文件后选择它，会打开**歌词文件**，并在**此文件夹中的其他歌词**下选中这些文件。
- 当作品可使用**管理歌词**时，**管理文件**默认隐藏由 Kikoto 管理的歌词。**由 Kikoto 管理的歌词**一行会统计它们的数量，并在**歌词文件**标签页上打开**管理歌词**。打开其中的**在列表中显示**开关后，它们会与其他文件一起列出，并可像任何文件一样选择。隐藏期间，选择整个作品文件夹进行删除时会包含这些歌词；任何更小的选择都会保留它们。
- **管理歌词**对具备媒体库写入和工作流权限的用户，在已配置[语音识别服务](settings.md#语音识别)时有**转写**标签页。详见[转写](#转写)。
- **管理文件**中的**快速选择**按位置或格式选择文件。本地作品还可在其中**查找相同文件**。它按内容比较此作品每个版本和每个文件夹中的本地文件，因此翻译版本中改过名的音频也会被识别为与原版相同。有相同副本的文件会标出该副本的位置，并出现两个选择项：**其他文件夹中也有**会选中列表中在别处存在相同内容的文件，**在此文件夹内重复**会选中所列文件夹内除第一个之外的每一个副本。只是相似的文件（例如同一音轨重新编码的版本）并不相同，也不会被标出。在你检查删除之前，不会删除任何内容。
- 本地作品的**管理文件**中有**编辑文件**，供可以管理本地文件的用户使用。它以三栏编辑当前列出的文件夹。**来源**列出**此文件夹**、作品各版本的其他本地文件夹，以及已配置远程来源提供的每个版本。**选择**显示所选位置的文件：取消勾选此文件夹的文件会将其移除，勾选其他位置的文件会将其添加。**最终目录**显示编辑后的文件夹，并把每个文件标记为保留、移除、复制、下载、被替换或已存在。来自其他本地文件夹的文件会被复制，原文件夹保持不变。来自远程版本的文件会被下载，这还需要 Fetch 权限，且该版本不会加入库中。如果文件会落在同名的不同文件上，就是一个冲突：保留文件夹中的文件、替换它、两者都保留，或重命名传入的文件。移除文件时，**应用更改**会先要求两次删除确认，然后作为一个活动工作流运行，在移除或添加任何内容之前先收集好所有要添加的文件。完成后目录会重新加载。
- 扫描在多个本地文件夹中找到同一编号的作品时，会保留所有这些文件夹。此时目录为每个副本显示一个文件夹，**管理文件**每次列出一个文件夹，并提供**文件夹**选择，且只有在只剩一个文件夹时才能忘记该作品。当作品位于多个文件夹，或媒体库中有它的其他版本时，具有媒体库管理权限的用户会在目录上方看到一条提示，其中的**管理歌词**和**管理文件**可用来把歌词集中到一个文件夹，并删除相同的内容。
- 先列出按自然顺序排序的文件夹，再列出按自然顺序排序的文件。文件夹播放遵循同一个可见顺序。
- 将图片和文本等可用的非播放文件保留在目录中，同时在“可播放”来源指标下把音频和含音频的视频一起计数。
- 在文件查看器中打开预览，可以通过标题栏控件、方向键、手机上的滑动或图片胶片条，在文件夹中同类型的文件之间逐个切换。图片位于深色舞台上，可以适应窗口大小，也可以围绕点击处显示实际大小并支持拖动平移，同时报告尺寸；视频使用同一个舞台。文本在阅读视图中打开，LRC、WebVTT 和 SRT 文件显示带时间戳的行，并带有 LRC 头部标签和“原始文本”切换，解析方式与播放器歌词相同。查看器为文本提供“复制”，为本地和缓存的文件提供“下载”，为本地图片提供“设为封面”，后者需要再点击一次来确认，并在几秒后或切换到另一张图片时重置。在手机上它会占满屏幕，在桌面端则显示在悬浮播放器之上。
- 按需将本地、缓存和远程的文本预览转换为 UTF-8，使用字节顺序标记、声明的字符集和自动的旧编码检测，而不会改写源文件。
- 在桌面端紧凑播放器处于活动状态时，预留底部滚动空间，以便最后的队列操作仍可触及。

## 操作

- 显示一个固定的“继续播放”操作。没有正的、未完成的作品游标时，它处于禁用状态；直接激活文件则从头开始。
- 更新快速收听状态。
- 管理收藏列表的成员关系。“列表”按钮显示作品所在列表的名称；作品在多个列表中时，显示按列表顺序排在最前的一个并标出其余数量，悬停提示列出全部名称。**添加列表**会在“列表”菜单中创建一个列表并选中它；**保存**会在已有选择的基础上应用成员关系。
- 将个人作品标签与提供方元数据标签分开编辑。
- 同步元数据。
- 从兼容的远程来源进行同步/缓存/Fetch。
- 接受 Fetch 时，会把所选来源记录为可用，并复用同一规范作品已有的排队中或运行中的 Fetch。
- 当前访客是匿名用户时，在任何 Fetch 准备请求之前先打开登录。
- 对已有本地文件夹的作品，在远程来源上使用 **Fetch** 会打开**编辑文件**并定位到该来源的版本，供可以管理本地文件并执行 Fetch 的用户使用。否则会打开 Fetch 对话框。
- 从所选来源的顶部信息区“来源”菜单中，打开该来源专属的跟踪、分叉、Fetch、原始页面、缓存、刷新和文件维护命令。
- 跟踪所选的远程来源，持久化其可浏览的文件树，并在汇总的“已跟踪”上下文中打开对应的来源，而无需再次分叉。
- 在可用时编辑手动覆盖。
- 在元数据编辑器中，把作品的元数据关联到另一个 DLsite 编号，例如某个特典版本已不再销售，而常规版本的编号不同。之后的元数据刷新会读取被关联的编号，并把它的元数据、标签和封面存到这部作品上；被关联的编号不会成为一部独立的作品。当作品自己的编号没有记录时，元数据不可用的提示会直接打开编辑器。

## 详情加载模型

作品详情应当优先使用已知的本地数据库状态，再单独加载较慢的、源自远程的状态：

1. 来自任何作品卡片界面的路由预览，或针对直接 URL 的轻量级编号解析。
2. 作品的基础元数据、用户状态、版本和制作人员。
3. 本地媒体和目录树。
4. 来源可用性摘要。
5. 用户打开的所选远程来源文件树（如有）。

这样可以避免远程来源的故障阻塞本地详情的外壳。目录阶段使用稳定的、目录形状的骨架屏。媒体错误只会替换这个骨架，而保持已加载的元数据和操作完好。Fetch 的路径选择和文件管理树，只有在选择了对应的“选项”命令之后才会推导。
