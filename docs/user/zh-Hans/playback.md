# 播放
[English](../en/playback.md) · [简体中文](../zh-Hans/playback.md) · [繁體中文](../zh-Hant/playback.md) · [日本語](../ja/playback.md) · [한국어](../ko/playback.md)

播放由全局的浏览器音频播放器处理。

## 当前行为

- 扩展名适合浏览器的本地和缓存音频，会直接以支持 HTTP Range 的方式提供。这样可以让启动和时长探测走浏览器原生的媒体路径，而无需等待 FFprobe。
- 当直接音频解码失败而文件仍然存在时，播放器会提供兼容性播放，范围可以只是当前音轨、当前队列，或今后所有的本地和缓存播放。兼容性播放以及扩展名不受支持的音频，会由 FFmpeg 转换为带有时长和拖动信息的完整 MP3 缓存文件。首次播放需要等待准备完成；之后的请求会复用结果，并支持 HTTP Range、拖动进度、继续播放以及音轨结束时的正常队列推进。已确认缺失的文件不会提供转换：如果在设置中开启了**失败时切换其他来源**，播放会按正常的来源回退顺序继续；否则播放会停止，并提供“重试”操作。
- 本地和缓存的视频会在播放前先检查。不兼容的视频首先返回探测到的总时长和一份完整的 HLS VOD 播放列表。六秒一段的 H.264/AAC 分段会按需独立生成，因此播放器可以请求靠后的分段，而无需转码之前的每一段。需要时由 Hls.js 提供 MSE 播放；原生支持 HLS 的客户端则直接使用同一份播放列表。
- 视频准备过程中的临时失败会得到有限次数的重试。若仍然失败，则保留行内的“重试”操作；从直接播放恢复为 HLS 以及显式重试，都会保留播放位置和视频是否处于暂停状态。
- 生成的视频分段是可重建的缓存数据，位于 `/cache/transcodes/hls`。音频/视频共用的转码 LRU 配额默认为 5 GiB。源路径、大小、修改时间或转码配置发生变化时，分段会失效。单个分段上限为 16 MiB，单次生成尝试上限为两分钟。被中断的进程遗留的过期部分文件会被回收。
- 准备好的音频是可重建的数据，位于 `/cache/transcodes/audio`，与视频共用转码缓存配额。每个文件的准备时间限制为四分钟、大小限制为 512 MiB；不完整或失败的输出绝不会发布。源文件变化会使缓存结果失效。原始文件保持不变。
- 已跟踪的远程媒体和远程预览媒体会按配置的来源策略获取，并默认通过后端原样代理。代理使面向浏览器的响应保持同源，并转发 Range 和条件请求头，同时绝不暴露所配置的来源 URL。远程响应不会经过 FFmpeg，即使客户端发送了 `forceTranscode` 也一样；不受支持的远程媒体必须先获取到本地或缓存位置，才能使用实时转换。远程播放采用流式传输，不会写入 `/cache`；单独的远程来源缓存工作流仍保持独立。
- 准备好的音频响应支持随机字节范围，并包含完整的长度。HLS 视频分段对其来源版本是不可变的，并且可以在完整的 VOD 时间线上拖动。视频输出限制在 720p 以内，编码为 `yuv420p` 之前会补齐为偶数尺寸，并采用保守的双线程配置。FFmpeg 和 FFprobe 各自有一个较小的固定并发上限和一个短而有界的等待队列；无法及时获得名额的请求会被拒绝，以免进程被无限期占用。
- Docker 镜像同时包含 `ffmpeg` 和 `ffprobe`。其他部署方式必须让这两个二进制文件都能在后端进程的 `PATH` 中找到。
- 点击一个可播放的文件，会把同一文件夹中按自然顺序排列的可播放文件加入队列，并从零开始播放所选文件。
- 作品详情提供固定的“继续播放”，而不是作品级别的播放。没有正的、未完成的游标时，“继续播放”处于禁用状态。
- 播放会在页面导航过程中持续。
- 当一部匹配的作品正在播放时进入作品详情，会选中当前的播放来源并打开该音轨所在的文件夹。队列处于暂停、播放的是无关的作品，以及页面打开之后才开始的播放，都保持正常的推荐目录。手动切换来源或版本也会让目录导航回到用户的控制之下。
- 桌面端在首次使用后，会保持四个主要浏览工作区处于已挂载状态。移动端只保持最近的两个工作区处于已挂载状态，既保留了快速返回，又限制了旧设备上隐藏的 DOM 和请求开销。
- 浏览器队列的持久化按服务器身份和已认证用户隔离（启用实例匿名访问时则按匿名主体）。没有作用域的 v1 队列/进度状态没有可靠的归属者，因此会被丢弃；停靠栏模式和迷你播放器位置仍是共享的设备偏好。
- 每个用户和规范的逻辑作品族只保存一个持久游标。它引用当前的版本/媒体项、来源/位置上下文、位置、时长、完成状态和时间戳。频繁的更新会被合并并串行发送；数据库暂时繁忙的响应会得到一次带短暂随机抖动的重试。
- 浏览器队列的持久化不保留每个音轨的进度。重新加载的队列元数据会从服务器刷新。当持久的作品游标仍指向恢复出来的当前音轨且尚未完成时，该音轨会从保存的位置继续。
- 播放器停靠栏支持迷你、紧凑和完整的“正在播放”状态、队列视图、拖动进度、上一首/下一首、跳转控制和播放模式。完整视图使用无边框的播放控制图标和一条细进度条，进度条显示已播放和剩余时间，两者之间是播放来源。除非在设置中开启了**快速切换来源**且该音轨有多个位置，否则来源只是一个普通标签；开启后它会打开一个位置菜单。第二行包含歌词、屏幕歌词、播放模式、睡眠定时器和队列；播放速度和兼容性范围放在标题旁的“更多”菜单中。紧凑栏额外增加一个“下一首”控件。
- 音轨播放期间，一旦当前音轨距离结尾不到 45 秒或已完全缓冲，就会预加载一次音轨结束后将被选中的下一个音轨。只会预热那一个音轨，并且使用播放器将要请求的同一个播放 URL，因此准备好的兼容性转换也同样就绪。单曲循环、有序队列的末尾、即将结束的睡眠定时器，以及浏览器请求减少数据用量时，都会跳过预加载。
- 向后和向前拖动的默认值是 10 秒和 30 秒。设置接受 1 到 300 的整数秒数，并按服务器和用户保存在浏览器中。相同的数值同时用于播放器按钮、键盘快捷键、浏览器 Media Session 操作以及 Android 媒体控件。
- 紧凑播放会在移动端和桌面端预留页面空间，以免最后的操作被遮住。PWA 更新提示会叠放在紧凑停靠栏上方。
- 移动端的完整播放在每一侧都使用边到边的安全区域。底部控件至少保持 44px 的触控高度，并与主屏幕指示条留出额外的间隔。
- 播放器的时间渲染限制在大约每秒两次更新。Android 桥接会合并待处理的状态，通常每五秒校准一次原生位置，而暂停、拖动、切换音轨和速度变化仍会立即生效。原生构建只使用 Android 媒体会话并关闭背景模糊；浏览器构建则保留浏览器的 Media Session 集成。
- 紧凑模式的元数据保持音轨标题和社团可见，没有社团时则回退为作品标题。这两行作为一个整体经过测量后一起滚动，并在每次循环之间于起点短暂停顿，同时支持减少动态效果。
- 紧凑模式的相对拖动定位把一次横跨整个宽度的拖动映射为音轨的 20%，并限制在 20 秒到 10 分钟之间，然后再将结果限制在可播放时长之内。
- 队列行可以通过拖动其手柄重新排序；列表在靠近边缘时会滚动，按 Escape 取消拖动。获得焦点的手柄也可以用上、下方向键移动其所在行。上移、下移和移除仍放在“选项”菜单中，该菜单会在选择之后、按 Escape 时或在外部交互时关闭。过长的队列标题会滚动显示，而不会改变播放器的大小。
- 文本歌词包括 LRC、SRT、VTT 和纯文本的伴随文件。对 `track.mp3` 而言，复合伴随文件如 `track.mp3.vtt` 优先，其次是同名主干的文件，然后是规范化名称的匹配。LRC 时间戳的分钟数可以超过 99，也可以带小时字段，例如 `[100:00.00]` 或 `[01:40:00.00]`。
- 如果有多个歌词文件匹配，歌词面板会提供显式的选择，而不是依赖数据库行的顺序。明显通用的同目录名称（如 `lyrics` 或 `subtitle`）可以由该文件夹中的各个音轨共用。
- 作品详情中的音频行提供相同的“自动”和显式歌词选择，而无需先播放。选择一个已持久化的作品会立即更新任何匹配的已排队音轨；仅限远程的预览选择仍是临时的。重名的文件名会带上它们的相对目录路径。
- 展开的播放器会同时根据可用宽度和高度来调整封面大小，因此竖屏手机、较矮的横屏手机和较小的桌面窗口都能完整显示封面、标题和播放控制。较矮的横屏手机会把播放控制放在封面旁边。
- 当前音轨有带时间的歌词时，当前行会显示在标题下方；选择它会打开歌词视图。歌词控件打开的是同一个视图：在手机上它取代封面，在桌面端则在正在播放栏旁边打开一个侧栏，并与队列共用标签页。当前行保持居中，手动滚动会让跟随暂停几秒，选择某一行会跳转到该行。没有匹配歌词的音轨会让该控件保持禁用。
- 屏幕歌词会让当前行和下一行显示在页面之外。支持 Document Picture-in-Picture 的浏览器会打开一个始终置顶的小窗口，在浏览器最小化时仍然可见；其他支持视频画中画的浏览器则显示渲染出来的歌词视频。Android 应用会在 Kikoto 处于后台时，在其他应用上方显示一个悬浮层。该悬浮层在屏幕居中打开，可以垂直拖动。它需要“显示在其他应用上层”的权限，并且即使 WebView 被限速，也会依据播放时钟推进歌词行。iOS 应用会在一个始终位于其他应用上方的画中画窗口中显示歌词行，并在 Kikoto 处于后台时继续推进。一旦得知音轨长度，该窗口会显示播放进度以及系统的快退和快进按钮；跳转的间隔由 iOS 设定。
- 每种播放器模式都预留相同的底部页面空间，因此在迷你、紧凑和完整模式之间切换，不会改变页面高度。

已认证用户显式选择的歌词，会按音频媒体项保存。该偏好针对的是歌词媒体项，而不是具体的文件位置，因此替换来源时可以选择另一个可用的位置。`自动` 会清除覆盖设置并恢复确定性的匹配；已保存的选择若已不可用，则会回退，而不会删除该偏好。

在**管理歌词**中保存的歌词分配，是某个音频文件的媒体库默认值。播放时先使用听众的显式选择，然后是媒体库的分配，最后才是名称匹配。若分配的歌词文件已不可用，则回退为名称匹配，而不会删除该分配。

## 游标边界

显式的“继续播放”会应用持久化的位置。它针对游标所属的版本和媒体项，先尝试已保存的位置，然后使用当前的来源优先级。重新加载的队列，在其恢复出来的当前音轨就是游标所指的媒体项时，也会为该音轨沿用游标，除非你已经播放或拖动过它。直接选择音轨则从零开始。在播放过程中切换到另一个位置或回退到另一个位置，会保留当前的内存中时间，而不会重新读取游标。

只有在一个音轨开始播放或你拖动过它之后，才会保存其进度。在此之前隐藏页面、锁定设备、暂停或切换音轨，都会让已保存的游标保持不变。

在远程作品被同步到本地媒体记录之前，远程预览播放不应持久化游标。

## 首选位置

播放应当优先选用持久的本地文件，其次是缓存文件，然后在可用时选用远程流位置。来源故障不应干扰已经可用的本地或缓存播放。

## 睡眠与耳机隐私

睡眠定时器在暂停后可以倒回 0–120 分钟，并限制在当前音轨的起点。音轨播放结束时同样适用；“继续播放”会使用倒回后的位置。该偏好按服务器和账户保存在设备上。Android 和 iOS 应用会在耳机或其他外部音频输出断开连接时暂停（包括在后台），并且重新连接时不会自动恢复播放；Android 还会关闭悬浮歌词。退出登录或切换服务器会清除 Android 应用的网页缓存，因此上一个会话的页面和图片不会保留在设备上。

在 Android 和 iOS 应用中，“设置 → 播放”中的**本设备隐私**包含以下选项，应用将其保存在设备上，适用于所有服务器和账户。iOS 对某个选项的叫法不同时，iOS 名称会放在括号中：

- **在最近任务中隐藏内容**（**后台时模糊**；默认开启）会在最近任务中显示遮罩，而不是当前页面。Android 13 及更高版本会将预览留空；更早的版本会在 Kikoto 离开前台时遮住窗口，分屏和自由窗口除外。iOS 会在应用切换器中，以及控制中心、通知中心或其他系统界面覆盖 Kikoto 时将其模糊。
- **锁定时的媒体控件**（**正在播放信息**；默认**隐藏封面**）设置媒体控件显示的内容：**全部显示**、不含封面的文字，或**仅显示应用名称**。在 Android 上，它适用于设备锁定时的媒体通知、锁屏以及已连接的蓝牙或车载屏幕，解锁后会恢复完整控件。iOS 无法让媒体控件得知设备是否锁定，因此该选择始终适用于锁屏、控制中心和已连接的屏幕。
- **外放前确认**（默认开启）会在没有连接耳机或其他音频输出时，用设备扬声器开始播放前先询问。一次确认持续到有音频输出连接或断开为止。从通知、锁屏、控制中心或媒体按键开始播放，会等待你在应用内确认。
- **禁止截屏和录屏**（**录屏或投屏时隐藏**；默认关闭）在 Android 上会让 Kikoto 及其悬浮歌词不出现在截屏、录屏和投屏中，你自己也无法截屏。iOS 无法禁止截屏；在屏幕录制、AirPlay 镜像或其他捕获进行时，它会遮住 Kikoto 并关闭屏幕歌词，直到捕获结束。
- **应用锁**（仅限 Android；默认关闭）会在你回到 Kikoto 时将其遮住，直到你用指纹、面容或设备锁屏密码解锁；Kikoto 不保存自己的密码。**锁定时机**设置 Kikoto 在后台最多可停留多久：**立即**（默认）、1、5 或 15 分钟。启动应用时始终需要验证。应用锁需要先在 Android 设置中设置锁屏密码。Kikoto 锁定期间，播放和媒体通知仍然正常工作。
