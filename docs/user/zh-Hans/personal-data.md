# 个人数据

[English](../en/personal-data.md) · [简体中文](../zh-Hans/personal-data.md) · [繁體中文](../zh-Hant/personal-data.md) · [日本語](../ja/personal-data.md) · [한국어](../ko/personal-data.md)

登录后可从侧栏、移动端账号菜单或快捷操作进入「标签」「历史」和「我的数据」。数据仅属于当前账号。

## 个人标签

支持搜索作品、社团、声优标签，包括未使用的标签。重命名更新所有关联；合并转移关联并去重，再删除原标签；删除不影响作品或元数据。

新任务的默认标签不再带日期。已有定时任务保留原模板，如需停止生成日期标签，请在工作流中移除 `{date}`。仍可主动使用日期模板。

## 收听历史

按最近收听时间查看作品、累计时长和播放次数，统计包含常听作品及最近 30 个 UTC 日期。只计算实际播放时间，不计暂停、缓冲或跳转，倍速不会额外增加时长。多个播放器分别计时；断网或客户端突然关闭可能导致部分时间未上报。

历史长期保存在服务器，推荐事件的 90 天清理不影响它。升级保留尚存的播放事件和继续播放时间，不推算缺失时长，已删除记录无法恢复。清空历史不影响标记、列表或进度；通过账号清空版本拒绝旧请求，防止延迟请求恢复已清空记录。

## 导入导出

Kikoto JSON 包含每部作品的收听标记、个人评分和备注、继续播放进度、累计统计、作品标签关联、自定义标签定义和有序收藏列表。系统标记列表由收听标记自动生成。社团和声优标签只导出定义，不包含关联或其他状态。

不导出媒体、源设置、地址、凭据、元数据、原始会话和每日统计。进度通过音轨标题及碟号、轨号匹配，不导出本地路径或源内 ID。

选择文件和格式后先预览，再导入。默认保留已有数据：已有个人状态的作品与同名列表会跳过。选择覆盖会替换对应标记、备注、作品标签、可匹配的进度和同名列表；统计取较大值，重复导入不会重复累加，也不减少实际收听时长。

按作品编号或明确的已知别名匹配现有作品。缺失编号会列出，不自动创建作品或抓取元数据；音轨缺失或重名时保留原进度。导入为一个原子事务。限制：10 MiB、20,000 部作品、5,000 个标签、1,000 个列表和各 50,000 个列表条目或作品标签关联。

Kikoeru 支持评价记录数组、`reviews` 数组或 API `works` 数组，应使用单个账号的数据并包含所有需要的分页。`primaryCode` 或 `source_id` 是作品编号；旧版数字 `work_id`/`id` 视为 RJ 商品编号。使用独立数据库 ID 的分支需先转换。支持个人 `userRating`/`user_rating` 和 `review_text`，不导入平台评分。

状态对应：`marked` → 想听，`listening` → 在听，`listened` → 听完，`replay` → 重听，`postponed` → 搁置，空值 → 未标记。完整规格见[英文文档](../en/personal-data.md)。
