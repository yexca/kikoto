# 个人数据

登录后打开**设置**：收听历史位于**历史**标签页，个人标签位于**标签**，**我的数据**是**账户**的最后一个部分。点击头像后的账户菜单以及快捷操作都可以直接打开其中每一项。它们只显示你自己账户的数据。

## 个人标签

可以搜索作品、社团或声优标签，包括未使用的标签。重命名会更新所有已关联的项目。合并会把关联转移到一个已有的标签，移除重复项，并删除旧标签。删除会移除标签及其关联，但不会删除作品或提供方元数据。

新的工作流标签默认值不含日期，因此重复运行会复用同一个标签。已保存的现有模板会被保留；如果希望较早建立的计划不再创建带日期的标签，请在“工作流”中删除 `{date}`。仍然支持显式带日期的模板。

## 收听历史

收听报告涵盖最近 30 天、最近 12 个月或全部时间。对于所选范围，它会显示：

- 收听时长、播放次数、作品数和活跃天数，以及每个活跃日的时长、每次播放的时长、收听最多的作品所占时长的比例，和范围内有收听的天数占比。
- 按 UTC 日、月或年划分的图表（全部时间在超过三年后改为按年显示），并标出平均值和最活跃的时段。
- 收听最多的五部作品（可展开到十部），每部都附有其时长及其占该范围内收听时长的比例。
- 收听节奏：当前和最长的连续有收听的天数、月数或年数，以及按星期几统计的平均收听时长（30 天），或有收听的月数或年数。

导入的累计总量没有日期，因此只计入“全部时间”。完整历史按最后收听时间排序，并显示每部作品的时长、播放次数和最后收听日期，折叠在报告下方，展开时才会加载。时长衡量的是实际收听，不含暂停、缓冲和拖动进度的时间；播放速度的变化不会使时长成倍增加。同时运行的多个播放器会各自独立计时。客户端中断或断开连接，可能导致部分时长未能上报。

历史记录会一直保存在你的服务器上，直到被清除，或者其账户/作品被删除。90 天后清理推荐事件，并不会移除它。升级会保留剩余的旧播放事件和续播时间戳，不会虚构时长；之前已删除的事件无法恢复。清除历史会保留标记、播放列表和续播进度。账户计数器会拒绝来自清除之前的延迟上报。

## 导出与导入

第 1 版 Kikoto 个人 JSON 包含每部作品的收听标记、个人评分/备注、续播信息、累计收听总量、作品标签关联、自定义标签定义，以及带有图标的、有序的收藏播放列表。系统的“标记”成员由标记推导得出。社团/声优标签定义会被包含在内；它们的实体关联和其他状态不在此格式的范围内。

不包含媒体、来源设置、端点、凭据、提供方元数据、原始会话和每日统计。续播目标由音轨标题和音轨/碟号来识别；不会导出本地路径和来源本地 ID。

选择一个来源（JSON 文件、Kikoeru 账户或 Kikoeru 数据库），先预览再导入。“保留现有数据”会跳过已有个人状态的作品，并保留已有的播放列表。“用导入的数据覆盖”会用文件中的内容替换标记、备注、作品标签、匹配的进度以及同名的播放列表。收听总量按最大值合并，因此重复导入不会重复计数，也不会减少已测得的收听时长。

只有已存在的作品和明确无歧义的已知别名才会按主编号匹配。缺失的编号会被列出；导入绝不会获取元数据或创建作品。缺失或有歧义的音轨会保持现有进度不变。导入以原子方式提交。限制：10 MiB、20,000 部作品、5,000 个标签定义、1,000 个播放列表，以及 50,000 个播放列表项或作品标签关联。

## Kikoeru

Kikoeru JSON 文件接受评价数组、`reviews` 数组或 API 的 `works` 数组。请使用单个账户的数据，并包含你想要的每一页。编号使用 `primaryCode` 或 `source_id`；数字形式的 `work_id`/`id` 是商品编号。把商品类型编码进 ID 的分支版本（类型 × 10¹² + 数字，RJ、BJ、VJ 和 CC 对应类型 0–3）会被解码。与商品编号无关的 ID 必须先转换。支持个人的 `userRating`/`user_rating` 和 `review_text`；不会导入提供方的评分。

**Kikoeru 账户**会替你读取数据。选择一个已配置的兼容 Kikoeru 的来源，或输入服务器的 API 地址，然后以无凭据（适用于关闭了登录的服务器）、令牌，或用户名和密码登录。服务器通过 `POST /api/auth/me` 登录，通过 `GET /api/review` 分页读取，并且在 Kikoeru 服务器提供时，读取你拥有的播放列表，包括它的“喜欢”和“标记”列表。没有播放列表的服务器只会导入评价。结果会经过与文件相同的预览和导入流程。

**Kikoeru 数据库文件**会上传开源 Kikoeru 的 SQLite 数据库，最大 512 MiB，并且只读取指定账户的评价。上传最长可以持续 15 分钟。请在 Kikoeru 停止或空闲时复制该文件，以便包含最近的写入。该数据库没有播放列表。

在令牌、密码、手动输入的地址或数据库离开浏览器之前，Kikoto 会说明风险并请求确认：

- 凭据会经过 Kikoto 服务器。它们只用于该次请求，绝不会被存储或记入日志，但运营该服务器的人有可能截获它们。
- Kikoeru 服务器看到的是来自 Kikoto 服务器网络地址的登录。第三方站点可能会标记该账户或对其加以限制。
- 令牌相当于你的账户，并且可能长期有效。
- Kikoeru 数据库保存着该服务器上的每个账户，包括密码哈希。上传的文件在读取期间保存在临时文件中，读取完成后立即删除。

这些请求从不跟随重定向，因此凭据只会到达你选择的地址。手动输入的地址必须是公网地址，除非你是管理员，或者管理员开启了**设置 → 媒体库 → Kikoeru 账户导入 → 允许所有账户使用局域网地址**。该开关会让任何已登录的账户都能使服务器连接其本地网络中的设备。没有可用商品编号的行会被跳过并计数，并且同一时间最多运行两个账户或数据库读取。

| Kikoeru 进度 | Kikoto 标记 |
| --- | --- |
| `marked` | 想听 |
| `listening` | 正在听 |
| `listened` | 已完成 |
| `replay` | 重听 |
| `postponed` | 已搁置 |
| 空 / null | 未标记 |
