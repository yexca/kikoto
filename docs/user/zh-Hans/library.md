# 媒体库
[English](../en/library.md) · [简体中文](../zh-Hans/library.md) · [繁體中文](../zh-Hant/library.md) · [日本語](../ja/library.md) · [한국어](../ko/library.md)

媒体库是浏览作品的主界面。

## 当前行为

- 显示本地、已跟踪以及已配置的远程来源标签页。
- 对大型结果集使用服务端分页。
- 在加载当前页之前，先搜索规范化后的标题、编号、语言版本别名、社团、标签和声优信息。提供方声明的版本编号仍可被搜索，而无需创建额外的作品，也不必在媒体库请求期间扫描原始元数据快照。
- 按字面匹配搜索文本，并忽略全角/半角、字母大小写和假名字形：`100%` 和 `a_b` 不是通配符，全角的 `ＡＢＣ` 能找到 `abc`，片假名也能找到用平假名书写的同一个词。在词前加上 `tag: 癒し`、`circle:`、`va:` 或 `mytag:` 这类子句，即可只搜索某一个字段。
- DLsite 标签也会匹配 Kikoto 已获取到的该标签在各语言中的名称：当请求英文版本的作品把显示为 `癒し` 的标签报告为 `Healing` 时，`tag: healing` 可以同时找到两者。标签、标题、社团或声优信息与搜索词完全相同的结果，会排在部分匹配的结果之前，所选排序则分别作用于每一组。
- 搜索框中的 `+` 按钮会打开一个浮动编辑器，用于编辑结构化的搜索条件。选择某个条件徽章，会在同一个弹出层中编辑它，而不会移动结果。
- 显示封面、标题、编号、单行省略显示的“社团 / 系列”、声优元数据、本地可用性、来源标签，以及（如有）快速收听标记。
- 将提供方标签测量后最多排成两行卡片内容。`+N` 徽章会在弹出层中显示被隐藏的标签；个人标签仍是单独的、由用户拥有的一行。
- 在同一个指标行中显示精简的 DL 销量，以及由五段组成的非数字评分对比。存在已保存的播放进度游标时，会出现播放历史图标。
- 仅当数据库得知某个非原版版本可通过已启用的来源获取时，才显示语言图标。未知的、或仅有元数据的语言关系并不意味着可用。
- 当有规范化的商业元数据时，显示当前价格，并将零价格的作品标为“免费”。
- 在统一的作品卡片和详情中，将已登录用户的作品标签与元数据标签分开显示。`mytag:` 用于筛选个人标签，不会改变提供方 `tag:` 搜索的含义。
- 在视觉上将来源可用性与元数据标签区分开。
- 在作品卡片上的社团名称旁显示已知的年龄分级，同时在作品详情中保留完整的年龄元数据。
- 媒体库、收藏、社团详情和声优详情等界面的作品合集都使用同一套响应式网格。列数选项是共享的，而不是在每个页面各自重新实现。
- 在本地保存所选的作品合集列数设置，并将其应用于媒体库、收藏、社团的作品合集和声优的作品合集。
- 支持稳定的带种子随机排序。种子能保持分页一致；重新洗牌会生成新的种子，而不是把顺序反过来。
- 新建的媒体库视图默认采用个性化推荐排序，同时保留历史记录/会话恢复得到的浏览选择。规范化 URL 只保留查询词和非默认的收听状态；链接中显式给出的浏览参数仍会被读取。推荐排位把收听意向与偏好亲和度分开：正在听和想听获得靠前的位置，未标记仍是主要的发现池，重听和已完成获得有限度的插入，已搁置则要等排期中的状态用尽后才出现。显式的状态筛选仍会返回所有匹配的作品。在每种状态之内，有上限的亲和度得分综合收藏、标签、声优和社团信号，且不会把候选作品本身当作口味历史。重复的正向反馈会强化每个匹配的信号，最多计入五部支持作品，常见标签的权重较低。带种子的发现加成会偏向证据较弱的作品；独立的结果扰动只在当前状态内的排序上调整该亲和度；一个小的创作者多样性调整也会影响排序。徽章和遥测保留有上限的亲和度得分。重听和收藏历史属于正向证据；仅仅“已完成”是中性的。每个浏览器标签页或原生应用启动都会绑定到一个不可变的推荐代，因此导航、分页、筛选、卡片变更和工具栏重新洗牌都不会重新计算亲和度。收藏和收听状态的变化会立即显示在卡片上，但要到下一个客户端会话才会影响排位。只有当推荐输入发生变化时，新会话才会重建推荐代；否则会用新的稳定种子沿用当前的推荐代。种子让状态混排和状态内的多样性都能安全分页，工具栏的刷新操作只会在当前推荐代内更改该种子。
- 远程推荐徽章也会为尚未导入的作品打分，使用已知的本地化标签和创作者别名。开启徽章后，会在一个批次中为当前页打分，而不会重新加载远程来源，然后逐步显示徽章（遵循减少动态效果的设置）。只显示达到你设定的徽章阈值的得分。打分失败时作品仍可使用，并提供“重试”。远程得分使用同一份冻结的会话偏好画像，不会导入任何作品。
- 在媒体库控件上方显示一条紧凑的、可横向滚动的最近播放条。它按用户排序，依据每个逻辑作品族拥有的唯一游标，并包含最新的音轨位置，而不会取代完整的作品卡片网格。该条可以折叠，这项偏好保存在浏览器中。
- 在本地、已跟踪和已配置的远程来源之间使用同一个查询。每个来源保留各自的分页、排序和滚动状态，而网格列数设置仍是共享的。用户在别处清除查询词后，来源不会恢复过时的查询文本。
- 将当前本地、已跟踪或远程来源的每页数量放在首行操作工具栏中，让顶部紧凑的分页专注于结果上下文和翻页。
- 数据库清理不在媒体库中进行。“元数据 -> 无可用来源”为没有可用来源或媒体位置的逻辑作品族提供分页搜索、来源检查，以及需确认的本地信息删除。
- `/no-source` 和 `/library/no-source` 链接会打开“元数据 -> 无可用来源”；`/library/all` 和 `/library/remote` 链接则打开媒体库。
- 当 `KIKOTO_MODE=demo` 时，后端的列表、详情和媒体响应只允许适合所有年龄段且永久免费的作品。本地作品使用规范化的商业元数据，未知元数据和临时免费促销都会被排除。模拟的 Remote Kikoeru 来源只会重新发布已获准的本地作品。演示会话可以播放已获准的完整媒体，但不能修改媒体库、设置或工作流状态。

在每个合集界面上，作品卡片都使用同一个摘要模型，已知的声优信息也包含在内。紧凑卡片最多显示两个声优名称，并概括其余的参与人员，不会让元数据无限撑大卡片。

收藏只在规范化 URL 中保留实体/搜索意图。它所选的列表、收藏筛选、排序、种子、分页、选择和作品锚点，会从当前历史记录条目中恢复，并以按用户划分的会话作为后备。`全部收藏`汇总带有快速标记的作品以及位于任何用户列表中的作品。`标记`是固定的系统列表，只包含快速标记不为“未标记”的作品；其成员由推导得出，不能作为列表编辑。其他列表由用户创建，并保留显式的成员关系。切换列表时，在结果加载期间完整的收藏列表行保持稳定，“已搁置”是收听状态选项中的最后一项。仅有播放游标永远不会把作品加入收藏。来源选择器可以将收藏的作品限定到若干个所选的已配置文件来源中的任意一个，而不会创建按来源划分的作品副本，也不会请求实时的远程刷新。

在宽屏上，结果旁边的书架栏会列出全部收藏、标记、你的列表，以及关注的社团和声优及其数量。与“工作流”和“设置”的侧栏一样，它可以隐藏名称而只保留图标，这个选择会记在该设备上。每个用户列表可以显示一个在“编辑列表”中选定的图标，图标栏中正是靠它来区分各个列表；该列表图标也会出现在“加入列表”菜单里。手机上则把相同的书架显示为一行可滚动的内容。打开的书架带有标题，其中有封面拼贴、数量、已完成的作品数，以及你正在听的作品。作品可以显示为卡片，也可以显示为更紧凑的列表，并附带每部作品的续播位置。

## 身份

媒体库卡片代表统一的作品，而不是按来源划分的副本。远程卡片可以在作品拥有本地文件之前就对其进行跟踪或同步，但由此产生的状态会附着在同一个统一的作品身份上。“跟踪”还会保存所选的来源目录树，并在“已跟踪”中打开该来源。

## 来源标签页

来源标签页应当帮助用户回答“这部作品可以从哪里播放或获取”。它们不是各自拥有元数据所有权的独立媒体库。本地、已跟踪、缓存和远程的各项事实，都指向同一个作品模型。
