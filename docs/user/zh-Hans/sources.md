# 来源

[English](../en/sources.md) · [简体中文](sources.md) · [繁體中文](../zh-Hant/sources.md) · [日本語](../ja/sources.md) · [한국어](../ko/sources.md)

来源描述文件来自哪里。

## 来源类型

- Local 文件夹来源。
- 兼容 Kikoeru 的远程来源。
- 仅用于迁移现有记录的旧版 Number178 兼容远程来源。

## 当前行为

- Local scan 会在配置的 data 根目录下检测受支持的作品代码文件夹。
- 远程来源标签页浏览已配置来源，但不会导入每一条结果。
- 作品详情使用后端聚合可用性检查。
- Remote sync 将元数据和来源文件树导入统一数据库。
- Remote cache 会在 cache 根目录下生成选定的远程文件。
- Remote fetch 将选定远程文件提升到本地 data 树。默认布局为 `/data/<source_code>/<code_prefix>_<code_group>/<work_code>`；旧的 `<source_name>` 模板令牌仍作为稳定 source code 的别名接受。
- 使用分来源保存模板的兼容来源会用机器标记和多语言 `README.md` 声明其 Fetch 根目录。Fetch 直接登记发布位置，因此文件变化不会触发 Local 文件夹 watcher。已有非空根目录若没有匹配标记，会显示为阻塞 Fetch 审核冲突，绝不会自动接管。
- 旧版 Kikoto 创建的无标记根目录，可通过同一 origin 来源的活动 `managed_fetch` 文件夹位置，或成功的 `remote_work_fetch` 运行记录识别。Kikoto 会根据这些精确的历史目标及其父目录验证完整根目录，不会遍历已确认的作品子树。根目录层级的普通 `README.md` 可以保留，但无法解释的条目、链接、重解析点，以及没有目标的过期记录会让根目录停留在阻塞审核状态。识别过程只读；下一次 Fetch 仅在不存在时写入标记并添加多语言 README。
- Cache 和 Local 删除针对具体文件位置，而不是统一作品。混合选择会作为一个可恢复工作流提交；Local 删除会保留作品进度和收听标记。
- 远程来源列表和详情页应保持来源范围视图，不会替代统一的本地作品详情模型。
- 兼容远程作品响应会映射来源当前的 `price`。该值不会作为价格历史持久化，也不视为权威常规价格。在 Demo 模式下，Remote Source 分页总会向上游搜索添加 `$age:general$` 和 `$-price:1$`。详情和媒体访问会用精确作品代码重复同样的过滤搜索；返回的年龄和价格字段不会在本地解释为策略输入。
- `kikoeru_compatible_number178` 为迁移来源保留适配器，但会拒绝新的来源和配置种子输入。历史拼写 `kikoeru_compilable_number178` 会自动迁移。

## 可用性检查

启动和来源变更批量检查会先验证相关来源健康状态。探测优先使用 `/api/health`；对于没有健康端点的兼容来源，则退回单条列表请求。

管理员也可以在 Maintenance 中通过 `POST /api/file-sources/{id}/health-check` 手动运行相同的有界探测。响应仅报告健康状态、检查时间和持续时间，不返回已配置的上游地址或原始上游错误。

如果来源无法访问，Kikoto 会将该来源标记为本批次不可用，并跳过逐作品检查，不会把每个候选作品都标记为缺失。

## 下载节流

远程下载会等待配置的延迟，并对临时错误使用退避重试。Maintenance 还会配置单文件媒体下载大小上限，默认 100 GB，允许范围为 1–2048 GB。即使来源没有声明响应大小，该限制也适用于 Fetch 和播放缓存生成。远程封面和 DLsite 封面使用独立的固定 20 MiB 上限。DLsite 元数据同步对产品和封面请求也使用配置的基础延迟和退避。

来源返回限流或暂时不可用的响应时，Kikoto 会按其要求暂停对该来源的请求，但暂停时间不会超过 Maintenance 中的最大退避。该来源排队中的作业会等待暂停结束，且不消耗重试次数；其他来源的作业照常执行。

Fetch 规划使用已经完整持久化的元数据和缓存来源可用性。如果请求代码没有 DLsite 快照或版本关系，准备阶段会先执行有界的目标作品族同步，再生成审核内容。已排队的 Fetch 会复用提交时接受的远程文件树，不会立即再次请求同一文件树。Local 登记成功后，该 Fetch 提升的缓存对象会被移除；未选中的缓存对象仍可用。
