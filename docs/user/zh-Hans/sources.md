# 来源
[English](../en/sources.md) · [简体中文](../zh-Hans/sources.md) · [繁體中文](../zh-Hant/sources.md) · [日本語](../ja/sources.md) · [한국어](../ko/sources.md)

来源描述文件来自哪里。

## 来源类型

- 本地文件夹来源。
- 兼容 Kikoeru 的远程来源。
- 旧版兼容 Number178 的远程来源，仅用于已迁移的现有记录。

## 当前行为

- 本地扫描会在已配置的数据根目录下检测受支持的作品编号文件夹。
- 远程来源标签页浏览已配置的来源，而不会导入每一条结果。
- 作品详情使用后端汇总的可用性检查。
- 远程同步会把元数据和来源文件树导入统一数据库。
- 远程缓存会把选中的远程文件落地到缓存根目录下。
- 远程 Fetch 会把选中的远程文件提升到本地数据目录树中。默认布局为 `/data/<source_code>/<code_prefix>_<code_group>/<work_code>`；旧版的 `<source_name>` 模板标记仍被接受，作为稳定来源编码的别名。
- 使用按来源分隔的保存模板的兼容来源，会用机器可读的标记和多语言的 `README.md` 来认领它的 Fetch 根目录。由于 Fetch 会直接登记发布结果，这里的文件变化不会触发本地文件夹监视器。已存在、非空且没有匹配标记的根目录，会显示为阻塞性的 Fetch 审阅冲突，不会被自动接管。
- 旧版 Kikoto 创建的无标记根目录，可以根据同一来源下处于活动状态的 `managed_fetch` 文件夹位置，或者一个已成功的 `remote_work_fetch` 运行（其成功的计划记录了相同的来源和目标根目录）来识别。Kikoto 会对照这些确切的历史目标及其上级目录来核对整个根目录，且不会遍历已证实的作品子树。根目录下允许存在普通的 `README.md`，但无法解释的条目、链接、重解析点，以及目标均已不存在的陈旧记录，都会让该根目录继续处于阻塞审阅状态。识别是只读的；下一次 Fetch 会写入标记，并仅在尚无多语言 README 时添加它。
- 缓存和本地删除针对具体的文件位置，而不是统一的作品。混合选择会作为一个可恢复的工作流提交；本地删除会保留作品进度和收听标记。
- 远程来源的列表和详情页应当保持为限定于来源的视图；它们不会取代统一的本地作品详情模型。
- 兼容的远程作品响应会映射来源当前的 `price`。该值不会作为价格历史保存，也不会被视为权威的常规价格。
- 演示模式绝不会联系远程服务器。它唯一的远程来源 Remote Kikoeru 由进程内从已获准的本地作品中随机挑选来模拟，媒体库会在其上方显示说明此事的提示。
- `kikoeru_compatible_number178` 为已迁移的来源保留其适配器，但新的来源和配置种子输入会拒绝它。历史上的 `kikoeru_compilable_number178` 拼写会被自动迁移。

## 可用性检查

启动时以及来源变更后的批量检查，会先验证相关来源的健康状况。探测优先使用 `/api/health`，对于不提供健康检查端点的兼容来源，则回退为只请求一项的列表请求。

管理员可以在“设置 -> 媒体库”中，通过 `POST /api/file-sources/{id}/health-check` 手动运行同样的有界探测。响应会报告健康状况、检查时间和耗时，而不会返回已配置的上游地址或原始的上游错误。

如果某个来源无法连接，Kikoto 会在该批次中把该来源标记为不可用，并跳过逐个作品的检查。它不会把每一部候选作品都标记为缺失。

## 下载节奏

远程下载会等待配置的延迟，并在遇到临时错误时带退避地重试。“设置 -> 缓存与获取”还可配置有界的单文件媒体下载大小；默认值为 100 GB，可接受的范围为 1–2048 GB。即使来源没有声明响应大小，该限制也适用于 Fetch 和播放缓存的落地。远程封面和 DLsite 封面使用另一个固定的 20 MiB 限制。DLsite 元数据同步对提供方的商品和封面请求，同样使用配置的基础延迟和退避。

当某个来源返回限流或暂时不可用的响应时，Kikoto 会按其要求的时长暂停对该来源的请求，但绝不会超过“设置 -> 缓存与获取”中的**最大退避**。该来源的排队任务会等待暂停结束，而不会耗尽其重试次数，其他来源的任务则继续运行。

Fetch 规划使用已经完整的已保存元数据和缓存的来源可用性。当所请求的编号没有 DLsite 快照或版本关系时，准备阶段会在构建审阅之前执行一次有界的、有针对性的作品族同步。排队的 Fetch 会复用提交时已接受的远程目录树，而不会立即再次请求同一棵树。本地登记成功后，该 Fetch 所提升的缓存对象会被移除；未选中的缓存对象仍然可用。
