# 工作流
[English](../en/workflows.md) · [简体中文](../zh-Hans/workflows.md) · [繁體中文](../zh-Hant/workflows.md) · [日本語](../ja/workflows.md) · [한국어](../ko/workflows.md)

工作流让后端操作变得可检查。

## 用户界面

- 工作流：内置的定义（包括预制的目录同步工作流），其触发器在所选定义中管理。没有自定义工作流编辑器。
- 顶部的状态条显示当前正在运行的内容及其进度、有多少运行需要处理，以及下一次计划的运行。它的前两个单元格和右端的**活动**会打开一个桌面端面板或移动端面板，涵盖所有工作流；“下一次计划”单元格则会选中对应的工作流。进行中的运行显示在**需要处理**和**历史记录**之上。每一行都显示状态、运行编号、触发方式和已用时间。列表行以及**最近运行**会在同一个面板内打开详情：开始和结束时间、时长、触发方式、步骤、候选项、运行操作，以及折叠起来的、包含运行事件的**诊断日志**。**返回运行记录**会回到列表。“活动”没有独立的页面：`/activity` 和 `/runs` 链接会打开带有“活动”面板的“工作流”，并选中所链接的运行。
- “活动”列出所有运行，包括拥有自己页面的功能的运行：翻译在[翻译](translation.md)页面中跟进，转写则在作品的**管理歌词 → 转写**中。关于此类运行的通知会打开那个页面。

## 谁可以使用工作流

工作流向拥有 `workflows:run` 的账号开放，即贡献者和管理员（见[用户](settings.md#用户)）。这些账号看到相同的定义、预设、触发器和运行（包括其他账号发起的运行），并可以跟进其状态、事件和文件进度。

- 启动、配置或定时某个工作流，需要它的各个步骤用到的全部权限：追踪需要 `remote:track`，获取及所有基于获取的批量操作需要 `remote:fetch` 和 `metadata:sync`，扫描、元数据类工作流和排行榜拉取需要 `metadata:sync`，来源检查需要 `sources:write`。没有 `metadata:sync` 的贡献者仍可查看这些工作流，但不能运行或自动化获取路径。
- 修改、停用或删除触发器，需要与创建它相同的权限。
- 可用性监视每次运行都会刷新作品系列元数据，因此配置、监视池和运行都需要 `metadata:sync`；追踪还需要 `remote:track`，获取还需要 `remote:fetch`，追踪并获取需要两个远程权限。
- 运行的取消、重试和条目审核，可由发起该运行的账号进行（直接发起，或作为触发它的触发器的所有者）。管理员可以对所有运行进行这些操作。重试需要发起同样工作所需的权限。
- 解决后会删除、归档本地文件或将其标记为不可用的条目（例如获取的归档审核）需要 `downloads:manage`。恢复停滞的运行需要 `sources:write`。

## 当前行为

- **获取**（Fetch）针对一个作品编号和一个已启用的兼容远程来源提供运行选项。在**筛选**下，可选择要排除的文件扩展名，或输入以逗号分隔的其他扩展名。默认不排除任何内容。**运行**会打开 Fetch 预览；先查看文件和目的地，再通过**发布 Fetch** 将该运行排队。切换语言版本时，这些排除设置同样适用。Fetch 只能手动运行，没有自动化触发器。
- 本地扫描会记录文件夹的发现和本地来源的存在情况，而无需等待元数据提供方。元数据同步、来源可用性、远程同步、缓存、Fetch、清理、社团刷新和批量远程操作，各自记录为独立的工作流运行。
- 对于一部明确的本地作品，当其文件夹消失，或其存储的路径不再属于检测到的文件夹时，扫描会把旧的本地文件位置标记为缺失。它不会删除文件，也不会改变 Fetch 的归属。被移动的文件夹会在打开时惰性索引。在多个文件夹中找到同一编号的作品时，会保留所有这些文件夹，其详情页会提示整理这些文件夹。
- 节点运行会显示步骤级别的进度。
- 候选项会显示可审阅的结果。
- “需要处理”包含已终止且带有需要用户决定的未解决候选项的运行。常规的部分完成或跳过的结果仍保留在“历史记录”中，并保留其警告状态、摘要和事件以供检查。
- 页眉的通知中心显示**动态**（你已完成或失败的工作流结果，例如 Fetch），对于工作流操作员，还显示**需要处理**的运行，最新的运行中任务位于两者之上。Fetch 通知会打开本地作品详情，并且可以为已登录用户单独关闭；需要处理的翻译会打开翻译页面的**已停止**视图，转写则打开其作品；**打开活动**会打开完整的面板。
- 工作流列表按类别对所有工作流分组：基础（本地扫描、本地文件、元数据同步和学习标签名称）、收集（**拉取 DLsite 排行榜**和**拉取远端源排行榜**）、目录同步（订阅刷新和目录同步预制工作流）和远程（可用性监视、Fetch 和检查作品在来源上的存在），每组顺序固定。每个条目都显示其最近一次运行的状态和时间，小图标则标出已启用的启动时触发器、计划或文件夹监视器。宽屏布局会把列表保持在所选工作流旁边；其下方的**收起标签页名称**会把列表折叠为图标，每个图标都为最近一次运行保留一个圆点，而**展开标签页名称**则再次展开。页面会记住这个选择。在手机上，列表是落地视图：点按某个工作流会打开它，页眉的返回按钮或浏览器的“后退”会回到列表。不能在该页面创建、编辑或删除定义。
- 所选工作流会概括其最近 20 次运行：最后一次运行、已完成运行中成功的比例、它们的典型（中位）时长，以及它下一次自动开始的时间（计划、下一次服务启动、文件夹变化，或仅限手动）。这些运行时长的柱状图按从旧到新排列，让普通的成功保持中性色，使失败和部分完成的运行更醒目；悬停在柱子上可查看详情，选择它则会打开该运行。
- “需要处理”汇集未解决的候选项、元数据问题和未确认的失败。解决或忽略已记录的问题，会清除对应的专用元数据运行提示。在未解决的候选项和可重试的元数据失败都处理完之后，其他失败可以标记已处理。如果一次运行剩下的元数据问题只是被报告为不可用的作品（例如已下架的作品），也可以标记已处理，这些问题仍保留在元数据页中。这种确认是按用户的。“历史记录”保留原始结果，包括失败、部分完成和已取消的运行。
- 元数据页负责待处理作品的恢复和 DLsite 代理快捷方式。它的元数据同步快捷方式会在此处选中已有的工作流。
- 内置的本地扫描和元数据同步支持可编辑的间隔触发器；本地扫描还支持启动时触发器。本地扫描不会检查远程可用性，也不会同步元数据。手动、启动时和间隔的扫描都提供默认关闭的 `后续运行`；开启它会在扫描结束后排队一个独立的元数据运行。元数据同步没有启动时触发器，因此不会与扫描的后续运行竞争。
- 本地扫描有一个启动时触发器和一个固定的文件夹监视器。新安装时两者都默认关闭，媒体库设置会提示开启它们。监视器可以暂停、恢复，或在“增量”和“完整”之间切换，但不能被创建、复制、转换、重命名或删除。默认是“增量”。监视器会登记发现目录以及已识别作品根目录之下的每个子目录，并动态登记新的目录树。它会在最近一次观察到事件之后等待五秒，忽略 Kikoto 的暂存、备份、回收站以及已认领的按来源划分的 Fetch 目录树，并对受影响的作品根目录进行协调。被移除的文件和文件夹会变为 `missing`；数据库记录会保留。监视器错误、过大的事件批次、根目录失效和重复的根目录会自动改用完整扫描。Fetch 直接登记它自己发布的位置；手动、启动时和间隔的扫描始终检查完整的数据目录树。运行期间发生的变化最多产生一次后续扫描。暂停期间的事件会被丢弃；离线期间的变化依赖启动时扫描。
- **刷新本地作品文件**排在第二位，位于本地扫描之后。它会对扫描已发现的本地作品文件夹内的媒体文件建立索引，这样打开作品时就不必按需索引大型文件夹。**增量**（默认）只覆盖其文件从未被索引过的文件夹；**完整**会重新索引所有可用的本地作品。同一时间只有一个运行处于排队或运行中，再次启动会返回当前活动的运行。它支持保存模式的启动时和间隔触发器，并且默认不带任何触发器。
- **检查作品在来源上的存在**位于“远程”中，排在 Fetch 之后。它会向一个远程来源查询媒体库中的作品是否存在，并像检查单个作品的可用性一样把结果记录到每个作品上；它不会添加作品。选项包括来源、作品（默认的**本地媒体库**或**数据库中的全部作品**）、筛选（默认的**无远程来源**，针对当前没有任何远程来源提供的作品，或**全部**），以及**每次作品数**（50 到 1000，默认 100）。没有已启用的兼容远程来源时，该工作流会被提示配置来源的遮罩覆盖。每个作品在来源上查询一次。匹配的作品多于上限时，优先检查该来源从未检查过的作品，其次是最久未检查的作品，因此重复运行即可覆盖整个媒体库。运行会先以与来源设置中的**检查健康状态**相同的方式检查来源，来源不可用时不记录任何作品就停止；部分查询失败时，该运行以部分完成结束。每个来源同时只有一个活动运行。它支持保存这些选项的启动时和间隔触发器，并且默认不带任何触发器。运行它需要管理来源的权限。
- 带有运行参数的工作流，会在摘要下方的**运行选项**表单中显示它们。表单以一个栏结尾，其中有 `运行`，并在 `运行` 不可用时给出原因，例如缺少必填输入。当较长的表单滚动时，该栏会停留在屏幕底部，位于手机导航和播放器之上。选项只应用于下一次手动运行，选择另一个工作流时会重置。本地扫描在那里显示它的后续运行选项；没有运行参数的内置工作流则改为在其页眉中显示 `运行`。
- 运行监视器位于表单之后，其后是触发器和最近的运行。它显示最近一次运行的各阶段及其日志，空间足够时并排显示。运行处于活动状态时，新的日志行会流式出现，除非你向上滚动，否则日志会跟随最新输出。选择某个阶段，可以只显示它的行；选择运行摘要，则会在“活动”中打开该运行。
- 可用性监视、**刷新订阅**、**拉取 DLsite 排行榜**和**拉取远端源排行榜**在[订阅](subscriptions.md)页面中配置：监视在那里保存它的配置和监视池，订阅刷新保存它的刷新计划，每个排行榜则保存各自的拉取计划。在这里，它们显示各自最近一次运行、健康状况概要和运行历史，链接到该页面，并且没有自己的运行选项或触发器。
- 同步社团目录、同步系列目录和同步声优目录（标签页**社团目录**、**系列目录**和**声优目录**）是按需运行的预制工作流。它们的运行选项分为三个部分：**输入**（目标和目录刷新，增量或完整）、**筛选**（发售日期范围和作品数量上限）以及**动作**（同步元数据、标签模板，对社团还有检测远程来源）。在宽屏上，这三个部分以列的形式并排显示。社团和系列的目标最多接受 20 个以逗号分隔的 ID，它们的目录会在筛选前合并。声优目标是一位选定的声优；其目录会使用显示名称和已确认的别名，在勾选的远程来源上刷新。系列读取其已存储的作品，没有目录刷新。同步元数据覆盖缺少元数据的目录作品，包括尚未在媒体库中的作品，并且筛选和标签应用于这些作品。所有筛选默认都是关闭的：没有发售范围或作品数量上限时，一次运行会同步每一部缺少元数据的目录作品。标签模板默认也是关闭的；开启后会为同步的作品打标签。关闭“同步元数据”后，社团或声优的目录同步只会刷新目录（并检查来源）。目录同步不会跟踪或 Fetch；如需这些操作，请使用远程来源中的作品、可用性监视或作品的详情页。
- 目录同步预制工作流没有触发器。如需按计划关注新作，请改为订阅社团、系列或声优；该预制工作流的触发器区域会链接到[订阅](subscriptions.md)。
- 元数据同步会刷新媒体库中已有的作品。它的运行选项选择**作品**（全部作品、一个社团、一位声优或指定作品）、**元数据来源**标签页，以及**刷新内容**（缺失或过期，或全部元数据）。全部作品和指定作品默认使用 DLsite，并且可以选择已启用且具备元数据能力的远程来源。社团只显示 DLsite。声优只显示远程来源，并且在配置并启用一个远程来源之前不可用。指定作品最多接受 100 个以空格、逗号或换行分隔的已有编号，默认使用全部元数据。选择 DLsite 时，运行选项还会显示[远程元数据回退](settings.md#远程元数据回退)和[购买特典关联](settings.md#购买特典)。这些选择适用于本次运行。间隔触发器会保存相同的选项，重试也会沿用它们。远程刷新会保留手动编辑和 DLsite 的优先级；“缺失或过期”会检查所选来源的元数据。当没有配置具备能力且已启用的远程来源时，来源选择器和回退控件会被隐藏。
- 工作流是内置的；用户无法自行创建。从旧版安装中保留下来的自定义工作流会在媒体库设置期间接受审阅，其中与预制工作流完全匹配的项可以变为审阅管理员的订阅，其他的可以导出；参见[入门指南](getting-started.md)。它们较早的运行仍保留在“活动”历史中。
- **拉取 DLsite 排行榜**会在一次运行中按每种排序拉取所有到期的 DLsite 排行榜，**拉取远端源排行榜**则每次运行拉取一个远程来源的热门列表；参见[排行榜](subscriptions.md#排行榜)。两者都不会把作品加入媒体库、同步其元数据、跟踪、Fetch 或为其打标签。已打过标签、已跟踪或已 Fetch 作品的热门收集运行仍可在“活动”中查看，但不能重试。
- 对每部规范作品，排队中或运行中的 Fetch 是唯一的。重复的 Fetch 请求会复用该运行，而不会把同一部作品下载两次，每位提出请求的用户都会收到这个共享运行的终态通知。
- Fetch 活动会报告字节级的远程传输进度、观察到的传输速率和预计剩余时间。大小未知的文件会明确标示，并且在得知其实际大小之前，不显示百分比和剩余时间。
- Fetch 运行的详情会列出它的文件。正在下载的文件保持在顶部，并带有自己的进度条，完整列表则把每个文件标记为已完成、等待中，或标出运行在哪里失败或暂停。
- 每个 Fetch 运行都以其作品命名，例如 `Fetch RJ00000001`，“活动”搜索可以通过作品编号找到某个 Fetch。**获取**标签页会列出 Fetch 历史和步骤，但没有运行表单：Fetch 总是从某部作品开始。由可用性监视或批量操作排队的 Fetch，会把该来源记录为其触发原因。
- 针对单个作品、社团、系列、声优或远程来源的运行会在标题中加上该对象，例如 `同步社团目录：RG00000000`，“活动”搜索也可以通过它找到该运行。
- 扫描绝不会把它看不到的位置上的作品标记为缺失：未挂载的数据文件夹或离线的存储池、比扫描深度更深的文件夹、无权读取的文件夹，以及 NAS 系统和操作系统添加的回收站与快照。对未挂载的标准媒体库的扫描会失败且不改变任何内容；跳过某个离线存储池或无法读取的文件夹的扫描会以部分完成结束，并指出其名称。
- 扫描、文件列表和文件夹监视会跳过文件夹 `@eaDir`、`#recycle`、`#snapshot`、`__MACOSX`、`.Trash-*`、`$RECYCLE.BIN`、`System Volume Information` 和 `lost+found`，以及文件 `._*`、`.DS_Store` 和 `Thumbs.db`。这些文件夹中的作品文件夹绝不会被发现为作品。已记录在回收站、快照、`.Trash-*`、`$RECYCLE.BIN`、`System Volume Information` 或 `lost+found` 文件夹中的作品文件夹保持其状态。`@eaDir` 和 `__MACOSX` 只保存元数据，从不保存你的文件：记录在其中的文件夹不是作品的文件夹，其文件绝不会加入作品，能看到它的下一次扫描会将其标记为缺失。扫描读取的作品文件夹中的这些文件夹和文件不是作品的文件，媒体库中列出的这类文件会被扫描标记为缺失。
- 当 FFprobe 无法读取某个媒体文件（例如已损坏的文件）时，Kikoto 会针对该文件的当前版本记录这一情况，并停止在后台探测它。超时或被中断的探测不会记录任何内容，扫描发现文件变化后会再次探测。
- 位于未挂载磁盘上的作品仍保留在媒体库中。它们的卡片显示 **本地 · 离线**，作品的本地文件会说明磁盘未挂载。在磁盘重新挂载之前，这些文件无法播放、下载、编辑或删除，**编辑文件** 会把这样的文件夹显示为离线，且不会从中取用任何文件。磁盘恢复后，无需扫描，文件即可重新使用。

## 限制

- 重试和检查点恢复只适用于明确声明其任务可恢复的工作流族；任意失败的节点无法单独恢复。
- 工作进程运行在 Kikoto 进程内部，因此排队的任务只有在该进程运行期间才会推进。不支持分布式或多实例的执行。
- 正常的服务停止会把运行中的可恢复任务放回队列，而不消耗它的重试预算。崩溃、强制终止或租约过期之后的恢复，受每个任务的重试预算限制。手动的陈旧运行恢复会把被中断的不可恢复工作标记为失败，以供检查。
