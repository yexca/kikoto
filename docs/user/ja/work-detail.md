# 作品詳細
[English](../en/work-detail.md) · [简体中文](../zh-Hans/work-detail.md) · [繁體中文](../zh-Hant/work-detail.md) · [日本語](../ja/work-detail.md) · [한국어](../ko/work-detail.md)

作品詳細では、1 つの作品に関するメタデータ、版、ファイルツリー、ソースの利用可能状態、再生操作を表示します。

## 多言語タイトル

エディターの **タイトル** セクションでは、日本語、簡体字中国語、繁体字中国語、英語、韓国語が、それぞれ全幅の行として並び、その後に **フォールバック** が続きます。フォールバックは、固有の手動タイトルを持たないすべての言語でプロバイダーのタイトルの代わりに表示されるタイトルで、版と説明は変わりません。原語の行には `origin` バッジが、現在表示しているメタデータ言語の行には `current` バッジが付き、同じ行に両方が表示されることもあります。各行自身の手動タイトルは編集可能なテキストで、プロバイダーのタイトルと継承されたタイトルはグレーのヒントのままであり、変更なしのまま保存されることはありません。各行のラベル行には、手動タイトルや編集済みのタイトルの印が付くか、継承されたタイトルの現在のソースが示されます。保存で送信されるのは変更されたフィールドとタイトル言語だけです。既存の手動タイトルをクリアする、またはその行で「元に戻す」を選ぶと、保存時にそのスコープが削除され、継承されたヒントをクリアしても何も変わりません。同じエディターは、メタデータ → 作品からも開けます。

メタデータ言語メニューには、既知の版、固有の手動タイトルまたは作品紹介を持つ言語、**LLM** と表示する承認済み翻訳が含まれます。LLM の選択は同じ作品のメタデータ表示に反映し、公式版や音声の別バージョンを作りません。原文へのフォールバックでは、未指定を含め、宣言された原語を保持します。[タイトルと説明の優先順位](../../architecture/data-model.md#manual-overrides-and-titles)を参照してください。

DLsite に作品の記録がなく、リモートソースが補完した場合、詳細の通知に **リモートソースで補完** と表示され、各ソースが補完した値が一覧されます。リモートのタイトルは、タイトルの順序では DLsite の後、作品自身のタイトルの前に来ます。言語を宣言しないため、言語の選択肢は増えず、テキストは変更されません。タイトルエディターにはそのソースが示されます。

プロバイダーの表示では、作品ファミリー内の原版以外の版はすべて翻訳として扱われ、第三者による翻訳も含まれます。先頭にある DLsite の言語版ラベル（`【简体中文版】` や `【ドイツ語版】` など）は 1 つだけが、その形式に基づいて取り除かれます。`【ASMR】` のようなラベル、中間にあるラベル、手動タイトルはそのまま残ります。各版のエントリは、非対応の言語を含め、それぞれ自身のタイトルを保持します。プロバイダーの生のタイトルとスナップショットは変更されません。カード、詳細、言語の選択肢、検索結果、新しい再生キューは同じ表示ルールを共有し、すべての手動タイトルは引き続き検索できます。紹介文はそのままプレーンテキストとして描画され、手動の作品紹介で置き換えられていない限り、選択した版に従います。一致する版のない手動の言語では、原版の紹介文が使われます。

## メタデータの編集

プレビューでは安定したタグ ID による統合も選択できます。DLsite ファミリーの受け入れは独立した操作で、通常のフィールド保存では同族の版をライブラリに追加しません。

**編集用に取得** は、現在の値、取得した値、保存予定の 3 列で作品を比較します。言語範囲は実際に存在する版から作られ、正規版には Original が付きます。取得した値をそのまま使うとプロバイダーのメタデータとして保存され、既存の手動上書きが解除されます。保存予定の値を編集した場合だけ手動上書きになります。プレビューは期限切れになり、開いている間に作品が変更された場合は適用できません。

ヒーローの **メタデータ** ボタンから、エディターが直接開きます。**メタデータを更新** は左下にあり、通常の DLsite の更新を実行します。有効なリモートソースがメタデータに対応している場合は、隣の矢印から `<ソース名>から` の選択肢が開きます。いずれかを選択すると、そのソースからこの作品の最新のメタデータを要求します。手動の編集と DLsite の値の優先順位は変わらず、保存していないエディターの下書きもそのまま残ります。この明示的な更新には、自動のリモートフォールバックを有効にしておく必要はありません。

admin と super_admin は `library:write` で作品のメタデータを編集できます。保存で送信されるのは、エディターの初期値から変更されたフィールドだけです。カバーだけを選択しても、自動のタイトル、サークル、シリーズ、声優クレジットは保持されます。フィールドをクリアすると、そのフィールドの上書きだけがリセットされます。同じファミリー内のトリミングした DLsite のタイトルと完全に一致する既存の固定されたタイトルの上書きは、アップグレード時に削除されます。サークル、シリーズ、声優の上書きは保持されます。

エディターのフィールドは、タイトル、作品紹介、カバー、タグ、クレジット、年齢区分、リンクのセクションに分類されます。未保存の変更があるセクションにはドットが表示され、フッターにそれらが一覧されます。フッターには **メタデータを更新** と **その他** もあり、**その他** から **編集用に取得** と [AIで翻訳](#aiで翻訳)を開けます。手動のサークル、シリーズ、声優リスト、カバーに対する「元に戻す」、およびメタデータのリンクの追加や削除を含め、すべての変更は保存するまで下書きのままなので、セクションを切り替えても編集内容が失われることはありません。キャンセルでは、下書きを破棄する前に確認されます。サークル、シリーズ、声優には、既知のエントリにリンクする候補が表示されます。その識別子は名前の下に表示されたままで、「ID を編集」の下で引き続き編集できます。カバーは、作品のローカル画像のサムネイルグリッドから選択します。Ctrl+Enter で保存します。

**作品紹介** セクションでは、日本語、簡体字中国語、繁体字中国語、英語、韓国語が、それぞれ複数行を入力できるフィールドとして並び、その後に **フォールバック** が続きます。フォールバックは、固有の作品紹介を持たないすべての言語でプロバイダーの紹介文の代わりに表示される紹介文です。各フィールドは、その言語が現在表示している紹介文から始まります。変更したテキストを保存すると、メタデータを更新しても保持される手動の作品紹介になります。言語固有の作品紹介はその言語でプロバイダーと LLM の紹介文を置き換え、フォールバックは固有の作品紹介を持たないすべての言語でそれらを置き換えます。手動の作品紹介だけを持つ言語には、通常のタイトルとともに、言語メニューに独自の選択肢が加わります。継承された紹介文をそのままにするかクリアしても、何も保存されません。手動の作品紹介をクリアするか「元に戻す」を選ぶと、保存時にその言語が継承する内容に戻ります。このフィールドには **編集用に取得** が不要なので、プロバイダーのメタデータがない作品にも作品紹介を設定できます。

**年齢区分** セクションでは、全年齢、R15、R18 を選べ、プロバイダーの年齢区分も表示されます。手動の年齢区分は、カスタム作品や DLsite が掲載しなくなった商品など、プロバイダーが年齢区分を示さない作品を補うか、プロバイダーの年齢区分をより厳しくします。プロバイダーより緩い年齢区分は選べません。作品には手動の年齢区分が表示され、ライブラリでもそれで検索され、[コンテンツ安全ポリシー](settings.md#コンテンツ安全ポリシー)でもそれで判定されます。ただしプロバイダーの年齢区分のほうが厳しい場合は、そちらが優先されます。「元に戻す」を選ぶと、保存時に手動の年齢区分が削除されます。

言語ごとに保存される唯一の値であるタイトル、作品紹介、タグ名について、タイトル、作品紹介、タグのセクションの上部にある **メタデータの言語** のタブで、表示する言語を選びます。**すべての言語** に続いて、日本語、簡体字中国語、繁体字中国語、英語、韓国語が、作品にその言語の版があるかどうかにかかわらず並び、さらに **フォールバック** があります。**その他** は、言語が宣言されていない原版を含め、作品が持つ他の言語の版を開きます。いずれかを選ぶとそのタブが選択され、`その他 - ドイツ語` のように言語名が表示されます。タイトル、作品紹介、タグ名を保存できるのは上記の 5 言語だけなので、「その他」の版には提供元のタイトルと紹介文、および各タグのフォールバック名が表示されます。5 言語のいずれかでは、その言語のタイトル、作品紹介、タグ名だけが表示され、**フォールバック** では、フォールバックのタイトル、作品紹介、タグ名だけが表示されます。作品に付くタグ、カバー、クレジット、年齢区分、リンクは、どの言語でも同じです。

タグセクションでは、共有されたメタデータのタグを検索し、この作品に追加または削除できます。作品に DLsite のメタデータがなくても、カスタムタグを作成できます。「DLsite タグに戻す」は、その作品のタグの追加と削除をクリアします。共有された名前は優先メタデータ言語に従い、手動の名前と学習したジャンル名が使われます。日本語のみの作品でも、既知の中国語のタグ名を表示できます。バックグラウンドの更新が完了した後も、非表示のタグはどこでも非表示のままです。個人の「マイタグ」は、アカウントが所有する別のタグです。デモではエディターが読み取り専用で表示されます。

作品のタグは、タグ追加の入力欄の下に、タグごとに 1 行ずつの表として並びます。**すべての言語** では、5 言語それぞれの列と、固有の名前を持たない言語に表示される名前である **フォールバック** 列が表示され、1 つの言語またはフォールバックを選ぶと、その列だけが表示されます。言語が継承した名前はグレーで表示され、この作品に追加したタグには **追加** の印が付きます。各タグの言語ボタンを押すと、その行の下に名前が開き、対応する各言語の名前とフォールバック名が別々の行に表示されます。選択した言語がある場合は、その言語とフォールバック名だけが表示されます。手動の名前は編集可能なテキストで、プロバイダーまたは学習した名前はグレーのヒントのままです。タグ名は共有されるため、名前を変更したタグは、それを持つすべての作品で変わります。パネルには、そのタグを共有している作品の数が表示されます。新しいカスタムタグは、入力された名前をフォールバック名として保持し、作成する前に他の言語の名前を設定することもできます。名前の編集は他のすべての変更と同様に下書きで、保存したときに書き込まれます。

新しいカスタム名は、保存によって共有タグが作成または再利用され、1 つのトランザクションでこの作品に付与されるまで、下書きのままです。キャンセルすると、共有のエントリは残りません。トリミングして大文字小文字を無視した後に、既知のいずれかの言語の名前と一致する場合は、そのタグが再利用されるため、繰り返しクリックしたり名前が重複したりしても、重複した概念は作成されません。

メタデータの言語を切り替えると、そのバージョンの手動または辞書のタグ名が利用可能な場合はそれが使われ、なければ優先言語にフォールバックします。どのバージョンでも同じタグが表示され、それらは原版から取得されるため、切り替えてもタグの名前が変わるだけで、追加されたり除外されたりすることはありません。追加、削除、最終ターゲットの非表示、統合のマッピングは引き続き適用されます。スナップショットのみのタグは、それ自身の射影が完了するまで表示されたままで、すべてのタグを削除すると、意図的に空の表示になります。

日本語のみの作品は、バックグラウンドの **タグ名を学習** ワークフローがそれらの名前を学習した後、優先言語でタグを表示します。それまでは、タグは日本語の名前にフォールバックします。タイトルは日本語のままです。

補完では、統合された名前は最終的なタグとして表示されます。非表示のターゲットへの統合を含め、非表示のタグに一致するものにはラベルが付き、追加できません。先にメタデータで非表示を解除してください。名前は、[設定](settings.md)で説明されている言語の優先順位に従います。

バックグラウンドの更新が完了するまで、メタデータが更新されても、作品は最後に保存されたタグのセット（空のセットを含む）を保持します。声優ページのリモート作品の一覧には、手動で追加した共有タグと並んでリモートのタグが表示されます。

## AIで翻訳

**AIで翻訳** は、作品に足りない他言語の内容を補います。対象は、タイトルと説明、共有タグの名前、ローカルのファイルとフォルダーの表示名、ローカルトラックの歌詞です。歌詞のないトラックは、先に音声認識（ASR）サービスで文字起こしでき、それ以外は LLM プロバイダーが翻訳します。各ステップは、どれを使うかを示します。ライブラリの書き込み権限を持つアカウントは、ローカルソースのオプションにある **歌詞を管理** や **表示名を編集** の隣から、またはメタデータエディターのフッターにある **その他** から、編集内容を保存または破棄した後に開きます。タイトル、説明、共有タグ名の翻訳にはメタデータ同期の権限も必要です。アカウントが翻訳できないカテゴリーは、理由とともに使用できない状態で表示され、ほかのカテゴリーは引き続き使えます。Demo ではこの機能は提供されません。

上部で翻訳先の言語を 1 つ以上選びます。作品の原語には印が付きます。表は、選んだ言語ごとに各カテゴリーを並べ、その言語に値のない対象の数を示します。すべてのカテゴリーが選択された状態で始まり、送信されるのは足りないものだけです。

- **タイトル** と **説明** は、その言語の版、手動の値、AI 翻訳のいずれもない言語で足りないものとして数えます。
- **共有タグ名** はタグごとに数えます。タグ名はそのタグを持つすべての作品で共有されるため、セルには何作品に表示されるかが示され、ほかの作品からすでにキューに入っている名前は、再送信されずに別のタスクで処理中として数えます。
- **ファイル名とフォルダー名** は名前ごとに数えます。原語の名前と、`Track01` や `mp3` のように言葉のない名前はスキップします。翻訳した名前が変えるのはディレクトリの表示だけで、ファイル自体の名前は変わりません。
- **歌詞** はトラックごとに数えます。**トラックと翻訳元の歌詞を選択** は、ローカルトラックを歌詞の言語に対して並べた表を開きます。緑のセルはその言語の歌詞があり、赤のセルはありません。選択した翻訳先にはプラスが表示されます。各トラックは、原語の歌詞、次にフォールバック歌詞、次に最初のその他の言語の歌詞から翻訳され、そのセルに翻訳元の印が付きます。同じ行の別の緑のセルをクリックすると、代わりにそのファイルから翻訳します。トラックと名前が一致するリモートの歌詞ファイルはそのトラックのフォールバック歌詞として扱われ、雲のマークが付きます。読み込むには管理者の有効化とリモート取得権限が必要です。

翻訳中のものは存在するものとして数えるため、二重に依頼されることはありません。**送信する内容** は、言語ごとに、リクエストの項目数、テキストの文字数、歌詞トラック数を合計します。**N 件を翻訳** は、この作品の AIで翻訳の実行を 1 件キューに入れます。各項目は完了するとすぐに適用されます。同じダイアログの **結果** タブと[翻訳ページ](translation.md)で実行の様子を確認できます。

### 音声からの歌詞

他の言語の歌詞があるトラックは、その歌詞から翻訳します。どの言語にも歌詞がないトラックは先に文字起こしが必要です。ダイアログには歌詞のないトラックの数が示され、既定でオンの **文字起こししてから翻訳** が、翻訳の前にそれらを文字起こしします。作品のどのトラックにも歌詞がない場合は、この旨の注記がダイアログの上部に表示され、ほかのカテゴリーはどちらの場合も翻訳できます。[音声認識サービス](settings.md#音声認識サービス)が設定されていない場合、ダイアログは設定へのリンクを表示し、これらのトラックはスキップされます。作品の原語が判明している必要があります。

各トラックは作品の原語で 1 回だけ文字起こしされ、選んだすべての言語は、ほかの翻訳ではなくその文字起こしから翻訳されます。文字起こしは、そのトラックの原語の歌詞にもなります。選んだ言語の歌詞を音声から直接書き出す音声モデル（たとえば日本語の音声から簡体字中国語を書き出す Kikoto Helper のモデル）は、文字起こしするトラックで選んだ言語がその 1 つだけの場合、直接書き出します。**音声から…を直接書き出す** をオフにすると、この動作を止められます。言語が 2 つ以上あるときは、モデルが原語を文字起こしし、すべての言語を LLM が翻訳します。

文字起こしは、完了するとすぐにそのトラックの原語の歌詞として書き込まれ、翻訳がそれに続きます。コンテンツ安全ポリシーが翻訳をブロックするテキストの文字起こしも書き込まれ、その翻訳には **ポリシーによりブロック** と表示されます。ASR と LLM が同じマシン（たとえば 1 つの Kikoto Helper）で動くときは、実行は一度に 1 件ずつリクエストを送るため、2 つのモデルが同時に読み込まれることはありません。文字起こしが失敗すると、それに依存する歌詞だけが止まります。

### 結果

各項目は、完了するとすぐに書き込まれます。書き込む前に、元のデータが変わっていないこと、コンテンツ安全ポリシーが許可していること、依頼者に今も権限があること、プロバイダーの設定が項目の送信時のものであることをあらためて確認します。確認に通らない項目は書き込まれず、理由とともに停止し、実行のほかの項目は続行します。

- タイトルまたは説明は、その言語の AI 翻訳になり、メタデータエディターで LLM の印が付き、プロバイダーの値や手動の値とは別に保持されます。そこで **取り消す** を選ぶと表示から外れ、元のデータが一致する限り **復元** で以前の値が戻ります。原文のフィールドが変わると、そのフィールドの翻訳は失効し、通常のメタデータ同期はそれ以外を保持します。
- タグ名は、タグや、どの作品が持つかを変えずに、そのタグのその言語の共有名になります。手動名、辞書の名前、プロバイダーの名前が優先します。
- 表示名は、その間にファイルまたはフォルダーがその言語の名前を得ていない限り書き込まれ、誰かが編集またはクリアするまで **表示名を編集** で LLM の印が付きます。
- 歌詞は、トラックの作品フォルダー内にある翻訳先言語の歌詞フォルダーに、トラック自身のパスと翻訳元ファイルの拡張子（文字起こしは `.vtt`）でファイルとして書き込まれ（例: `lyrics_kikoto/zh-hans/mp3/Track 01.lrc`）、トラックに割り当てられます。元の歌詞ファイルは変更されません。同じ名前の別のファイルまたはフォルダーがすでにある場合はそれを残し、新しいファイルは番号付きの名前で隣に保存します。歌詞フォルダーがあるべき場所に Kikoto が作成していないファイルまたはフォルダーがあると、歌詞は書き込まれず、結果は保持され、その場所が空いたら **再送信** が追加のリクエストなしで書き込みます。AI が作成した歌詞ファイルは、ほかの歌詞と同じく **歌詞を管理** で割り当て解除や削除ができます。

**結果** タブは、この作品の項目を言語、次にカテゴリーの順に一覧し、処理中のもの、停止したものとその理由、書き込まれたものを示し、歌詞の項目には作成されたファイルが表示されます。**プレビュー** は、他の歌詞と同じタイミング確認で歌詞ファイルの最初の数行を表示します。

### 歌詞の出典表記

音声認識または翻訳で作成した歌詞ファイルは、作成したモデル名を歌詞自身の言語で記した 1 行で始まります。簡体字中国語の翻訳なら「当前歌词由 example-model 翻译」、英語の音声なら「Lyrics generated by example-asr」、文字起こしと翻訳の両方を経た場合は両方のモデル名です。記載されるのはモデル名だけです。LRC には `[00:00.00]` の行、WebVTT と SRT には 0 から最初の行までのキュー、ASS には Dialogue 行、テキストには先頭行が追加されます。最初の行が 0 から始まる場合、出典表記はその行と一緒にその上に表示されます。翻訳元として使うファイルは、テキストを送る前にこの行が取り除かれ、翻訳には新しい行が付きます。プレビューのタイミング確認もこの行を除外します。プレーヤーはこのような歌詞に AI が作成した旨を表示し、モデル名を示します。管理者は[設定 → 音声認識・LLM](settings.md#ai-歌詞)でこの行をオフにでき、この設定はその後に作成するファイルに適用されます。

### 実行の流れ

AIで翻訳の実行は、作品のタイトル、説明、タグ名を言語ごとに 1 件のリクエストで、表示名を短い名前のバッチで、歌詞を上限のある部分に分けて送り、完了した部分を保持します。LRC、WebVTT、SRT、標準 ASS の Dialogue とテキストは時間軸とキューの順序を保ち、各行のテキストだけを翻訳します。歌詞の入力と出力は各 128 KiB、原本は 4,000 行、テキストの各行は 4,096 バイトまでです。各リクエストの前に、依頼者の権限、プロバイダーの設定、コンテンツ安全ポリシー、元のデータをあらためて確認します。[コンテンツ安全ポリシー](settings.md#コンテンツ安全ポリシー)は、音声を送る前に作品のメタデータを、翻訳する前にテキスト全文を確認します。プロバイダーが拒否したリクエストや、一時的に利用できない元のファイルはその項目を失敗とし、翻訳ページの **再送信** で再びキューに入れます。元のデータ、プロバイダー、コンテンツポリシーが変わった項目は、作品からの新しいリクエストで再び翻訳されます。再起動またはキャンセルで中断されたリクエストは結果不明となり、**再送信** はプロバイダーが二重に課金する可能性があることの確認を求めます。実行をキャンセルすると、まだ送っていないものはすべて停止します。管理者向けに、Activity が実行の診断情報を保持します。

## 文字起こし

**歌詞を管理 → 文字起こし** は、設定済みの[音声認識サービス](settings.md#音声認識サービス)でローカルトラックの音声をタイムスタンプ付きの歌詞に 1 言語ずつ変換します。文字起こしと翻訳をまとめて行うには、[AIで翻訳](#音声からの歌詞)を使います。このタブには、作品のローカル音声ファイルが、それぞれ歌詞のある言語とともにフォルダーごとに一覧されます。一覧の上のフィルターは、**歌詞なし**（初期値）のトラック、作品の原語の歌詞がないトラック（**日本語の歌詞なし** など）、または **すべて** のトラックを表示します。トラックを選ぶか、一覧の先頭から表示中のすべてのトラックを選ぶと、下部のバーで **音声の言語**、**歌詞の言語**、サービスとモデルを選べ、**文字起こし** は選んだトラックごとに 1 件の文字起こしをキューに入れます。音声の言語は音声で話されている言語です。初期値は作品の原語で、ヒントとしてサービスに送られます。**自動検出** ではサービスが判断します。歌詞の言語は、結果を保存・割り当てる言語です。**音声の言語と同じ** は初期状態でオンで、そのとき歌詞の言語は音声の言語になり、検出された音声はフォールバック歌詞として保存されます。翻訳するモデル（たとえば日本語の音声から簡体字中国語を書き出す Kikoto Helper のモデル）は、自分の歌詞の言語で書き出します。そのモデルを選ぶと、音声の言語がモデルの入力言語に設定され、**音声の言語と同じ** がオフになり、歌詞の言語がモデルの書き出す言語に設定されます。**音声の言語と同じ** をオフにすると別の歌詞の言語を選べます。選んだモデルがその音声の言語からその言語を書き出せない間は、**文字起こし** は使用できず、バーの下に注記が表示されます。共有の[コンテンツ安全ポリシー](settings.md#コンテンツ安全ポリシー)で作品のメタデータとサービスの受信上限を照合します。音声自体は検査しません。フィルターの隣にある **区分を確認** は何も送信せずに作品の区分を表示し、受け取れないサービスに印を付けます。確認は押したときにだけ実行されます。すでに文字起こし中のトラックが二重にキューへ入ることはなく、トラックの行には開いている文字起こしの状態が表示されます。

文字起こしは Activity のワークフローです。Kikoto はトラックを自分でデコードし、16 kHz モノラル音声を最長 5 分ずつの部分に分けて送ります。各部分は末尾 1 分間のうち最も静かな位置で区切るため、区切りは単語の間に来ます。完了した部分は保持され、ワークフローは部分の合間に待機中の他の処理へキューを譲るので、長いトラックがスキャンや Fetch を妨げることはありません。各部分の送信前に、サービス設定、コンテンツポリシー、権限、音声ファイルが変わっていないか再確認します。再起動で中断されたリクエストや、サービスが拒否した部分があると文字起こしは停止し、Activity の **再試行** は最後に完了した部分の続きから、中断された部分を再送して再開します。実行をキャンセルすると停止します。

完了した文字起こしはトラック一覧の下の一覧で確認を待ちます。**プレビュー** は他の歌詞と同じタイミング確認で最初の数行を表示します。**歌詞に追加** は、トラックの作品フォルダー内にある、その言語の歌詞フォルダーに、トラック自身のパスに沿った WebVTT ファイルとして保存し（例: `lyrics_kikoto/ja/mp3/Track 01.vtt`）、トラックに割り当てます。[出典表記](#歌詞の出典表記)がオンの間、ファイルはその行で始まります。同じ名前の別のファイルまたはフォルダーがすでにある場合はそれを残し、文字起こしは番号付きの名前で隣に保存します。歌詞フォルダー、またはその中のフォルダーがあるべき場所に Kikoto が作成していないファイルまたはフォルダーがあると、その名前を変えるか移動するまで **歌詞に追加** は実行できず、文字起こしは保持されます。不要な文字起こしは **破棄** で削除します。歌詞への追加が完了しなかった場合は結果が保持され、**歌詞に追加** で再試行できます。

デモでは、このタブに作品のトラックの文字起こしサンプルと例のサービスが表示されます。音声は送信されず、**プレビュー** にはサンプルのテキストが表示され、**区分を確認**、**文字起こし**、**歌詞に追加**、**破棄** は使用できません。

## カスタム作品

[カスタム作品](settings.md#メタデータ)にはプロバイダーのメタデータもリモートソースもありません。詳細には DLsite のリンク、DLsite の評価、販売数、メタデータの通知が表示されず、メタデータの更新、リモートソースのタブ、ソース確認も用意されません。ディレクトリにはローカルフォルダーだけが一覧されます。メタデータエディターには **編集用に取得** もリンクセクションもないため、カスタム作品ではメタデータのリンク、購入特典の親、セット内容を設定できません。タイトル、作品紹介、年齢区分、カバー、タグ、クレジットは手作業で編集します。**ファイルを管理** と **歌詞を管理** の **歌詞ファイル** タブには、ローカルフォルダーと版だけが一覧されます。フォルダーが見つからないとき、ディレクトリには、フォルダー名に `[KT00000001]` のように角括弧で囲んだ KT コードが付けばスキャンで作品が再び見つかることが説明されます。カバーはローカル画像から選び、カバーをリセットすると代わりに作品番号が表示されます。

## 購入特典

早期購入特典（`【早期購入特典】`）などの購入特典は、独自のファイルを持つ DLsite の独立した商品ですが、DLsite はそれがどの作品に属するかを示しません。メタデータ同期はそれを親の作品にリンクでき（[購入特典](settings.md#購入特典)を参照）、ライブラリのエディターでは、エディターのリンクセクションにある **購入特典** で、親のコードを入力または削除できます。リンクされた特典は別の作品のままで、独自のタイトル、カバー、ファイル、再生の進捗、ライブラリのカードを保持し、不足しているタグ、声優、シリーズを親から引き継ぎます。その詳細には、親の作品とともに **特典の対象** が表示されます。親がライブラリにない場合は、DLsite へのリンク付きの親のコードが表示されます。親の詳細には、同じファミリーの別の版にリンクされた特典を含め、ライブラリにある **購入特典** が一覧されます。親のコードがライブラリの作品になることはありません。リンクを削除すると、その作品の自動検出も停止し、次の更新で継承された値が取り除かれます。

## セット作品

公式セットは、たとえば `コンプリートパック` やセット販売のように、単体でも販売されている作品を収録した DLsite の独立した商品です。DLsite が内容を示すのは一部のセットだけで、メタデータ同期はそれらを自動で一覧します。それ以外は、ライブラリのエディターで、エディターのリンクセクションにある **セットの内容** に収録する作品を一覧します: 作品コードを入力するか、タイトルがセットらしい場合にセクションが提案する、セットの DLsite シリーズの作品を追加します（そうでない場合は **表示** で提案を開きます）。変更は保存時に反映されます。セットの詳細には含まれる作品とともに **収録作品** が表示され、各作品の詳細にはセットとともに **収録先** が表示されます。ライブラリにないコードは DLsite へのリンク付きで表示されます。セットと各作品は、それぞれ独自のファイル、再生の進捗、ライブラリのカードを持つ別の作品のままで、セットに含まれる作品がセットのファイルから再生されることはありません。削除した作品がメタデータ同期で再び一覧されることはありません。ライブラリで作品の番号やタイトルを検索すると、その作品を収録したセットも見つかります。

## 現在の動作

- 作品コードで読み込み、翻訳された DLsite ファミリーのルートを解決します。
- カバー、タイトル、コード、サークル、タグ、評価、声優のメタデータ、DLsite へのリンクを表示します。
- マークの操作の横に、あなたの評価を星と数字で表示します。未評価の作品は、**評価** というラベルの付いた空の星になります。選ぶと 5 つの星が開き、作品を星 1 から星 5 で評価できます。評価済みの場合は **評価を取り消す** も表示されます。[作品カード](library.md#現在の動作)には、**評価** のラベルを除いた同じ操作があります。この評価は個人のもので、DLsite の評価とは別であり、[おすすめ](library.md)の主な証拠になります。
- 論理的な作品ファミリーの既知の言語版を表示します。
- メタデータ言語とディレクトリ版のセレクターは、作品コードの横にある 2 つの別々のコンパクトなチップのままです。各チップは現在の選択を示し、それぞれ独自のリストを開きます。原版のディレクトリ版は `原版 · <language>` と表示されます。スマートフォンでは作品コードと 2 つのチップが 1 行に収まり、チップは言語をコード（`JA`、`EN`、簡体字中国語は `SC`、繁体字中国語は `TC`、`KO`）で示し、メタデータのチップは原語の印を省き、原版のディレクトリ版は `原版` と表示されます。リストには言語名がそのまま表示されます。バリアントが 1 つしかない場合、メタデータのチップは読み取り専用のラベルになります。ローカルの作品では、メタデータは既定で優先メタデータ言語になります。リモートのみの作品では、ソースが記述している言語のうち、お客様の言語の中で最初のものが既定になり、次にソースのフォールバック言語が使われます。一時的に切り替えると、表示されるタイトルとタグ名が変わりますが、保存はされません。原版のバリアントは、設定された既定が選択されたままの間は、常に最初に一覧されます。
- ディレクトリ版は、メタデータの利用可能状態ではなく、ファイルの利用可能状態として扱います。保存されたローカルのコンテキストでは、折りたたまれたセレクターにはローカルフォルダーまたはローカルメディアのある版だけが表示され、展開するとすべての既知の版が表示されます。リモートの兄弟版は、そのソースが自身のデータベースで報告している場合にのみ選択できます。ローカルで利用可能な兄弟版は、選択したリモートソースにそれが含まれていなくても、そのローカルディレクトリを通じて選択できます。リモートのコンテキストでは、代わりに既定でソースが報告する利用可能状態が使われます。
- メタデータのみ、リモートのみ、利用不可の版も、ローカル再生を暗示することなく表示します。
- カードから渡された、またはコードから解決されたプレビューを最初に描画し、その後、基本の詳細とメディアツリーを別々の段階として読み込みます。
- カードや履歴のプレビューで既知の作品 ID を保持するため、お気に入りなどのコレクションのルートが、ライブラリの読み込みと冗長なコード解決を競合させることがありません。
- 保存済みとリモートのみのアイデンティティコントローラーに対して、1 つのレスポンシブなページコンポーザーを使用します。どちらも、戻る、ヒーロー、モバイルの情報／ディレクトリ、デスクトップのディレクトリ、モーダルの配置を共有しますが、リモートのみのプレビューに保存された状態を与えることはありません。
- モバイルの戻るコントロールは、サーバーとユーザーごとに記録された最後のライブラリ一覧の位置への「上へ」として扱います。幅の広いレイアウトでは、ソースを考慮した履歴の戻りを維持します。
- ローカルのメディアファイルは、メディアの段階で具体的なツリーが必要になったときにのみ、遅延してインデックスされます。完了した空のスキャンは、ライブラリのスキャンでその状態が無効になるまで記憶されます。
- 同じメディアを持つ作品の同時インデックスをまとめ、最初のインデックス時のファイルあたりのデータベース文を減らします。遅い収集と書き込みの段階は、診断のために別々にログに記録されます。
- ソースの利用可能状態は、バックエンドの集約チェックで読み込みます。
- 利用可能状態が分かった後で、リモートソースのツリーを遅延して開きます。明示的な保存済みのリモートソースのルートは、集約された確認の前に、識別されたソースを読み込むことができ、読み込みに成功すると、現在の詳細で利用可能としてマークします。
- 可変の高さのディレクトリ行で、スペースのない長い名前も含め、フォルダーとファイルの完全な名前を折り返し、ページが横にあふれることはありません。
- ディレクトリのパンくずを 1 行に保ちます。モバイルでは中間の祖先がメニューにまとめられ、デスクトップでは表示される各セグメントを制限して、現在のフォルダーがスクロールして見える状態を保ちます。完全な名前は、行、祖先のコマンド、タイトル、アクセシブルなラベルから引き続き確認できます。
- 選択したソースの操作は 1 か所にまとまります。幅の広いページではソース情報に、コンパクトな画面では情報タブに直接並び、その中間の幅ではヒーローのアクションバーのソースメニューになります。メニューのアイコンはローカル、追跡済み、リモートの各コンテキストで変わり、ヘッダーには選択したソースが示され、外側の操作、Escape、ソースの変更で閉じます。
- 追跡済みの存在を 1 つの追跡済みタブに集約します。作品が複数のファイルソースで追跡されている場合、タブにはドロップダウンが表示され、タブの行にソース名を追加することなく、アクティブな追跡済みディレクトリを切り替えられます。
- ディレクトリの説明に、選択した追跡済みソース名を使用し、その選択を詳細の URL に保持します。
- カバーから色を付けた背景を持つヒーローで開きます。カバーの横には、DLsite へのリンクと言語チップ付きの作品コード、タイトル、サークル、シリーズ、CV のクレジット行、1 行のタグ、コンパクトな統計ストリップ（DLsite の評価、あなたの評価、年齢区分、販売数、発売日、再生可能な時間。スマートフォンでは 1 行）、メタデータの通知、下端に揃えられたヒーローのアクションが表示されます。タグの行にはプロバイダーのタグが最初に並び、続いて独自のアクセントスタイルでユーザーの個人タグが並び、最後に追加または編集のアイコンが付きます。長いプロバイダーのタグのリストは `+N` コントロールの背後に折りたたまれます。プロバイダーのタグまたは個人タグを選択すると、詳細を開いた元のライブラリ検索に `tag:` または `mytag:` の句が追加されます。別のページから詳細を開いた後で個人タグを選択すると、新しいローカルのライブラリ検索が始まります。ディレクトリは、その下のメインの列を占めます。ソース情報とメタデータの更新時刻は 1 つのパネルを共有し、幅の広いページではディレクトリの横に、狭いページではその後に続けて表示されます。ソース情報には、ファイル／音声の数、サイズと再生時間の網羅状況が報告され、ソースの再生時間を黙って置き換えるのではなく、メタデータの再生時間へのフォールバックにラベルが付きます。そのパネルの下の「クレジット」カードには、声優以外に DLsite がクレジットしているスタッフ（作者、シナリオ、イラスト、音楽、その他）が一覧表示されます。作品がクレジットしている役割だけが表示され、DLsite がスタッフを挙げていない場合はカード自体が表示されません。名前を選択すると、詳細を開いた元のライブラリ検索に `staff:` の句が追加され、どのスタッフの役割でもその名前が見つかります。コンパクトな画面では、ヒーローが同じクレジット行、タグの行、統計ストリップを保ち、「再開」、マーク、評価、リストのアクションを情報とディレクトリのタブの上の 1 行に並べます。アクションが収まらないときは、この行が横にスクロールします。スマートフォンでは「再開」をアイコンだけで表示し、マーク、評価、リストにはラベルを付けます。情報にはソースパネルと「クレジット」カードが表示されます。ソースパネルには選択したソースの操作が並び、メタデータの更新時刻の横に「メタデータを編集」があります。スマートフォンではタイトルは最大 3 行で表示され、省略されている場合はタイトルをタップすると全文が表示されます。作品コードの行の右端にあるボタンは作品情報を隠し、作品コード、メタデータの通知、アクションだけを残します。この選択はその端末に記憶され、ほかの作品を開いても保たれます。
- ディレクトリは 1 つのパネルとして表示されます。ファイルのサマリーとソース確認を含むヘッダー、ステータスのドット付きの下線式ソースタブ、フォルダーエクスプローラーです。スマートフォンでは、選択中のディレクトリタブの矢印から **ソースタブの表示** の一覧を開け、その下に **ソースを確認** があります。ファイル名とフォルダー名は 2 行までで表示されます。ディレクトリ右上の **全文表示** で全文を表示でき、この選択はその端末に記憶されます。ディレクトリが十分に広く、作品にフォルダーがある場合は、選択したフォルダーの内容の横に固定のフォルダー列が表示されます。そうでない場合は、フォルダーボタンが、スマートフォンではボトムシートとして、それ以外ではポップオーバーとして、同じナビゲーターを開きます。列のヘッダーにある **フォルダーパネルを隠す** を選ぶと、内容が全幅で表示され、フォルダーボタンの横に **フォルダーパネルを表示** が残ります。この選択はそのデバイスに記憶されます。ナビゲーターは、自然順に並べたフォルダーを再生可能なファイルまたは画像の数とともに一覧し、小さなツリーは完全に、大きなツリーは選択中、おすすめ、再生中のフォルダーに向けて開き、1 つのサブフォルダーだけを持つフォルダーを 1 つの行にまとめ、おすすめのフォルダーと再生中のフォルダーに印を付けます。
- フォルダーのルーティングルールが推奨するフォルダーで開きます。内容のツールバーには、上へのコントロールとパンくず、フォルダーのトラック数と再生時間、おすすめバッジ（またはおすすめのフォルダーに戻るコマンド）、折りたたまれた歌詞の数、現在のフォルダーの再生可能なファイルを対象とするすべて再生コマンドが表示されます。
- フォルダーの内容は、サブフォルダーのタイル、アルバム形式のトラックリスト、画像ギャラリー、ドキュメント、その他のファイルにグループ化され、複数のグループがある場合はグループにラベルが付きます。サブフォルダーのタイルは、含まれる内容を要約し、再生可能なファイルがある場合は直接再生するコマンドを提供します。トラックにはフォルダーの再生順に番号が付き、名前の上にサイズと作品の再開位置、末尾の列に正確な再生時間が表示されます。ホバーすると再生のキューが表示され、現在のトラックはアクセント色の行とライブアイコンで示されます。再開のマーカーは、再読み込みなしで再生の保存に追従します。ローカルとキャッシュされた画像には、遅延読み込みのサムネイルが表示され、リモートの画像はプレビューするときにだけ読み込まれます。
- 一致した同じフォルダーの歌詞サイドカーは、既定のディレクトリ行から折りたたまれ、一致しないテキストは表示されたままになります。音声行には、歌詞の選択、プレビュー、表示のアクションがあり、ディレクトリのコントロールで折りたたまれたすべての歌詞を表示できます。ファイル管理と Fetch の選択では、歌詞を折りたたみません。
- ローカルのファイルやフォルダーは、メタデータ言語のうち表示名がある最初の言語の表示名で表示され、なければ実際の名前で表示されます。そうした名前があるディレクトリでは、ディレクトリ右上に **表示名** ボタンが現れ、表示名を表示している間は強調表示されます。ツールチップで実際のファイル名ではないことを示し、オフにすると実際の名前を表示します。この選択はその端末に記憶され、名前を変えた項目はツールチップに実際の名前を残します。プレーヤー、キュー、画面歌詞、システムのメディアコントロールも同じ名前でトラックを表示し、同じ選択に従います。メタデータ言語を変えたり名前を保存したりすると、キューのトラックは再生を止めずに新しい名前になります。並び順、トラック番号、おすすめフォルダー、歌詞の照合は実際の名前で決まり、ファイル管理、Fetch、プレビュー、ダウンロードも実際の名前を使います。ライブラリ書き込み権限のあるユーザーは、ローカルソースの **表示名を編集** オプションで言語ごとに名前を編集します。空欄は実際の名前を表示し、ファイルは自分の拡張子を保ちます。**実際の名前をコピー** と **名前を貼り付け** で、1 行 1 名のリスト全体を書き出して戻せます。**ファイルを管理** で移動したファイルやフォルダーは名前を保ち、Kikoto の外で名前を変えたものは名前を失います。
- ローカルソースの **歌詞を管理** オプションは、歌詞の選択肢を持つすべてのローカル音声ファイルを一覧します。ライブラリの書き込み権限を持つユーザーは、音声と名前が一致しない翻訳歌詞を含め、作品の任意のローカル歌詞ファイルを割り当てたり、歌詞フォルダーをトラック番号（または両方のフォルダーが同じ数のファイルを持つ場合は位置）でトラックに合わせたりできます。各フォルダーと言語の切り替えには歌詞のあるトラック数が表示され、ファイル名の一致に任せたトラックや歌詞のないトラックの選択欄は破線で示されます。広い画面では選んだトラックの歌詞が一覧の横に表示され、狭い画面では各行が最初の数行をプレビューします。どちらも、最後のタイム付きの行がトラックの終了後に始まる場合は警告します。割り当てはすべてのリスナーで共有され、自動の選択になりますが、リスナー自身の選択が引き続き優先されます。
- トラックには、言語ごとに 1 つの歌詞ファイルを指定できます。**歌詞の言語** のストリップで **フォールバック**、日本語、簡体字中国語、繁体字中国語、英語、韓国語を切り替えられ、それぞれの言語で歌詞のあるトラックの数が表示されます。**フォールバック** の歌詞は、リスナーのどの言語にも歌詞がない場合に使われ、指定のないトラックがファイル名の照合にフォールバックするのも、ここだけです。再生では、リスナーの優先メタデータ言語のうち歌詞がある最初の言語、次にフォールバック歌詞、最後にその他の言語が使われます。ファイルの言語は自分で宣言します。Kikoto がファイルから推測することはありません。
- **歌詞を管理** には、ローカルファイルを管理するユーザー向けの **歌詞ファイル** タブがあります。Kikoto は、作品フォルダー内の 1 つの `lyrics_kikoto` フォルダーで歌詞を管理し、言語ごとに言語名のフォルダーに置きます: `ja`、`en`、`zh-hans`、`zh-hant`、`ko`、およびフォールバック歌詞用の `fallback` です（例: `lyrics_kikoto/ja`）。Kikoto は自分で作成した `lyrics_kikoto` フォルダーに自分のものである印を付けます。作品に付属する歌詞フォルダー（`lyrics` など）は作品自身のファイルです。その歌詞は **このフォルダーのその他の歌詞** に表示され、Kikoto がそこに歌詞を追加したり、管理中の歌詞として削除したりすることはありません。Kikoto が作成していない `lyrics_kikoto` フォルダーや同名のファイルがあると、その名前を変えるか移動するまで歌詞を追加できません。このタブでは **ファイルを管理** と同じく 3 列で編集します。左列は歌詞の取得元、中央列は選んだ取得元の歌詞ファイル、右列は編集後の管理中の歌詞です。作品にローカルフォルダーが複数ある場合は、右列で編集するフォルダーを選びます。
- 取得元は次のとおりです。**管理中の歌詞** ではチェックを外したファイルが削除されます。**このフォルダーのその他の歌詞** で選択したファイルは歌詞フォルダーにコピーされて元の場所にも残ります。**作品自身のファイル** を **lyrics_kikoto に移動** にすると移動します。この選択は管理者の[既定](settings.md#ライブラリ)から始まり、変更しない限りコピーです。作品の他のローカルフォルダー（ライブラリ内の別の版を含む）のファイルはコピーされ、設定済みのリモートソースが提供する版のファイルはダウンロードされます。選択したファイルは、その取得元の **この歌詞の言語** で選んだ言語の歌詞フォルダーに入ります。別の版の歌詞は最初その版の言語になります。Kikoto は作品自身のファイルの言語を推測しないため、プレビューの前に言語を選びます。管理中の歌詞の言語を変えるには、**このフォルダーのその他の歌詞** で **管理中の歌詞も表示して言語を変更する** をオンにし、そこで選択します。これらはコピー中でも新しい言語に移動します。ファイルは取得元でのパスを保ちますが、すでに入っている歌詞フォルダーは除かれます。
- 右列には結果がプレビューされます。同じ内容のファイルがすでにある場合はそのままです。同じ名前の別のファイルは競合となり、右列で解決します: 既存のファイルを残す、置き換える、両方残す、または追加するファイルの名前を変える、のいずれかで、先に削除する必要はありません。邪魔になるフォルダーやファイルは **ファイルを管理** と同じように扱われます。**変更を適用** はファイルを削除する前に確認を求めます。ライブラリの書き込み権限があれば、**追加した歌詞を一致するトラックに割り当てる** により、追加した各ファイルをファイル名、次にトラック順で一致したトラックにその言語で割り当てます。その言語の歌詞がすでにあるトラックは変わりません。移動したファイルを使う割り当ては、そのファイルの言語に移ります。コピーしたファイルは別のファイルで、作品自身のファイルは割り当てを保ちます。読み取ったリモートの版はライブラリに追加されません。
- **歌詞を管理** には、ライブラリ書き込みとワークフローの権限を持つユーザー向けに、[音声認識サービス](settings.md#音声認識サービス)が設定されている場合に **文字起こし** タブがあります。[文字起こし](#文字起こし)を参照してください。デモではサンプルとともに表示されます。
- ローカル作品の **ファイルを管理** は、ローカルファイルを管理できるユーザー向けにファイルワークスペースを開きます。変更するのは作品の 1 つのローカルフォルダー、**このフォルダー** だけで、それ以外の場所はすべてコピーまたはダウンロードの元になるソースです。場所は、**このフォルダー**、作品の各エディションのほかのローカルフォルダー、設定済みのリモートソースが最後に提供していると確認された各エディションで、それぞれの場所で編集が何をできるかが、文言、アイコン、固有の色で示されます。**このフォルダー** は **編集対象**、ほかのローカルフォルダーは **コピー** か **統合** を選べ、リモートエディションは **読み取り専用** です。場所のファイルは最初に表示されるときに読み込まれるため、**このフォルダー** はすぐに表示され、リモートエディションは開いたときに初めて読み取られます。**リモート** の横の **ソースを確認** は、ソースを確認できるユーザー向けで、応答するすべてのリモートソースに作品の各エディションをあらためて問い合わせ、一覧を更新します。それ以外のユーザーと、追跡済みソースの **キャッシュを管理** には、ソースのファイルが一覧され、選択して削除できます。
- スマートフォンや狭いウィンドウでは、ワークスペースに 4 つのビューがあります。**ソース**、選んだ場所のファイルを表示する **選択**、編集後のフォルダーを表示する **最終フォルダー**、そして **削除予定** です。**同一ファイルを探す** で同一ファイルが見つかると、5 つ目のビュー **同一** も表示されます。**選択** では、**このフォルダー** の選択したファイルは保持され、チェックを外したファイルは編集を適用すると削除されます。**すべて残す** と **すべて削除** は、すべてのファイルに対してこれを行います。ほかの場所で選択したファイルは追加されます。**最終フォルダー** は各ファイルを保持、移動、コピー、ダウンロード、置き換え、既にありますのいずれかで示し、選んだばかりのファイルは、プレビューに反映されるまで確認中と示されます。
- 幅がおよそ 1280 ピクセル以上になると、ワークスペースは固定の 3 列になります。左にほかの場所、中央に **このフォルダー**、右に **削除予定** を表示します。**このフォルダー** は常に編集後のフォルダーを表示します。左の列は、作品のほかのローカルフォルダーをまとめた案内と、どのソースが提供しているかにかかわらずすべてのリモート版をまとめた案内で始まり、それぞれに件数を示します。ローカルフォルダーの案内には、フォルダーごとに **コピー** か **統合** かが示されます。案内を開くと 1 つのフォルダーまたは版のファイルを表示し、ピッカーで同じ種類のほかの場所に切り替え、戻るボタンで案内に戻ります。リモート版は開いたときに読み込まれます。左からファイルやフォルダーを **このフォルダー** にドラッグするとそこにコピーされ、リモート版からの場合はダウンロードされます。**このフォルダー** の中でドラッグすると移動します。ドラッグがフォルダーの上にある間、そのフォルダーはドロップで何が行われるかを示し、**このフォルダー** はドロップで何が追加されたかを示します。ほかの場所はドロップを受け付けず、移動も削除もできません。そのメニューにはその理由が示され、編集で変わるのは **このフォルダー** だけです。
- **すべての変更を取り消す** は、選択、削除、移動、新しいフォルダーから、統合、歌詞の役割、競合の選択まで、編集の変更をすべて一度に破棄し、現在のフォルダーからやり直します。ディスク上は何も変わらないため確認はしません。次に何かを変更するまでは、状態表示の隣の **元に戻す** で取り消した変更を戻せます。
- ドラッグは近道です。各行には、タッチ画面とキーボード向けのメニューがあります。**このフォルダー** では、ファイルに **移動先** と **削除**、編集で追加されるファイルに **追加しない**、編集で削除されるファイルに **残す**、フォルダーに **新しいフォルダー**、**名前を変更**、**移動先**、**フォルダーを削除** があります。ほかの場所では、行き先のフォルダーを選ぶ **このフォルダーにコピー** または **このフォルダーにダウンロード** があります。中身のあるフォルダーを削除すると、先に確認があり、その中身は 1 つ上の階層へ移ります。ファイルやフォルダーの行き先にすでに同じ名前がある場合は、`01 (2).mp3` のように番号が付きます。選択を外したファイルは移動先の場所を手放すため、もう一度選択すると元のパスに戻ります。それでも 2 つのファイルが同じパスに置かれる場合、編集はそのパスを示し、どちらかを移動するか選択を外すまで待ちます。移動したファイルは再生の進捗、歌詞、そのほかの参照を保ちます。編集で空になったフォルダーは削除され、作成したフォルダーは空でも残ります。
- **削除予定** は、編集で削除されるものをフォルダー別に、数とサイズとともに一覧します。対象は、チェックを外した、または削除した **このフォルダー** のファイル、追加するファイルに置き換えられるファイル、このフォルダーに統合する各フォルダーです。**残す** は項目を編集から外します。これは適用前の編集内容であり、削除したファイルの行き先ではありません。編集を適用するまで何も削除されず、削除されたものは元に戻せません。
- **選択** の **まとめて選択** は、幅の広い **このフォルダー** のペインでは開いた状態で表示され、**このフォルダー** のファイルを形式で残すか削除します。
- **同一ファイルを探す** は **このフォルダー** の見出しにあり、作品のすべてのエディションとフォルダーのローカルファイルを内容で比較するため、翻訳版で名前が変わっている音声も、原版のものと同じと認識されます。開始前に動作が説明されます。大きなファイルほど時間がかかること、**中止** で比較を終了できること、ファイルに印を付けるだけであることです。完了すると、**このフォルダー** の何個のファイルに同一のコピーがあり、提案どおり削除するとどれだけ空きが増えるか、または同一のものがないことが 1 行で示されます。該当する各ファイルには、コピーの数と、別のコピーが別のフォルダー（**他の場所にも**）にあるか **このフォルダー** 内（**重複**）にあるかが、文字、アイコン、その場所の色で示されます。各フォルダーには同一ファイルの数が表示され、比較が完了すると開きます。**同一ファイルのみ表示** は、編集で削除されるファイルも含め、同一ファイルだけを取り消し線付きで表示し、それぞれに **残す** が付きます。幅の広いワークスペースでは、印を選ぶと、もう一方のコピーがあるフォルダーが左側で開き、そこにファイルが表示されます。同じトラックを再エンコードしたものなど、似ているだけのファイルは同一ではなく、印は付きません。
- **同一ファイルを確認** は、同一ファイルの組ごとに、すべてのコピーとその場所を一覧します。幅の広いワークスペースでは左側に、それ以外では **同一** ビューとして表示されます。**別のフォルダーにもある** には、内容が別のフォルダーまたはエディションにもあるファイルが並びます。ここにあるコピーは **削除予定** に入り、もう一方のコピーは残るため、内容は失われません。もう一方のコピーは参照用に表示されるだけで、編集が変更するのは **このフォルダー** だけです。**このフォルダー内で重複** では、各組で選んだ 1 つのコピーが残ります。Kikoto は、名前に `(1)`、`(copy)`、` - Copy` などのコピーの印がないコピーを最初に、次に所属するフォルダーが最も少ないもの、次に名前順で最初のものを提案します。**削除予定に加える** は組を選んだ状態にし、**残す** はそれを取り消します。**提案どおり削除予定に加える** はすべての組に対してこれを行います。これらはほかの選択と同様に編集を変更するため、**削除予定**、**すべての変更を取り消す**、**元に戻す** もそれに従い、すべてのコピーが削除予定になった組には、内容が失われることが示されます。
- Kikoto の `lyrics_kikoto` フォルダーには **Kikoto が管理する歌詞** と印が付き、その **歌詞を管理** は、ワークスペースの上で **歌詞を管理** を **歌詞ファイル** タブで開きます。ワークスペースは変更を保ち、その後のフォルダーの状態を表示します。このフォルダーは歌詞の役割を通してのみ整理されるため、それを含む選択をドラッグしてもドロップされません。**このフォルダー** にほかの歌詞ファイル（`.lrc`、`.vtt`、`.srt`、`.ass`、`.ssa`、`.txt`）があると、注記がその数を示し、**「歌詞を管理」で開く** が **歌詞ファイル** を **このフォルダーのその他の歌詞** で開いて、そこで言語ごとの歌詞にできます。
- ほかのローカルフォルダーには、目印の位置に **コピー** と **統合** があり、フォルダーごとに選べ、最初は **コピー** です。**コピー** は選んだファイルを取り込み、そのフォルダーは変更しません。**統合** はフォルダーのファイルが読み込まれてから選べ、オフラインのストレージプールにあるフォルダーは統合されません。統合するフォルダーは、まだ何も選択されていないときはすべてのファイルが取り込まれ、フォルダー全体が削除されることを示し、**削除予定** に表示されます。このフォルダーに編集でコピーされるものがそろうと、統合したフォルダーはまだ残っているものすべてとともに削除されます。**コピー** に戻すとフォルダーは残ります。リモートエディションのファイルはダウンロードされます。これには取得（Fetch）の権限も必要で、そのエディションはライブラリに追加されません。別の場所の歌詞ファイルは、そのパスのままではなく歌詞として追加できます。ファイル名の下で言語を選ぶか、その場所の選択した歌詞ファイルすべてについては **選択した歌詞ファイル** で言語を選ぶと、**歌詞ファイル** と同様に `lyrics_kikoto` 内のその言語のフォルダーに入ります。言語は利用者が指定し、Kikoto は推測しません。ライブラリへの書き込み権限がある場合、**追加した歌詞を一致するトラックに割り当てる** は、追加した各歌詞ファイルをその言語で、ファイル名、次にトラック順で一致するトラックに割り当てます。同じ編集で追加されるトラックも対象で、その言語の歌詞がすでにあるトラックは変わりません。同じ名前の別のファイルに重なる場合は競合になり、フォルダー内のファイルを保持する、置き換える、両方を残す、追加するファイルの名前を変える、のいずれかで解決します。同じ名前のフォルダーやリンクは置き換えられないため、それ以外の選択肢だけが表示されます。追加するパスのフォルダーがあるべき場所にファイルがある場合は、そのファイルを保持するか、追加するファイルを別のパスに名前変更するかの 2 つだけです。
- ファイルを削除する場合、**変更を適用** は 2 回の削除確認を求めます。統合するフォルダーがある場合は、まず統合するフォルダーの全ファイルを編集後のフォルダーと内容で比較し、そこに同一のコピーがなく、そのフォルダーの削除で失われる各ファイルを一覧にして、削除の前にもう一度確認します。リモートソースからダウンロードしたファイルは比較されません。NAS やシステムがファイルの横に置く `@eaDir` フォルダーや `Thumbs.db` などのメタデータは比較されず、統合したフォルダーとともに削除されます。比較の後に統合するフォルダーまたはこのフォルダーが変わった場合、編集は適用されず、統合をもう一度確認するよう求められます。編集は 1 つのアクティビティワークフローとして実行され、何かを削除、移動、または追加する前に、追加するファイルをすべて集め、ファイルは編集を適用してから変更されていない場合に限って削除し、統合したフォルダーは最後に、確認で一覧にしたファイルだけが変更されずに残り、確認でコピーが見つかった各ファイルの同一のコピーがこのフォルダーにまだある場合に限って削除します。そうでなければ編集は止まり、統合をもう一度確認するよう求めます。止まった編集を再試行すると、止まったところから続きます。取得（Fetch）がまだ進行中の作品のフォルダーは統合されません。完了するとディレクトリが再読み込みされます。
- ワークスペースの上にある **フォルダーを削除して作品を忘れる** は、フォルダー全体とそのファイルのすべてのコピーを削除し、ソースが残らなければ作品を忘れます。編集のファイル変更とは別になっており、2 回の確認を求め、作品を忘れることができるユーザーに、作品のローカルフォルダーが 1 つだけの間は表示されます。オフラインのストレージプールにあるフォルダーは、ディスクがマウントされるまでファイルの代わりに通知を表示します。
- スキャンで作品のコードが複数のローカルフォルダーに見つかった場合、そのすべてが保持されます。ディレクトリにはコピーごとに 1 つのフォルダーが表示され、**ファイルを管理** は **フォルダー** の選択で 1 つのフォルダーずつ一覧し、作品を忘れることができるのは、フォルダーが 1 つだけ残ったときに限られます。ライブラリの書き込み権限を持つユーザーには、作品が複数のフォルダーにある場合、またはライブラリにその別の版がある場合、ディレクトリの上に通知が表示され、**歌詞を管理** と **ファイルを管理** から、歌詞を 1 つのフォルダーにまとめ、同一のものを削除できます。
- 自然順に並べたフォルダーを、自然順に並べたファイルの前に一覧します。フォルダーの再生もその同じ表示順に従います。
- 画像やテキストなど、再生できない利用可能なファイルは、ディレクトリに残し、音声と音声を含む動画はまとめて、再生可能なソースの指標にカウントします。
- プレビューは、ヘッダーのコントロール、矢印キー、スマートフォンでのスワイプ、または画像のフィルムストリップで、フォルダー内の同じ種類のファイルを順に移動できるファイルビューアーで開きます。画像は暗いステージに置かれ、ウィンドウに合わせるか、クリックした点を中心に実寸で表示し、ドラッグでパンでき、寸法が報告されます。動画も同じステージを使用します。テキストは閲覧ビューで開き、LRC、WebVTT、SRT のファイルは、プレーヤーの歌詞と同じ方法で解析された、タイムスタンプ付きの行を表示し、LRC のヘッダータグと元のテキストの切り替えがあります。ビューアーには、テキストの「コピー」、ローカルおよびキャッシュされたファイルの「ダウンロード」、ローカル画像の「カバーを設定」があり、「カバーを設定」は確認のために 2 回目のクリックが必要で、数秒後または別の画像に移動するとリセットされます。スマートフォンでは画面全体に表示され、デスクトップでは浮動プレーヤーの上に開きます。
- ローカル、キャッシュ、リモートのテキストプレビューを、バイトオーダーマーク、宣言された文字セット、レガシーエンコーディングの自動検出を使い、元のファイルを書き換えることなく、必要に応じて UTF-8 に変換します。
- デスクトップのコンパクトプレーヤーが有効な間は、最後のキュー操作に届くよう、下部のスクロール領域を確保します。

## 操作

- 固定の再開操作を 1 つ表示します。未完了で正の値の作品カーソルがない場合は無効になります。ファイルを直接実行した場合は、先頭から開始します。
- クイック聴取ステータスを更新します。
- お気に入りリストのメンバーを管理します。作品がどのリストにも入っていない間、リストボタンにはプラス付きのリストアイコンと **リスト** というラベルが表示されます。入っている場合は、作品が入っているリストの名前が表示されます。複数のリストに入っている場合は、リスト順で先頭のリスト名と残りの件数が表示され、ツールチップにすべての名前が表示されます。このボタンは **リストに追加** を開きます。詳しくは[ライブラリ](library.md#現在の動作)を参照してください。
- 個人の作品タグを、プロバイダーのメタデータタグとは別に編集します。
- メタデータを同期します。
- 互換性のあるリモートソースから、同期／キャッシュ／取得を行います。
- 取得（Fetch）は、受け付けられた時点で選択したソースを利用可能として記録し、同じ正規の作品に対して、キューにある、または実行中の既存の Fetch を再利用します。
- 現在の訪問者が匿名の場合は、Fetch の準備リクエストの前にログインを開きます。
- ローカルフォルダーのある作品では、リモートソースの **取得（Fetch）** は、ローカルファイルの管理と取得ができるユーザーに対して、そのソースのエディションを選んだ状態で **ファイルを管理** を開きます。これらのユーザーには、ローカルフォルダーのない作品で、新しいフォルダーへの Fetch が同じ 3 列で開きます。ソースのエディションが先頭に並んで全ファイルが選択され、作品のほかのエディション、ソース、ローカルフォルダーからファイルを追加でき、歌詞ファイルは **ファイルを管理** と同様に、言語を指定した歌詞としてトラックへの割り当てとともに追加できます。その **最終フォルダー** は **ファイルを管理** と同様に整理されますが、ファイルのないフォルダーは作成されません。エディション自身のファイルが 1 回の Fetch になります。それ以外はすべて、Fetch がフォルダーを公開した後に フォルダー編集ワークフローで追加されるため、Fetch が公開するファイルと同じ場所に入るファイルは、先に解決すべき競合になります。そのワークフローが読み書きするストレージプールがオフラインの間は待機し、プールが戻ると開始されます。キューに追加できない場合は、アクティビティの Fetch の実行に理由が表示され、フォルダーには Fetch のファイルだけが残ります。保存先フォルダーの確認が必要な場合は、**通常の Fetch で確認** が取得ダイアログを開きます。それ以外のユーザーには取得ダイアログが開きます。
- 選択したソースのヒーローのソースメニューから、ソース固有の追跡、フォーク、取得、元のページを開く、キャッシュ、更新、ファイルメンテナンスの各コマンドを開きます。
- 選択したリモートソースを追跡し、閲覧可能なツリーを保存して、2 回目のフォークを必要とせずに、集約された追跡済みコンテキスト内の対応するソースを開きます。
- 可能な場合は、手動の上書きを編集します。
- メタデータエディターから、作品のメタデータを別の DLsite コードにリンクします。たとえば、特典版が販売終了となり、通常版のコードが異なる場合などです。その後のメタデータの更新では、リンクされたコードを読み取り、そのメタデータ、タグ、カバーをこの作品に保存します。リンクされたコードが別の作品になることはありません。作品自身のコードに記録がない場合は、メタデータが利用できないという通知から、エディターが直接開きます。

## 詳細の読み込みモデル

作品詳細は、まず既知のローカルデータベースの状態を優先し、より遅いリモート由来の状態は別に読み込む必要があります。

1. 任意の作品カードの画面からのルートプレビュー、または直接 URL の場合は軽量なコード解決。
2. 基本的な作品のメタデータ、ユーザーの状態、版、クレジット。
3. ローカルメディアとディレクトリツリー。
4. ソースの利用可能状態のサマリー。
5. ユーザーが開いた場合は、選択したリモートソースのツリー。

これにより、リモートソースの失敗がローカルの詳細シェルを妨げることがなくなります。
ディレクトリの段階では、安定したディレクトリ形状のスケルトンを使用します。メディアのエラーはそのスケルトンだけを置き換え、読み込まれたメタデータとアクションはそのまま残ります。
Fetch のパス選択とファイル管理のツリーは、対応するオプションコマンドが選択された後にのみ導出されます。
