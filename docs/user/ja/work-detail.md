# 作品詳細
[English](../en/work-detail.md) · [简体中文](../zh-Hans/work-detail.md) · [繁體中文](../zh-Hant/work-detail.md) · [日本語](../ja/work-detail.md) · [한국어](../ko/work-detail.md)

作品詳細では、1 つの作品に関するメタデータ、版、ファイルツリー、ソースの利用可能状態、再生操作を表示します。

## 多言語タイトル

エディターのタイトルセクションでは、日本語、簡体字中国語、繁体字中国語、英語、韓国語が最初に、それぞれ全幅の行として並びます。原語の行には `origin` バッジが、現在表示しているメタデータ言語の行には `current` バッジが付き、同じ行に両方が表示されることもあります。**全言語共通タイトル** はそれらの下の **タイトルの詳細設定** にあり、既定では折りたたまれています。既存の全言語共通タイトルがある場合は、編集やクリアのためにこの設定が自動的に開きます。ヒントには、全言語共通タイトルはすべての言語でプロバイダーのタイトルを上書きするが、言語別の手動タイトルが優先されること、そして版と説明は変わらないことが説明されています。各行自身の手動タイトルは編集可能なテキストで、プロバイダーのタイトルと継承されたタイトルはグレーのヒントのままであり、変更なしのまま保存されることはありません。各行には現在のソースが示され、手動タイトルや編集済みのタイトルには印が付きます。保存で送信されるのは変更されたフィールドとタイトル言語だけです。既存の手動タイトルをクリアする、またはその行で「元に戻す」を選ぶと、保存時にそのスコープが削除され、継承されたヒントをクリアしても何も変わりません。同じエディターは、メタデータ → 作品からも開けます。

メタデータ言語メニューには既知の版、言語別の手動タイトル、**LLM** と表示する承認済み翻訳が含まれます。LLM の選択は同じ作品のメタデータ表示に反映し、公式版や音声の別バージョンを作りません。原文へのフォールバックでは、未指定を含め、宣言された原語を保持します。[タイトルと説明の優先順位](../../architecture/data-model.md#manual-overrides-and-titles)を参照してください。

DLsite に作品の記録がなく、リモートソースが補完した場合、詳細の通知に **リモートソースで補完** と表示され、各ソースが補完した値が一覧されます。リモートのタイトルは、タイトルの順序では DLsite の後、作品自身のタイトルの前に来ます。言語を宣言しないため、言語の選択肢は増えず、テキストは変更されません。タイトルエディターにはそのソースが示されます。

プロバイダーの表示では、作品ファミリー内の原版以外の版はすべて翻訳として扱われ、第三者による翻訳も含まれます。先頭にある DLsite の言語版ラベル（`【简体中文版】` や `【ドイツ語版】` など）は 1 つだけが、その形式に基づいて取り除かれます。`【ASMR】` のようなラベル、中間にあるラベル、手動タイトルはそのまま残ります。各版のエントリは、非対応の言語を含め、それぞれ自身のタイトルを保持します。プロバイダーの生のタイトルとスナップショットは変更されません。カード、詳細、言語の選択肢、検索結果、新しい再生キューは同じ表示ルールを共有し、すべての手動タイトルは引き続き検索できます。紹介文はそのままプレーンテキストとして描画され、選択した版に従います。一致する版のない手動の言語では、原版の紹介文が使われます。

## メタデータの編集

プレビューでは安定したタグ ID による統合も選択できます。DLsite ファミリーの受け入れは独立した操作で、通常のフィールド保存では同族の版をライブラリに追加しません。

**編集用に取得** は、現在の値、取得した値、保存予定の 3 列で作品を比較します。言語範囲は実際に存在する版から作られ、正規版には Original が付きます。取得した値をそのまま使うとプロバイダーのメタデータとして保存され、既存の手動上書きが解除されます。保存予定の値を編集した場合だけ手動上書きになります。プレビューは期限切れになり、開いている間に作品が変更された場合は適用できません。

ヒーローの **メタデータ** ボタンから、エディターが直接開きます。**メタデータを更新** は左下にあり、通常の DLsite の更新を実行します。有効なリモートソースがメタデータに対応している場合は、隣の矢印から `<ソース名>から` の選択肢が開きます。いずれかを選択すると、そのソースからこの作品の最新のメタデータを要求します。手動の編集と DLsite の値の優先順位は変わらず、保存していないエディターの下書きもそのまま残ります。この明示的な更新には、自動のリモートフォールバックを有効にしておく必要はありません。

admin と super_admin は `library:write` で作品のメタデータを編集できます。保存で送信されるのは、エディターの初期値から変更されたフィールドだけです。カバーだけを選択しても、自動のタイトル、サークル、シリーズ、声優クレジットは保持されます。フィールドをクリアすると、そのフィールドの上書きだけがリセットされます。同じファミリー内のトリミングした DLsite のタイトルと完全に一致する既存の固定されたタイトルの上書きは、アップグレード時に削除されます。サークル、シリーズ、声優の上書きは保持されます。

エディターのフィールドは、タイトル、カバー、タグ、クレジット、メタデータ提供元のセクションに分類されます。未保存の変更があるセクションにはドットが表示され、フッターにそれらが一覧されます。手動のサークル、シリーズ、声優リスト、カバーに対する「元に戻す」、およびメタデータのリンクの追加や削除を含め、すべての変更は保存するまで下書きのままなので、セクションを切り替えても編集内容が失われることはありません。キャンセルでは、下書きを破棄する前に確認されます。サークル、シリーズ、声優には、既知のエントリにリンクする候補が表示されます。その識別子は名前の下に表示されたままで、「ID を編集」の下で引き続き編集できます。カバーは、作品のローカル画像のサムネイルグリッドから選択します。Ctrl+Enter で保存します。

セクションの上にある **メタデータの言語** のタブで、エディターに表示する言語を選びます。**すべての言語** に続いて、日本語、簡体字中国語、繁体字中国語、英語、韓国語が、作品にその言語の版があるかどうかにかかわらず並びます。**その他** は、言語が宣言されていない原版を含め、作品が持つ他の言語の版を開きます。いずれかを選ぶとそのタブが選択され、`その他 - ドイツ語` のように言語名が表示されます。タイトルとタグ名を保存できるのは上記の 5 言語だけなので、「その他」の版には提供元のタイトルと各タグの既定の名前が表示されます。5 言語のいずれかでは、タイトルセクションにその言語の行だけが表示され、タグセクションでは各タグがその言語の名前で表示されます。その言語の名前がないタグは、代わりに使われる名前がグレーで表示され、言語ボタンからはその言語の名前と全言語共通の名前だけが開きます。作品ファミリーの一覧には、選択した言語の版が表示されます。作品に付くタグ、カバー、クレジットは、どの言語でも同じです。

タグセクションでは、共有されたメタデータのタグを検索し、この作品に追加または削除できます。作品に DLsite のメタデータがなくても、カスタムタグを作成できます。「DLsite タグに戻す」は、その作品のタグの追加と削除をクリアします。共有された名前は優先メタデータ言語に従い、手動の名前と学習したジャンル名が使われます。日本語のみの作品でも、既知の中国語のタグ名を表示できます。バックグラウンドの更新が完了した後も、非表示のタグはどこでも非表示のままです。個人の「マイタグ」は、アカウントが所有する別のタグです。デモではエディターが読み取り専用で表示されます。

作品のタグは、タグ追加の入力欄の下に 1 行ずつ一覧表示され、各行の下に他の言語での名前が並びます。この作品に追加したタグには **追加** の印が付きます。各タグの言語ボタンを押すと、その行の中にすべての言語での名前が開き、全言語共通の名前と対応する各言語の名前が別々の行に表示されます。手動の名前は編集可能なテキストで、プロバイダーまたは学習した名前はグレーのヒントのままです。タグ名は共有されるため、名前を変更したタグは、それを持つすべての作品で変わります。パネルには、そのタグを共有している作品の数が表示されます。新しいカスタムタグは、入力された名前を全言語共通の名前として保持し、作成する前に他の言語の名前を設定することもできます。名前の編集は他のすべての変更と同様に下書きで、保存したときに書き込まれます。

新しいカスタム名は、保存によって共有タグが作成または再利用され、1 つのトランザクションでこの作品に付与されるまで、下書きのままです。キャンセルすると、共有のエントリは残りません。トリミングして大文字小文字を無視した後に、既知のいずれかの言語の名前と一致する場合は、そのタグが再利用されるため、繰り返しクリックしたり名前が重複したりしても、重複した概念は作成されません。

メタデータの言語を切り替えると、そのバージョンの手動または辞書のタグ名が利用可能な場合はそれが使われ、なければ優先言語にフォールバックします。どのバージョンでも同じタグが表示され、それらは原版から取得されるため、切り替えてもタグの名前が変わるだけで、追加されたり除外されたりすることはありません。追加、削除、最終ターゲットの非表示、統合のマッピングは引き続き適用されます。スナップショットのみのタグは、それ自身の射影が完了するまで表示されたままで、すべてのタグを削除すると、意図的に空の表示になります。

日本語のみの作品は、バックグラウンドの **タグ名を学習** ワークフローがそれらの名前を学習した後、優先言語でタグを表示します。それまでは、タグは日本語の名前にフォールバックします。タイトルは日本語のままです。

補完では、統合された名前は最終的なタグとして表示されます。非表示のターゲットへの統合を含め、非表示のタグに一致するものにはラベルが付き、追加できません。先にメタデータで非表示を解除してください。名前は、[設定](settings.md)で説明されている言語の優先順位に従います。

バックグラウンドの更新が完了するまで、メタデータが更新されても、作品は最後に保存されたタグのセット（空のセットを含む）を保持します。声優ページのリモート作品の一覧には、手動で追加した共有タグと並んでリモートのタグが表示されます。

## LLM 翻訳

判定方法は[コンテンツ安全ポリシー](settings.md#コンテンツ安全ポリシー)を参照してください。

メタデータ同期とライブラリ書き込み権限を持つ編集者は、メタデータエディターの **LLM 翻訳** から、プロバイダーとそのモデルの 1 つ、対象言語と送信項目を選びます。対象言語は、モデルが作品の原語からインターフェース言語へ翻訳できればその言語、できなければモデルが対応する言語で始まり、対応しない言語は選択できないものとして表示します。**送信せずに内容を確認** は設定したポリシーモードで今回のリクエストを判定します。判定、該当項目とルール ID を表示し、LLM には接続しません。ルールと接続先の境界は [Settings → LLM](settings.md#llm-プロバイダー) で設定します。

同期プレビューは 15 分、バックグラウンドプレビューは 24 時間有効で、再起動後も保持され、開始したユーザーと作品に結び付けられます。確定時に原文、現在の権限、ポリシーの版とモデル設定を再確認し、変更があれば失効します。レビューには確認待ち、承認、拒否と期限切れを表示します。確定したタイトルと説明は LLM の出典を別に保持し、提供元のスナップショットと手動値を上書きしません。通常の同期では翻訳を保持し、原文の変更は対応する項目だけを失効させます。**取り消す** は表示から外し、**復元** は原文の入力が一致する記録のみ再利用します。

**共有タグ名** は既存の共有タグで不足する言語名を翻訳し、手動名、提供元の名前と再利用できる承認済み翻訳を省きます。確定すると他の作品の共有名にも反映し、タグ ID と作品への関連は保持します。手動名と提供元の名前が優先します。名前の変更、非表示と統合は保持されたリスク情報を消しません。

歌詞は [歌詞を管理 → 翻訳](#翻訳) から翻訳します。

**バックグラウンド翻訳を開始** は明示した既存作品 1–100 件を受け付けます。同じ送信は永続タスクを再利用します。完了したタスクのプレビューが期限切れ、または確認済みの場合、再送信は新しいタスクを作り、元の Activity 記録を保持します。Activity に進捗、キャンセル、再起動復旧と失敗を表示します。実行時に権限、入力、ポリシーと選択した接続先を再確認し、完成した部分を保持します。明確な拒否と送信前の失敗は同じ接続先へ明示的に再試行できます。結果不明のリクエストは自動再送を停止し、**結果不明のリクエストを再送** は再課金の可能性の明示的な承認が必要です。接続先、モデル、ポリシーまたは入力が変わると再送できません。結果は必ずユーザーの確認を待ちます。

## 文字起こし

**歌詞を管理 → 文字起こし** は、設定済みの[音声認識サービス](settings.md#音声認識サービス)でローカルトラックの音声をタイムスタンプ付きの歌詞に変換します。このタブには、作品のローカル音声ファイルが、それぞれ歌詞のある言語とともにフォルダーごとに一覧されます。一覧の上のフィルターは、**歌詞なし**（初期値）のトラック、作品の原語の歌詞がないトラック（**日本語の歌詞なし** など）、または **すべて** のトラックを表示します。トラックを選ぶか、一覧の先頭から表示中のすべてのトラックを選ぶと、下部のバーで **音声の言語**、サービスとモデルを選べ、**文字起こし** は選んだトラックごとに 1 件の文字起こしをキューに入れます。音声の言語は音声で話されている言語です。初期値は作品の原語で、ヒントとしてサービスに送られ、結果はその言語で保存・割り当てされます。**自動検出** ではサービスが判断し、結果をフォールバック歌詞として保存します。共有の[コンテンツ安全ポリシー](settings.md#コンテンツ安全ポリシー)で作品のメタデータとサービスの受信上限を照合します。音声自体は検査しません。フィルターの隣にある **区分を確認** は何も送信せずに作品の区分を表示し、受け取れないサービスに印を付けます。確認は押したときにだけ実行されます。すでに文字起こし中のトラックが二重にキューへ入ることはなく、トラックの行には開いている文字起こしの状態が表示されます。

文字起こしは Activity のワークフローです。Kikoto はトラックを自分でデコードし、16 kHz モノラル音声を最長 5 分ずつの部分に分けて送ります。各部分は末尾 1 分間のうち最も静かな位置で区切るため、区切りは単語の間に来ます。完了した部分は保持され、ワークフローは部分の合間に待機中の他の処理へキューを譲るので、長いトラックがスキャンや Fetch を妨げることはありません。各部分の送信前に、サービス設定、コンテンツポリシー、権限、音声ファイルが変わっていないか再確認します。再起動で中断されたリクエストや、サービスが拒否した部分があると文字起こしは停止し、Activity の **再試行** は最後に完了した部分の続きから、中断された部分を再送して再開します。実行をキャンセルすると停止します。

完了した文字起こしはトラック一覧の下の一覧で確認を待ちます。**プレビュー** は他の歌詞と同じタイミング確認で最初の数行を表示します。**歌詞に追加** は、トラックの作品フォルダー内にある、その言語の歌詞フォルダーに、トラック自身のパスに沿った WebVTT ファイルとして保存し（例: `lyrics_kikoto/ja/mp3/Track 01.vtt`）、トラックに割り当てます。同じ名前の別のファイルまたはフォルダーがすでにある場合はそれを残し、文字起こしは番号付きの名前で隣に保存します。歌詞フォルダー、またはその中のフォルダーがあるべき場所に Kikoto が作成していないファイルまたはフォルダーがあると、その名前を変えるか移動するまで **歌詞に追加** は実行できず、文字起こしは保持されます。不要な文字起こしは **破棄** で削除します。歌詞への追加が完了しなかった場合は結果が保持され、**歌詞に追加** で再試行できます。

## 翻訳

**歌詞を管理 → 翻訳** は、設定済みの [LLM プロバイダー](settings.md#llm-プロバイダー)でローカルトラックの歌詞を翻訳します。このタブは、作品のローカルトラックを歌詞の言語に対して並べた表です。緑のセルはその言語の歌詞があり、赤のセルはありません。**フォールバック** 列は、フォールバック歌詞が翻訳先にならないため、トラックにフォールバック歌詞がない場合はダッシュを表示します。右上の **言語** で表示する列を選びます。赤のセルをクリックするとそのトラックのその言語を作成対象にし、言語の見出しをクリックするとその言語の歌詞がないすべてのトラックを選択します。選んだ各トラックは、作品の原語の歌詞、次にフォールバック歌詞、次に最初のその他の言語の歌詞から翻訳され、そのセルに **翻訳元** の印が付きます。同じ行の別の緑のセルをクリックすると、代わりにそのファイルから翻訳します。翻訳が実行中、またはレビュー待ちのセルには状態が表示され、再び選ぶことはできません。下部のバーでプロバイダーとモデルを選び、**翻訳** は選んだセルごとに 1 件の翻訳をキューに入れます。選んだモデルが翻訳できない言語の列には [LLM 翻訳](#llm-翻訳) と同じく印が付き、そのセルは選べません。トラックには作品フォルダー内のローカルファイルが必要で、翻訳はその作品フォルダーに保存されます。トラックと名前が一致するリモートの歌詞ファイルはそのトラックのフォールバック歌詞として扱われ、雲のマークが付きます。翻訳には管理者の有効化とリモート取得権限が必要です。コンテンツ安全ポリシーは [LLM 翻訳](#llm-翻訳) と同じで、何かを送信する前に歌詞全文を確認します。**区分を確認** は何も送信せずに、表示中の列にあるすべての歌詞ファイルでその確認を行い、緑のセルごとに区分を表示し、区分ごとの件数を数え、選んだ翻訳元を受け取れないプロバイダーに印を付けます。確認は押したときにだけ実行されます。

翻訳は Activity のワークフローで、歌詞を上限のある部分に分けて送り、完了した部分を保持します。LRC、WebVTT、SRT、標準 ASS の Dialogue とテキストは時間軸とキューの順序を保ち、各行のテキストだけを翻訳します。入力と出力は各 128 KiB、原本は 4,000 行、テキストの各行は 4,096 バイトまでです。プロバイダーが拒否した部分や、一時的に利用できない作品フォルダーは Activity から再試行できます。再起動で中断されたリクエストは結果不明となり、**再送信** は再課金の可能性を承認すると再度送信します。歌詞、プロバイダー設定、コンテンツポリシー、権限のいずれかが変わると翻訳は停止し、最初からやり直す必要があります。

完了した翻訳は表の下の一覧で 24 時間確認を待ち、開始したユーザーに結び付けられます。**プレビュー** は他の歌詞と同じタイミング確認で最初の数行を表示します。**歌詞に追加** は歌詞ファイル、ポリシー、プロバイダーを再確認してから、トラックの作品フォルダー内にある対象言語の歌詞フォルダーに、トラック自身のパスと原本の拡張子で保存し（例: `lyrics_kikoto/zh-hans/mp3/Track 01.lrc`）、その言語でトラックに割り当てます。原本の歌詞ファイルは変更されません。同じ名前の別のファイルまたはフォルダーがすでにある場合はそれを残し、翻訳は番号付きの名前で隣に保存します。歌詞フォルダー、またはその中のフォルダーがあるべき場所に Kikoto が作成していないファイルまたはフォルダーがあると、その名前を変えるか移動するまで **歌詞に追加** は実行できず、翻訳は保持されます。不要な翻訳は **破棄** で削除します。歌詞への追加が完了しなかった場合は結果が保持され、プロバイダーに接続せずに **歌詞に追加** で再試行できます。

## 購入特典

早期購入特典（`【早期購入特典】`）などの購入特典は、独自のファイルを持つ DLsite の独立した商品ですが、DLsite はそれがどの作品に属するかを示しません。メタデータ同期はそれを親の作品にリンクでき（[購入特典](settings.md#購入特典)を参照）、ライブラリのエディターでは、エディターのメタデータ提供元セクションにある **購入特典** で、親のコードを入力または削除できます。リンクされた特典は別の作品のままで、独自のタイトル、カバー、ファイル、再生の進捗、ライブラリのカードを保持し、不足しているタグ、声優、シリーズを親から引き継ぎます。その詳細には、親の作品とともに **特典の対象** が表示されます。親がライブラリにない場合は、DLsite へのリンク付きの親のコードが表示されます。親の詳細には、同じファミリーの別の版にリンクされた特典を含め、ライブラリにある **購入特典** が一覧されます。親のコードがライブラリの作品になることはありません。リンクを削除すると、その作品の自動検出も停止し、次の更新で継承された値が取り除かれます。

## 現在の動作

- 作品コードで読み込み、翻訳された DLsite ファミリーのルートを解決します。
- カバー、タイトル、コード、サークル、タグ、評価、声優のメタデータ、DLsite へのリンクを表示します。
- 論理的な作品ファミリーの既知の言語版を表示します。
- メタデータ言語とディレクトリ版のセレクターは、作品コードの横にある 2 つの別々のコンパクトなチップのままです。各チップは現在の選択を示し、それぞれ独自のリストを開きます。原版のディレクトリ版は `原版 · <language>` と表示されます。バリアントが 1 つしかない場合、メタデータのチップは読み取り専用のラベルになります。ローカルの作品では、メタデータは既定で優先メタデータ言語になります。リモートのみの作品では、ソースが記述している言語のうち、お客様の言語の中で最初のものが既定になり、次にソースのフォールバック言語が使われます。一時的に切り替えると、表示されるタイトルとタグ名が変わりますが、保存はされません。原版のバリアントは、設定された既定が選択されたままの間は、常に最初に一覧されます。
- ディレクトリ版は、メタデータの利用可能状態ではなく、ファイルの利用可能状態として扱います。保存されたローカルのコンテキストでは、折りたたまれたセレクターにはローカルフォルダーまたはローカルメディアのある版だけが表示され、展開するとすべての既知の版が表示されます。リモートの兄弟版は、そのソースが自身のデータベースで報告している場合にのみ選択できます。ローカルで利用可能な兄弟版は、選択したリモートソースにそれが含まれていなくても、そのローカルディレクトリを通じて選択できます。リモートのコンテキストでは、代わりに既定でソースが報告する利用可能状態が使われます。
- メタデータのみ、リモートのみ、利用不可の版も、ローカル再生を暗示することなく表示します。
- カードから渡された、またはコードから解決されたプレビューを最初に描画し、その後、基本の詳細とメディアツリーを別々の段階として読み込みます。
- カードや履歴のプレビューで既知の作品 ID を保持するため、お気に入りなどのコレクションのルートが、ライブラリの読み込みと冗長なコード解決を競合させることがありません。
- 保存済みとリモートのみのアイデンティティコントローラーに対して、1 つのレスポンシブなページコンポーザーを使用します。どちらも、戻る、ヒーロー、モバイルの情報／ディレクトリ、デスクトップのディレクトリ、モーダルの配置を共有しますが、リモートのみのプレビューに保存された状態を与えることはありません。
- モバイルの戻るコントロールは、サーバーとユーザーごとに記録された最後のライブラリ一覧の位置への「上へ」として扱います。幅の広いレイアウトでは、ソースを考慮した履歴の戻りを維持します。
- ローカルのメディアファイルは、メディアの段階で具体的なツリーが必要になったときにのみ、遅延してインデックスされます。完了した空のスキャンは、ライブラリのスキャンでその状態が無効になるまで記憶されます。
- 同じメディアを持つ作品の同時インデックスをまとめ、最初のインデックス時のファイルあたりのデータベース文を減らします。遅い収集と書き込みの段階は、診断のために別々にログに記録されます。
- ソースの利用可能状態は、バックエンドの集約チェックで読み込みます。
- 利用可能状態が分かった後で、リモートソースのツリーを遅延して開きます。明示的な保存済みのリモートソースのルートは、集約された確認の前に、識別されたソースを読み込むことができ、読み込みに成功すると、現在の詳細で利用可能としてマークします。
- 可変の高さのディレクトリ行で、スペースのない長い名前も含め、フォルダーとファイルの完全な名前を折り返し、ページが横にあふれることはありません。
- ディレクトリのパンくずを 1 行に保ちます。モバイルでは中間の祖先がメニューにまとめられ、デスクトップでは表示される各セグメントを制限して、現在のフォルダーがスクロールして見える状態を保ちます。完全な名前は、行、祖先のコマンド、タイトル、アクセシブルなラベルから引き続き確認できます。
- ヒーローのアクションバーには、ソースメニューが 1 つあります。そのアイコンはローカル、追跡済み、リモートの各コンテキストで変わり、ヘッダーには選択したソースが示され、外側の操作、Escape、ソースの変更で閉じます。
- 追跡済みの存在を 1 つの追跡済みタブに集約します。作品が複数のファイルソースで追跡されている場合、タブにはドロップダウンが表示され、タブの行にソース名を追加することなく、アクティブな追跡済みディレクトリを切り替えられます。
- ディレクトリの説明に、選択した追跡済みソース名を使用し、その選択を詳細の URL に保持します。
- カバーから色を付けた背景を持つヒーローで開きます。カバーの横には、DLsite へのリンクと言語チップ付きの作品コード、タイトル、サークル、シリーズ、CV のクレジット行、1 行のタグ、コンパクトな統計ストリップ（評価、年齢区分、販売数、発売日、再生可能な時間。スマートフォンでは 1 行）、メタデータの通知、下端に揃えられたヒーローのアクションが表示されます。タグの行にはプロバイダーのタグが最初に並び、続いて独自のアクセントスタイルでユーザーの個人タグが並び、最後に追加または編集のアイコンが付きます。長いプロバイダーのタグのリストは `+N` コントロールの背後に折りたたまれます。プロバイダーのタグまたは個人タグを選択すると、詳細を開いた元のライブラリ検索に `tag:` または `mytag:` の句が追加されます。別のページから詳細を開いた後で個人タグを選択すると、新しいローカルのライブラリ検索が始まります。ディレクトリは、その下のメインの列を占めます。ソース情報とメタデータの更新時刻は 1 つのパネルを共有し、幅の広いページではディレクトリの横に、狭いページではその後に続けて表示されます。ソース情報には、ファイル／音声の数、サイズと再生時間の網羅状況が報告され、ソースの再生時間を黙って置き換えるのではなく、メタデータの再生時間へのフォールバックにラベルが付きます。コンパクトな画面では、ヒーローが同じクレジット行、タグの行、統計ストリップ、アクションを情報とディレクトリのタブの上に保ち、情報にはソースパネルが表示され、マーク、リスト、DLsite、メタデータ、ソースはアイコンに折りたたまれます。
- ディレクトリは 1 つのパネルとして表示されます。ファイルのサマリーとソース確認を含むヘッダー、ステータスのドット付きの下線式ソースタブ、フォルダーエクスプローラーです。ディレクトリが十分に広く、作品にフォルダーがある場合は、選択したフォルダーの内容の横に固定のフォルダー列が表示されます。そうでない場合は、フォルダーボタンが、スマートフォンではボトムシートとして、それ以外ではポップオーバーとして、同じナビゲーターを開きます。列のヘッダーにある **フォルダーパネルを隠す** を選ぶと、内容が全幅で表示され、フォルダーボタンの横に **フォルダーパネルを表示** が残ります。この選択はそのデバイスに記憶されます。ナビゲーターは、自然順に並べたフォルダーを再生可能なファイルまたは画像の数とともに一覧し、小さなツリーは完全に、大きなツリーは選択中、おすすめ、再生中のフォルダーに向けて開き、1 つのサブフォルダーだけを持つフォルダーを 1 つの行にまとめ、おすすめのフォルダーと再生中のフォルダーに印を付けます。
- フォルダーのルーティングルールが推奨するフォルダーで開きます。内容のツールバーには、上へのコントロールとパンくず、フォルダーのトラック数と再生時間、おすすめバッジ（またはおすすめのフォルダーに戻るコマンド）、折りたたまれた歌詞の数、現在のフォルダーの再生可能なファイルを対象とするすべて再生コマンドが表示されます。
- フォルダーの内容は、サブフォルダーのタイル、アルバム形式のトラックリスト、画像ギャラリー、ドキュメント、その他のファイルにグループ化され、複数のグループがある場合はグループにラベルが付きます。サブフォルダーのタイルは、含まれる内容を要約し、再生可能なファイルがある場合は直接再生するコマンドを提供します。トラックにはフォルダーの再生順に番号が付き、名前の上にサイズと作品の再開位置、末尾の列に正確な再生時間が表示されます。ホバーすると再生のキューが表示され、現在のトラックはアクセント色の行とライブアイコンで示されます。再開のマーカーは、再読み込みなしで再生の保存に追従します。ローカルとキャッシュされた画像には、遅延読み込みのサムネイルが表示され、リモートの画像はプレビューするときにだけ読み込まれます。
- 一致した同じフォルダーの歌詞サイドカーは、既定のディレクトリ行から折りたたまれ、一致しないテキストは表示されたままになります。音声行には、歌詞の選択、プレビュー、表示のアクションがあり、ディレクトリのコントロールで折りたたまれたすべての歌詞を表示できます。ファイル管理と Fetch の選択では、歌詞を折りたたみません。
- ローカルソースの **歌詞を管理** オプションは、歌詞の選択肢を持つすべてのローカル音声ファイルを一覧します。ライブラリの書き込み権限を持つユーザーは、音声と名前が一致しない翻訳歌詞を含め、作品の任意のローカル歌詞ファイルを割り当てたり、歌詞フォルダーをトラック番号（または両方のフォルダーが同じ数のファイルを持つ場合は位置）でトラックに合わせたりできます。各行は最初の数行をプレビューし、最後のタイム付きの行がトラックの終了後に始まる場合は警告します。割り当てはすべてのリスナーで共有され、自動の選択になりますが、リスナー自身の選択が引き続き優先されます。
- トラックには、言語ごとに 1 つの歌詞ファイルを指定できます。**歌詞の言語** のストリップで **フォールバック**、日本語、簡体字中国語、繁体字中国語、英語、韓国語を切り替えられ、それぞれの言語で歌詞のあるトラックの数が表示されます。**フォールバック** の歌詞は、リスナーのどの言語にも歌詞がない場合に使われ、指定のないトラックがファイル名の照合にフォールバックするのも、ここだけです。再生では、リスナーの優先メタデータ言語のうち歌詞がある最初の言語、次にフォールバック歌詞、最後にその他の言語が使われます。ファイルの言語は自分で宣言します。Kikoto がファイルから推測することはありません。
- **歌詞を管理** には、ローカルファイルを管理するユーザー向けの **歌詞ファイル** タブがあります。Kikoto は、作品フォルダー内の 1 つの `lyrics_kikoto` フォルダーで歌詞を管理し、言語ごとに言語名のフォルダーに置きます: `ja`、`en`、`zh-hans`、`zh-hant`、`ko`、およびフォールバック歌詞用の `fallback` です（例: `lyrics_kikoto/ja`）。Kikoto は自分で作成した `lyrics_kikoto` フォルダーに自分のものである印を付けます。作品に付属する歌詞フォルダー（`lyrics` など）は作品自身のファイルです。その歌詞は **このフォルダーのその他の歌詞** に表示され、Kikoto がそこに歌詞を追加したり、管理中の歌詞として削除したりすることはありません。Kikoto が作成していない `lyrics_kikoto` フォルダーや同名のファイルがあると、その名前を変えるか移動するまで歌詞を追加できません。このタブでは **ファイルを編集** と同じく 3 列で編集します。左列は歌詞の取得元、中央列は選んだ取得元の歌詞ファイル、右列は編集後の管理中の歌詞です。作品にローカルフォルダーが複数ある場合は、右列で編集するフォルダーを選びます。
- 取得元は次のとおりです。**管理中の歌詞** ではチェックを外したファイルが削除されます。**このフォルダーのその他の歌詞** で選択したファイルは歌詞フォルダーにコピーされて元の場所にも残ります。**作品自身のファイル** を **lyrics_kikoto に移動** にすると移動します。この選択は管理者の[既定](settings.md#ライブラリ)から始まり、変更しない限りコピーです。作品の他のローカルフォルダー（ライブラリ内の別の版を含む）のファイルはコピーされ、設定済みのリモートソースが提供する版のファイルはダウンロードされます。選択したファイルは、その取得元の **この歌詞の言語** で選んだ言語の歌詞フォルダーに入ります。別の版の歌詞は最初その版の言語になります。Kikoto は作品自身のファイルの言語を推測しないため、プレビューの前に言語を選びます。管理中の歌詞の言語を変えるには、**このフォルダーのその他の歌詞** で **管理中の歌詞も表示して言語を変更する** をオンにし、そこで選択します。これらはコピー中でも新しい言語に移動します。ファイルは取得元でのパスを保ちますが、すでに入っている歌詞フォルダーは除かれます。
- 右列には結果がプレビューされます。同じ内容のファイルがすでにある場合はそのままです。同じ名前の別のファイルは競合となり、右列で解決します: 既存のファイルを残す、置き換える、両方残す、または追加するファイルの名前を変える、のいずれかで、先に削除する必要はありません。邪魔になるフォルダーやファイルは **ファイルを編集** と同じように扱われます。**変更を適用** はファイルを削除する前に確認を求めます。ライブラリの書き込み権限があれば、**追加した歌詞を一致するトラックに割り当てる** により、追加した各ファイルをファイル名、次にトラック順で一致したトラックにその言語で割り当てます。その言語の歌詞がすでにあるトラックは変わりません。移動したファイルを使う割り当ては、そのファイルの言語に移ります。コピーしたファイルは別のファイルで、作品自身のファイルは割り当てを保ちます。読み取ったリモートの版はライブラリに追加されません。
- ローカル作品の **ファイルを管理** には、作品フォルダー内の別の場所にある歌詞のための **歌詞として管理** があります。`.lrc`、`.vtt`、`.srt`、`.ass`、`.txt` ファイルを選択してこれを選ぶと、**このフォルダーのその他の歌詞** でそれらのファイルを選択した状態で **歌詞ファイル** が開きます。
- 作品で **歌詞を管理** が利用できる場合、**ファイルを管理** は Kikoto が管理する歌詞を既定で隠します。**Kikoto が管理する歌詞** の行がそれらの数を示し、**歌詞を管理** を **歌詞ファイル** タブで開きます。その行の **一覧に表示** スイッチをオンにすると、ほかのファイルと一緒に一覧され、ほかのファイルと同じように選択できます。隠れている間は、作品フォルダー全体を削除対象に選ぶと、それらも含まれます。それより小さい選択では、そのまま残ります。
- **歌詞を管理** には、ライブラリ書き込みとワークフローの権限を持つユーザー向けに、[音声認識サービス](settings.md#音声認識サービス)が設定されている場合に **文字起こし** タブがあります。[文字起こし](#文字起こし)を参照してください。
- **ファイルを管理** の **まとめて選択** は、場所や形式でファイルを選択します。ローカル作品では **同一ファイルを探す** もあります。作品のすべての版とフォルダーのローカルファイルを内容で比較するため、翻訳版で名前が変わっている音声も、原版のものと同じと認識されます。同一のコピーがあるファイルには、そのコピーの場所が示され、2 つの選択肢が表示されます。**別のフォルダーにもある** は、一覧のファイルのうち同じ内容のファイルが他の場所にもあるものを選択し、**このフォルダー内で重複** は、一覧のフォルダー内で、最初の 1 つを除くすべてのコピーを選択します。同じトラックを再エンコードしたものなど、似ているだけのファイルは同一ではなく、印は付きません。削除を確認するまで、何も削除されません。
- ローカル作品の **ファイルを管理** には、ローカルファイルを管理できるユーザー向けの **ファイルを編集** があります。表示中のフォルダーを 3 列で編集します。**ソース** には **このフォルダー**、作品の各エディションのほかのローカルフォルダー、設定済みのリモートソースが提供する各エディションが並びます。**選択** には選んだ場所のファイルが表示され、このフォルダーのファイルのチェックを外すと削除され、ほかの場所のファイルにチェックを入れると追加されます。**最終フォルダー** には編集後のフォルダーが表示され、各ファイルが保持、削除、コピー、ダウンロード、置き換え、既にありますのいずれかで示されます。ほかのローカルフォルダーのファイルはコピーされ、元のフォルダーは変更されません。リモートエディションのファイルはダウンロードされます。これには取得（Fetch）の権限も必要で、そのエディションはライブラリに追加されません。同じ名前の別のファイルに重なる場合は競合になり、フォルダー内のファイルを保持する、置き換える、両方を残す、追加するファイルの名前を変える、のいずれかで解決します。同じ名前のフォルダーやリンクは置き換えられないため、それ以外の選択肢だけが表示されます。追加するパスのフォルダーがあるべき場所にファイルがある場合は、そのファイルを保持するか、追加するファイルを別のパスに名前変更するかの 2 つだけです。ファイルを削除する場合、**変更を適用** は 2 回の削除確認を求めたうえで 1 つのアクティビティワークフローとして実行され、何かを削除または追加する前に、追加するファイルをすべて集めます。完了するとディレクトリが再読み込みされます。
- スキャンで作品のコードが複数のローカルフォルダーに見つかった場合、そのすべてが保持されます。ディレクトリにはコピーごとに 1 つのフォルダーが表示され、**ファイルを管理** は **フォルダー** の選択で 1 つのフォルダーずつ一覧し、作品を忘れることができるのは、フォルダーが 1 つだけ残ったときに限られます。ライブラリの書き込み権限を持つユーザーには、作品が複数のフォルダーにある場合、またはライブラリにその別の版がある場合、ディレクトリの上に通知が表示され、**歌詞を管理** と **ファイルを管理** から、歌詞を 1 つのフォルダーにまとめ、同一のものを削除できます。
- 自然順に並べたフォルダーを、自然順に並べたファイルの前に一覧します。フォルダーの再生もその同じ表示順に従います。
- 画像やテキストなど、再生できない利用可能なファイルは、ディレクトリに残し、音声と音声を含む動画はまとめて、再生可能なソースの指標にカウントします。
- プレビューは、ヘッダーのコントロール、矢印キー、スマートフォンでのスワイプ、または画像のフィルムストリップで、フォルダー内の同じ種類のファイルを順に移動できるファイルビューアーで開きます。画像は暗いステージに置かれ、ウィンドウに合わせるか、クリックした点を中心に実寸で表示し、ドラッグでパンでき、寸法が報告されます。動画も同じステージを使用します。テキストは閲覧ビューで開き、LRC、WebVTT、SRT のファイルは、プレーヤーの歌詞と同じ方法で解析された、タイムスタンプ付きの行を表示し、LRC のヘッダータグと元のテキストの切り替えがあります。ビューアーには、テキストの「コピー」、ローカルおよびキャッシュされたファイルの「ダウンロード」、ローカル画像の「カバーを設定」があり、「カバーを設定」は確認のために 2 回目のクリックが必要で、数秒後または別の画像に移動するとリセットされます。スマートフォンでは画面全体に表示され、デスクトップでは浮動プレーヤーの上に開きます。
- ローカル、キャッシュ、リモートのテキストプレビューを、バイトオーダーマーク、宣言された文字セット、レガシーエンコーディングの自動検出を使い、元のファイルを書き換えることなく、必要に応じて UTF-8 に変換します。
- デスクトップのコンパクトプレーヤーが有効な間は、最後のキュー操作に届くよう、下部のスクロール領域を確保します。

## 操作

- 固定の再開操作を 1 つ表示します。未完了で正の値の作品カーソルがない場合は無効になります。ファイルを直接実行した場合は、先頭から開始します。
- クイック聴取ステータスを更新します。
- お気に入りリストのメンバーを管理します。リストボタンには作品が入っているリストの名前が表示されます。複数のリストに入っている場合は、リスト順で先頭のリスト名と残りの件数が表示され、ツールチップにすべての名前が表示されます。**リストを追加** はリストメニューの中にリストを作成して選択し、**保存** は既存の選択に加えてメンバーを適用します。
- 個人の作品タグを、プロバイダーのメタデータタグとは別に編集します。
- メタデータを同期します。
- 互換性のあるリモートソースから、同期／キャッシュ／取得を行います。
- 取得（Fetch）は、受け付けられた時点で選択したソースを利用可能として記録し、同じ正規の作品に対して、キューにある、または実行中の既存の Fetch を再利用します。
- 現在の訪問者が匿名の場合は、Fetch の準備リクエストの前にログインを開きます。
- ローカルフォルダーのある作品では、リモートソースの **取得（Fetch）** は、ローカルファイルの管理と取得ができるユーザーに対して、そのソースのエディションを選んだ状態で **ファイルを編集** を開きます。それ以外の場合は取得ダイアログを開きます。
- 選択したソースのヒーローのソースメニューから、ソース固有の追跡、フォーク、取得、元のページを開く、キャッシュ、更新、ファイルメンテナンスの各コマンドを開きます。
- 選択したリモートソースを追跡し、閲覧可能なツリーを保存して、2 回目のフォークを必要とせずに、集約された追跡済みコンテキスト内の対応するソースを開きます。
- 可能な場合は、手動の上書きを編集します。
- メタデータエディターから、作品のメタデータを別の DLsite コードにリンクします。たとえば、特典版が販売終了となり、通常版のコードが異なる場合などです。その後のメタデータの更新では、リンクされたコードを読み取り、そのメタデータ、タグ、カバーをこの作品に保存します。リンクされたコードが別の作品になることはありません。作品自身のコードに記録がない場合は、メタデータが利用できないという通知から、エディターが直接開きます。

## 詳細の読み込みモデル

作品詳細は、まず既知のローカルデータベースの状態を優先し、より遅いリモート由来の状態は別に読み込む必要があります。

1. 任意の作品カードの画面からのルートプレビュー、または直接 URL の場合は軽量なコード解決。
2. 基本的な作品のメタデータ、ユーザーの状態、版、クレジット。
3. ローカルメディアとディレクトリツリー。
4. ソースの利用可能状態のサマリー。
5. ユーザーが開いた場合は、選択したリモートソースのツリー。

これにより、リモートソースの失敗がローカルの詳細シェルを妨げることがなくなります。
ディレクトリの段階では、安定したディレクトリ形状のスケルトンを使用します。メディアのエラーはそのスケルトンだけを置き換え、読み込まれたメタデータとアクションはそのまま残ります。
Fetch のパス選択とファイル管理のツリーは、対応するオプションコマンドが選択された後にのみ導出されます。
