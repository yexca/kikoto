# ワークフロー
[English](../en/workflows.md) · [简体中文](../zh-Hans/workflows.md) · [繁體中文](../zh-Hant/workflows.md) · [日本語](../ja/workflows.md) · [한국어](../ko/workflows.md)

ワークフローは、バックエンドの操作を確認できるようにします。

## ユーザー画面

- **ワークフロー** は、管理者が手動で開始する維持作業と、すべてのワークフローの実行をまとめます。
  上部の **実行中** には、キュー済みと実行中の、すべてのワークフローの実行が、ある間だけ表示され、
  その下に 3 つのタブ、既定の **操作**、**要対応**、**履歴** が並びます。
- **操作** には、カードと **次回** があります。**ライブラリ** の下に 3 枚のカードがあります。
  **スキャン**（ローカルライブラリをスキャン）、**メタデータ**（作品メタデータを同期）、
  **インデックス**（ローカル作品のファイルを更新）です。[記録](record-library.md)がオンの間は、
  **記録** に **記録のスキャン**（記録フォルダーをスキャン）と **メディア情報**（記録の動画と
  音声ファイルの長さとカバーアートを読み取る）が加わります。
  1 つの対象に対する作業は、その対象のある場所から開始します。取得は作品から、カタログ同期は
  そのサークル、シリーズ、声優から、リモートソースのライブラリ作品の確認は
  [ライブラリ](settings.md#ライブラリ)設定のそのソースからです。カスタムワークフローのエディターは
  ありません。
- カードには、操作の名前、状態、自動で開始されるタイミング、**実行** が表示されます。状態は
  **未実行**、**開始中**、**待機中**、**実行中**（進捗付き）、または最新の実行がどう終わったかと
  その時刻（**成功**、**失敗** など）で表示されます。**確認が必要** は、判断を待つ項目がある実行を
  示します。状態を選ぶと、その実行が開きます。その下の行には **起動時**、**スキャンで作品が追加された後**、**フォルダーを監視中**、
  **6 時間ごと** のような自動開始の条件と次回の予定実行が表示され、すべてのトリガーがオフのときは
  **自動実行は一時停止中** と表示されます。スマートフォンではカードが縦に並びます。
- **実行** は操作を開始し、カードにはその実行がすぐに表示されます。メタデータとインデックスは増分で
  実行されます。メタデータは DLsite からすべての作品の不足または古いメタデータを更新し、インデックスは
  ファイルが一度もインデックスされていないローカル作品だけをインデックスします。実行の横の
  **完全** をオンにすると、代わりにすべての作品のメタデータを更新、またはすべてのローカル作品を
  再インデックスします。これはその実行にだけ適用され、実行が要求されるとオフに戻ります。スキャンは
  常にすべてのフォルダーを確認するため、スキャンに **完全** はありません。スキャンとインデックスは
  ライブラリ全体を対象とするため、実行が終わるまで再び開始できません。メタデータは範囲ごとに実行され、
  実行中でも別の実行を開始できます。そのカードは実行中の実行を追い、ほかの実行の数を示します。
  新しい実行がほかの実行のあとで待つときはそのことを伝えます。トリガー、または別の
  ブラウザーで開始された実行も、同じようにそのカードに表示されます。
- 記録のスキャンは、[記録フォルダー](record-library.md#スキャンと-artwork)の新しいファイルと削除されたファイルを見つけます。メディア情報は、
  タイムアウトのあとで前回の実行が見送ったファイルを含め、待機中のすべてのファイルを読み取り、
  記録のページでフォルダーを開くと、そのフォルダーのファイルは単独で読み取られます。どちらにも
  完全はなく、キュー済みまたは実行中の実行は一度に 1 つだけで、別の実行を開始するとその実行が
  返されます。記録のスキャンは起動時または定期的に、メディア情報は定期的に、または記録のスキャンで新しいファイルが見つかった後に、トリガーボタンから実行することもできます。
- **メタデータのオプション** は、メタデータカードの名前の横のボタンで、
  [リモートメタデータの補完](settings.md#リモートメタデータの補完)（既定ではオフ。オンにすると、
  DLsite が作品を見つけられなかったときに、選択したソース最大 16 件へ設定した順に問い合わせます）と
  [購入特典の関連付け](settings.md#購入特典)（既定ではオン）を設定します。このカードの実行とメタデータのトリガーがそれらを使います。既定と異なる間は、カードに
  **リモート補完: Example Remote B → Example Remote A** のように表示されます。設定は
  このブラウザーとメタデータのトリガーに保存されます。オフにしたソースや
  メタデータを提供しなくなったソースは補完から外れます。
- カードの名前の行の末尾にあるカレンダーボタンは、その操作を
  自動で実行する設定を開き、いずれかがオンのあいだは点灯します。操作を開始できる方法ごとに
  スイッチが 1 つあり、変更はそのつど保存されます。スキャンと記録のスキャンは **起動時** に実行でき、
  スキャンはフォルダーも監視します（**ローカルライブラリフォルダーの変更時**）。メタデータ、インデックス、
  メディア情報は、代わりにそれぞれが続くスキャンが見つけた分だけを対象に、**スキャンで作品が追加された後**、
  **スキャンで新しいフォルダーが見つかった後**、**記録のスキャンで新しいファイルが見つかった後** に
  実行されます。どの操作も **定期的に**（間隔は 1、6、12 時間、1 日、7 日）実行できます。オンの間、
  メタデータまたはインデックスの定期実行とフォルダーの監視では、**増分** か **完全** を選べます。
  オフにすると一時停止し、間隔とモードは保持されます。新規インストールでは、ライブラリのセットアップか
  トリガーをオンにするまで、何も自動では実行されません。
- **実行中** と **次回** は、それぞれ 5 件を表示し、**すべて表示** で残りを表示します。
  **要対応** は判断を待つ実行を 1 ページ 20 件で一覧し、あるときはタブに件数が表示されます。
  **履歴** は終了した実行を新しい順に一覧し、失敗した実行または 1 つのワークフローに
  絞り込めます。検索フィールドではワークフロー名、作品コード、サークル、ソースで実行を探せます。
- **次回** は、オンのトリガーだけを、間隔のスケジュールを次回の実行順に、続いて起動時、スキャン後、フォルダーの
  トリガーの順に一覧し、それぞれの実行時期と完全で実行するかどうかを示します。一時停止中のトリガーは
  何も実行しないため **次回** には表示されず、カードのトリガー一覧や設定元のページに表示されます。
  ランキングの取得は、いずれかのランキングに取得の予定があるあいだだけ、その予定時刻とともに表示されます。
  オンとオフは「見つける」の各ランキングのスケジュールで決まります。
  操作のトリガーには、一時停止のスイッチと、そのカードのトリガーを開く編集ボタンが
  あります。ほかのワークフローのトリガー（ランキングの取得やソースのライブラリ作品の確認など）は、
  その設定場所へ移動します。
- 各実行には、ステータス、実行番号、トリガー、経過時間が表示されます。実行を選択すると、その詳細が
  開きます。開始と終了の時刻、所要時間、トリガー、ステップ、候補、実行の操作、そして折りたたまれた、
  実行イベントの **診断ログ** が表示されます。広い画面では、**要対応** または **履歴** で選んだ実行が
  その一覧の横に開き、一覧をスクロールしても表示されたままです。**実行を閉じる**、Esc キー、または
  その実行をもう一度選ぶと閉じ、別のタブやフィルターに切り替えても閉じます。**実行中**、カード、通知、
  ほかのページから開いた実行と、狭い画面でのすべての実行はページ全体に表示され、**実行履歴に戻る**
  またはヘッダーの戻るボタンで開いたときの一覧に戻ります。`/runs` と
  `/activity` のリンク、およびワークフロー内の実行への以前のリンクは、リンク先の実行を選択した
  ワークフローを開きます。
- ワークフローには、独自のページを持つ機能の実行も含め、すべての実行が一覧表示されます。翻訳は
  [翻訳](translation.md)ページで追跡し、文字起こしは作品の **歌詞を管理 → 文字起こし** で
  行います。そうした実行に関する通知は、そのページを開きます。

## ワークフローを使えるアカウント

ワークフローは `workflows:run` を持つアカウント、つまりコントリビューターと管理者に開きます
（[ユーザー](settings.md#ユーザー) を参照）。これらのアカウントは、他のアカウントが開始した実行も
含め、同じ定義、プリセット、トリガー、実行を見ることができ、その状態、イベント、ファイルの進捗を
追えます。

- ワークフローの開始、設定、スケジュールには、そのステップが使うすべての権限が必要です。追跡には
  `remote:track`、取得と取得ベースのすべての一括処理には `remote:fetch` と `metadata:sync` の
  両方、スキャン、メタデータのワークフロー、ランキングの取得には `metadata:sync`、記録の操作には
  `library:write`、ソースの確認には `sources:write` が必要です。`metadata:sync` のないコントリビューターもこれらの操作を表示できますが、
  取得経路を実行または自動化できません。
- トリガーの編集、オフ、削除には、それを作成するのと同じ権限が必要です。
- 配信状況の監視は見守るだけで、毎回作品ファミリーのメタデータを更新するため、そのソース設定、
  監視プール、確認には `metadata:sync` が必要です。監視中の作品の追跡と取得は手動で開始し、それぞれの
  権限を確認します。追跡には `remote:track`、取得には、リモートソースの一括取得と同じく
  `remote:fetch` と `metadata:sync` が必要です。
- 実行のキャンセル、再試行、項目の確認は、その実行を開始したアカウント（直接、または起動した
  トリガーの所有者として）が行えます。管理者はすべての実行に対して行えます。再試行には、同じ処理を
  開始するのと同じ権限が必要です。
- 取得のアーカイブの確認など、解決するとローカルファイルを削除、アーカイブ、または利用不可にする
  項目には `downloads:manage` が必要です。停滞した実行の復旧には `sources:write` が必要です。

## 現在の動作

- **取得** は、作品の[詳細ページ](work-detail.md)から開始します。ライブラリにない作品も、
  クイックアクションがそのコードで開きます。手動で実行され、自動化のトリガーはありません。
- ローカルスキャンは、メタデータプロバイダーを待たずに、フォルダーの検出とローカルソースの存在を
  記録します。メタデータ同期、ソースの利用可能状態、リモート同期、キャッシュ、取得、クリーンアップ、
  サークルの更新、リモートの一括操作は、それぞれ別のワークフローの実行として記録されます。
- 曖昧さのない 1 つのローカル作品について、スキャンは、フォルダーが消えた場合、または保存されている
  パスが検出されたフォルダーに属さなくなった場合に、古いローカルファイルの場所を見つからないものとして
  マークします。ファイルの削除や Fetch の所有権の変更は行いません。移動されたフォルダーは、開いたときに
  遅延してインデックスされます。作品のコードが複数のフォルダーで見つかった場合、そのすべてが保持され、
  詳細ページから整理できます。
- ノードの実行では、ステップごとの進捗が表示されます。
- 候補では、レビュー可能な結果が表示されます。
- 要対応には、ユーザーの判断が必要な未解決の候補がある、終了した実行が含まれます。通常の一部成功や
  スキップされた結果は履歴に残り、確認のために警告のステータス、概要、イベントが保持されます。
- ヘッダーの通知センターには、**更新**（Fetch など、完了または失敗したご自身のワークフロー結果）と、
  ワークフローの運用者には **要対応** な実行が表示され、実行中の最新のジョブがその両方の上に
  表示されます。Fetch の通知はローカルの作品詳細を開き、サインインしているユーザーごとに個別に
  却下できます。再試行で成功した Fetch や追跡は、失敗の通知を却下していても改めて通知されます。対応が必要な翻訳は翻訳ページの **停止** ビューを開き、文字起こしはその作品を開きます。
  **ワークフローを開く** でワークフローが開きます。
- **リモートソースのランキングを取得**、**DLsite ランキングを取得**、配信状況の監視、
  **購読を更新** は、[見つける](discover.md)のページで実行と設定を行い、タグ名を学習は単独で
  実行されます。これらにカードはありません。履歴はそれらの実行を一覧し、そのワークフローの
  メニューでいずれかに絞り込めます。操作をこのページから作成、編集、削除することはできません。
- 要対応には、未解決の候補、メタデータの問題、未確認の失敗が集まります。記録された問題を解決または
  無視すると、対応する専用のメタデータ実行の通知が消えます。その他の失敗は、未解決の候補と再試行できる
  メタデータの失敗が解決された後で、確認済みにできます。残るメタデータの問題が、販売終了した作品など
  取得できないと報告された作品だけの実行も、それらの問題をメタデータに残したまま確認済みにできます。
  この確認はユーザーごとです。履歴には、失敗、一部成功、キャンセルされた実行を含め、元の結果が保持されます。
- メタデータは、保留中の作品の復旧と DLsite プロキシのショートカットを担当します。
- ローカルスキャンは、リモートの利用可能状態の確認やメタデータの同期は行いません。メタデータ同期がスキャンに続くのは、
  自身の **スキャンで作品が追加された後** トリガーだけで、スキャンの終了後に開始されます。起動時トリガーはないため、
  起動時のスキャンと競合することはありません。
- ローカルスキャンには、起動時トリガーが 1 つと、固定のフォルダーウォッチャーが 1 つあります。
  新規インストールではどちらもオフで、ライブラリのセットアップでオンにするかどうかが案内されます。
  ウォッチャーは一時停止、再開、増分と完全の切り替えができますが、作成、複製、変換、名前変更、
  削除はできません。既定は増分です。ウォッチャーは、検出ディレクトリと、認識された作品ルート配下の
  すべてのサブディレクトリを登録し、その後、新しいディレクトリツリーを動的に登録します。最後に
  観測されたイベントから 5 秒待機し、Kikoto のステージング、バックアップ、ごみ箱、およびソース別に
  占有された Fetch のツリーを無視して、影響を受けた作品ルートを照合します。削除されたファイルと
  フォルダーは `missing` になり、データベースのレコードは保持されます。ウォッチャーのエラー、
  サイズが大きすぎるイベントバッチ、ルートの無効化、重複したルートでは、自動的に完全スキャンが使われます。
  Fetch は自身が公開した場所を直接登録し、手動、起動時、間隔のスキャンは常にデータツリー全体を
  検査します。スキャンのトリガーでは、ウォッチャーのスイッチで一時停止でき、オンの間は
  その横の **増分** と **完全** でスキャンの方法を選べます。アクティブな実行中の変更は、最大でも 1 回の後続スキャンになります。一時停止中の
  イベントは破棄され、オフライン中の変更は起動時のスキャンに任されます。
- **インデックス**（ローカル作品のファイルを更新）は、スキャンがすでに検出したローカルの作品フォルダー内の
  メディアファイルをインデックスするため、作品を開いたときに大きなフォルダーをその場で
  インデックスすることはありません。増分は、ファイルが一度もインデックスされていないフォルダーだけを
  対象とし、完全は利用可能なすべてのローカル作品を再インデックスします。同時にキューに入る、または
  実行できるのは 1 回だけで、別の実行を開始するとアクティブな実行が返されます。完全なスキャンの
  後に未インデックスのフォルダーが残ったとき、または完全を保存できる間隔で実行され、既定の
  トリガーなしで提供されます。
- **ソース上の作品を確認** は、1 つのリモートソースにライブラリの作品が存在するかを照会し、
  作品ごとの利用可能性の確認と同じように各作品へ結果を記録します。作品を追加することはありません。
  [ライブラリ](settings.md#ライブラリ)設定のそのソースから実行とスケジュール設定を行い、
  ワークフローにその実行が一覧されます。作品ごとにソースを 1 回照会します。対象が 1 回の実行で
  確認できる数より多い場合は、このソースで未確認の作品を優先し、次に確認が最も古い作品を確認する
  ため、実行を繰り返すとライブラリ全体を確認できます。実行はまず **状態を確認** と同じ方法で
  ソースの状態を確認し、ソースが利用不可の場合は作品を記録せずに停止します。照会の一部が失敗した
  場合、その実行は一部成功になります。同時に有効な実行はソースごとに 1 回だけです。
- 配信状況の監視、**購読を更新**、**DLsite ランキングを取得**、**リモートソースのランキングを取得** は、
  [見つける](discover.md)のページで設定します。そのページでは、監視がソースの設定を保持し、
  そのプールが **監視** の表示となり、購読の更新がそのスケジュールを、各ランキングがそれぞれの
  取得スケジュールを保持します。これらに絞り込んだ履歴には、設定先が示され、
  そのページへのリンクが表示されます。
- サークルのカタログを同期、シリーズのカタログを同期、声優のカタログを同期は、その対象から
  オンデマンドで実行されるプリセットのワークフローです。サークルまたは声優の **その他** メニューの
  **カタログを同期…**、サークルのそのシリーズが表示されている間は同じ場所の
  **シリーズのカタログを同期…**
  です。[サークル](circles.md)と[声優](voices.md)を参照してください。いずれも対象を入力済みの
  ダイアログで実行オプションを開き、**実行** でその同期をキューに追加してダイアログを閉じ、
  その実行へのリンクを表示します。実行オプションには 3 つのセクションがあります。
  **入力**（対象とカタログ更新。増分または完全）、**フィルター**（発売日の範囲と作品数の上限）、
  **アクション**（メタデータを同期、タグテンプレート、サークルの場合はリモートソースを確認）です。
  サークルとシリーズの
  対象には、カンマ区切りで最大 20 件の ID を指定でき、そのカタログはフィルターの前に結合されます。
  声優の対象は、選択した 1 人の声優で、そのカタログは、チェックしたリモートソースで表示名と
  確認済みの別名を使って更新されます。シリーズは保存済みの作品を読み取り、カタログの更新は
  ありません。メタデータを同期は、メタデータのないカタログ作品（まだライブラリにない作品を含む）を
  対象とし、フィルターとタグはそれらの作品に適用されます。すべてのフィルターは既定でオフです。
  発売日の範囲や作品数の上限がなければ、実行はメタデータのないすべてのカタログ作品を同期します。
  タグテンプレートも既定ではオフで、同期した作品にタグを付けるにはオンにします。メタデータを同期が
  オフの場合、サークルまたは声優のカタログ同期は、カタログを更新するだけです（およびソースの確認）。
  カタログ同期は追跡や Fetch を行いません。そのためには、リモートソースの作品、見つけるの **監視** の
  表示、または作品の詳細ページを使用してください。
- カタログ同期のプリセットにはトリガーがありません。新作をスケジュールに沿って追いかけるには、
  代わりにサークル、シリーズ、声優を購読してください。[見つける](discover.md)を
  参照してください。
- メタデータ同期はライブラリにある作品を更新します。**メタデータ** カードは、DLsite からすべての
  作品を、そのオプションで設定した補完と購入特典の関連付けを使って同期します。1 つの作品、サークル、
  声優の同期は、その作品、サークル、声優から開始します。メタデータ同期の実行は、1 つのサークル、
  1 人の声優、または最大 100 件の指定した作品、DLsite の代わりのリモートソース、
  [リモートメタデータの補完](settings.md#リモートメタデータの補完)、
  [購入特典の関連付け](settings.md#購入特典)も受け付けます。再試行は実行の選択を維持し、編集した
  トリガーは保存している選択を維持します。DLsite では、指定したコードのうちライブラリにないものは
  その作品と言語版が追加され、DLsite に掲載されていないコードは利用不可として数えられます。
  リモートソースはライブラリにある作品だけを更新します。指定した作品を保持したトリガーは、
  実行されるタイミングで自動的にオフになります。リモートの更新は手動の編集と DLsite の優先順位を
  維持します。
- ワークフローは組み込みで、ユーザーが独自に作成することはできません。以前のインストールから
  引き継がれたカスタムワークフローは、ライブラリのセットアップでレビューされ、プリセットと完全に
  一致するものは確認した管理者の購読にでき、その他はエクスポートできます。[はじめに](getting-started.md)を
  参照してください。それらの以前の実行は、履歴に残ります。
- **DLsite ランキングを取得** は、取得時期になったすべての DLsite のランキングを、各並び順を
  含めて 1 回の実行で取得し、**リモートソースのランキングを取得** は、1 回の実行につきリモートソース 1 つの人気リストを取得します。
  [ランキング](discover.md#ランキング)を参照してください。どちらも、作品をライブラリに追加せず、
  そのメタデータの同期、追跡、取得、タグ付けも行いません。作品にタグを付けた、追跡した、または取得した
  人気コレクションの実行は、履歴で引き続き読めますが、再試行できません。
- キューにある、または実行中の Fetch は、正規の作品ごとに一意です。繰り返された Fetch のリクエストは、
  同じ作品を 2 回ダウンロードするのではなく、その実行を再利用し、リクエストしたすべてのユーザーが、
  共有された実行の最終的な通知を受け取ります。
- Fetch の実行には、バイト単位のリモート転送の進捗、観測された転送速度、推定残り時間が
  報告されます。サイズ不明のファイルは不明と明示され、実際のサイズが分かるまで、パーセンテージと
  残り時間の表示は抑制されます。
- Fetch の実行の詳細には、そのファイルが一覧されます。ダウンロード中のファイルは独自の進捗バーとともに
  先頭に留まり、完全な一覧では、各ファイルが完了、待機中、または実行が失敗または一時停止した場所として
  示されます。
- 各 Fetch の実行には、`RJ00000001 を取得` のように作品名が付けられ、履歴の検索では、作品
  コードで Fetch を見つけられます。一括操作（見つけるの **監視** の
  表示から開始したものを含む）によってキューに入れられた Fetch は、その起点をトリガーの理由として記録します。
- 1つの作品、サークル、シリーズ、声優、またはリモートソースを対象とする実行は、`サークルのカタログを同期 · RG00000000`
  のようにその対象をタイトルに加え、履歴の検索でもその対象で見つけられます。
- スキャンは、見えない場所にある作品を見つからないものとしてマークすることはありません。マウント
  されていないデータフォルダーやオフラインのストレージプール、スキャン深度より深いフォルダー、
  読み取り権限のないフォルダー、そして NAS やオペレーティングシステムが追加するごみ箱とスナップショットです。
  マウントされていない標準ライブラリのスキャンは失敗し、何も変更しません。オフラインのプールや
  読み取れないフォルダーをスキップしたスキャンは、一部成功として終了し、その名前を示します。
- スキャン、ファイル一覧、フォルダーウォッチは、フォルダー `@eaDir`、`#recycle`、`#snapshot`、
  `__MACOSX`、`.Trash-*`、`$RECYCLE.BIN`、`System Volume Information`、`lost+found` と、ファイル
  `._*`、`.DS_Store`、`Thumbs.db` をスキップします。これらのフォルダーの中にある作品フォルダーが作品として
  見つかることはありません。ごみ箱、スナップショット、`.Trash-*`、`$RECYCLE.BIN`、
  `System Volume Information`、`lost+found` のフォルダーにすでに記録されている作品フォルダーは状態を保ちます。
  `@eaDir` と `__MACOSX` はメタデータだけを保持し、ユーザーのファイルを保持しません。その中に記録された
  フォルダーは作品のフォルダーではなく、そのファイルが作品に加わることはなく、それを見ることのできる次の
  スキャンが見つからないものとして記録します。
  スキャンが読み取る作品フォルダーの中にあるこれらのフォルダーとファイルは作品のファイルではなく、
  ライブラリに載っているものはスキャンが見つからないものとして記録します。
- FFprobe が破損したファイルなどのメディアファイルを読み取れない場合、Kikoto はそのファイルの
  現在のバージョンについてそれを記録し、バックグラウンドでのプローブを止めます。タイムアウトや
  中断されたプローブは何も記録せず、ファイルの変更を検出したスキャンは再びプローブします。
- マウントされていないディスク上の作品はライブラリに残ります。カードには **ローカル · オフライン** と表示され、作品のローカルファイルにはディスクがマウントされていないことが示されます。再びマウントされるまで、そのファイルは再生、ダウンロード、編集、削除できず、**ファイルを管理** はそのフォルダーをオフラインとして示し、そこからは何も取り込みません。ディスクが戻ると、スキャンしなくてもファイルは再び利用できます。

## 制限

- 再試行とチェックポイントからの復旧は、ジョブが復旧可能であると明示的に宣言しているワークフローの
  ファミリーにのみ適用されます。失敗した任意のノードを単独で再開することはできません。
- ワーカーは Kikoto のプロセス内で動作するため、キューにあるジョブは、そのプロセスが動作している間
  だけ進行します。分散実行や複数インスタンスでの実行はサポートされていません。
- 通常のサービス停止では、実行中の復旧可能なジョブは、再試行の予算を消費することなくキューに戻ります。
  クラッシュ、強制終了、リースの期限切れの後の復旧は、各ジョブの再試行の予算によって制限されます。
  手動での古い実行の復旧は、中断された復旧不可能な作業を、確認のために失敗としてマークします。
