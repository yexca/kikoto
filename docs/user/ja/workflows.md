# ワークフロー

[English](../en/workflows.md) · [简体中文](../zh-Hans/workflows.md) · [繁體中文](../zh-Hant/workflows.md) · [日本語](../ja/workflows.md) · [한국어](../ko/workflows.md)

ワークフローはバックグラウンド処理を確認可能にします。

## 主要内容

- Workflows で定義とトリガーを管理し、Activity で実行状態を確認します。
- スキャン、メタデータ Sync、リモート Sync、Cache、Fetch、クリーンアップは独立した実行です。
- **ローカル作品のファイルを更新** はローカルスキャンの次（2 番目）に表示されます。スキャンで検出済みのローカル作品フォルダー内のメディアファイルをインデックスし、作品を開いたときに大きなフォルダーをその場でインデックスせずに済むようにします。**増分**（既定）はファイルが一度もインデックスされていないフォルダーのみ、**完全**は利用可能なすべてのローカル作品を再インデックスします。キューまたは実行中の実行は常に 1 件で、追加で開始すると実行中のものが返されます。モードを保存する Startup トリガーと間隔トリガーに対応し、既定のトリガーはありません。
- 消えたフォルダーは `missing`、重複コードは Review に残します。
- Fetch は canonical Work ごとに一件へ統合され、転送量・実測速度・残り時間の目安を Activity に表示します。
- Fetch の実行詳細にはファイル一覧があり、ダウンロード中のファイルは個別の進捗バー付きで先頭に表示されます。一覧では完了・待機中と、実行が失敗または一時停止したファイルを示します。
- 実行詳細には開始・終了時刻、所要時間、トリガー、ステップ、既定で折りたたまれた診断ログを表示します。
- 復旧を宣言したワークフローだけがチェックポイントと再試行をサポートします。
- サークルをフォロー、シリーズをフォロー、声優をフォローはプリセットワークフローです。実行オプションは **入力**（対象とカタログ更新：差分または完全）、**フィルター**（発売日範囲と作品数の上限）、**アクション**（メタデータを同期、タグテンプレート、サークルではリモートソース確認）の 3 つに分かれ、広い画面では 3 列に並びます。実行オプション下部の **Run** で実行します。トリガーポップオーバーは上の値を既定で使い、「実行オプションをカスタマイズ」を有効にすると個別設定できます。メタデータ同期には Startup トリガーがありません。メタデータ同期はメタデータのないカタログ作品（ライブラリにまだない作品を含む）を対象とし、フィルターとタグはこれらの作品に適用されます。フィルターは既定ですべてオフで、発売日範囲も作品数の上限もない場合はメタデータのないカタログ作品をすべて同期します。タグテンプレートも既定でオフで、同期した作品にタグを付けるにはオンにします。フィルターなしの自動実行を保存するときは、トリガーポップオーバーがフィルターをオンにするよう勧めます。メタデータ同期をオフにすると、サークルと声優のフォローはカタログ更新（とソース確認）だけを行います。Track と Fetch はフォローのアクションではなくなりました。自動実行は差分カタログ更新のみで、完全更新は手動に限られます。
- 声優は 1 人を選び、チェックしたリモートソースでカタログを更新します。シリーズは保存済みの作品を読み込み、カタログ更新はありません。アップグレードすると、以前に保存したフォローのトリガーは無効になり、再設定が必要と表示されます。トリガーを開いて実行オプションを確認・保存し、再度オンにしてください。メタデータ同期はライブラリにある作品を更新します。実行オプションで **作品**（すべての作品、1 つのサークル、1 人の声優）と **更新対象**（欠落・古いもの、またはすべてのメタデータ）を選び、間隔トリガーも同じ選択を保存します。`sources:write` を持つ管理者には **実行** の横に **設定** も表示され、インスタンス全体の[リモートメタデータの補完](settings.md#リモートメタデータの補完)を変更し、その設定だけを保存します。
- ユーザー作成のカスタムワークフロー、DAG エディター、スラッシュコマンド、定義の実行ダイアログは削除されました。アップグレード時に既存のユーザー定義とそのトリガーは削除されますが、実行履歴は Activity に残ります。

ページ上部のステータスバーには、実行中の処理と進捗、要対応の実行数、次の予定実行が表示されます。最初の 2 つの項目かステータスバー右端の Activity を選ぶとデスクトップのパネルまたはモバイルのシートが開き、次の予定を選ぶとそのワークフローを選択します。実行中の処理を上部に表示し、その下を **Needs attention** と **History** に分けます。未解決の候補、メタデータ問題、未確認の失敗が要対応となります。記録されたメタデータ問題の解消で通知を解除し、その他の失敗はユーザーごとに確認できます。History は元の結果を保持します。メタデータには問題対応と DLsite プロキシのショートカットを置き、同期は既存ワークフローへのショートカットから開きます。

Activity はすべてのワークフローの実行と件数を表示し、ワークフローを切り替えても変わりません。Recent runs や一覧の行から同じパネル内で詳細、イベント、候補を確認できます。独立した Full Activity ページは廃止し、旧リンクと通知は対象ワークフローの Activity を開きます。

- ワークフロー一覧はすべてのワークフローを分類ごとに固定順で並べます：基本（ローカルスキャン、ローカルファイル、メタデータ同期）、収集（人気作品の収集）、フォロー（プリセットのフォローワークフロー）、リモート（Availability Watch と Fetch の履歴）。各項目には最新の実行の状態と時刻が表示され、有効な Startup トリガー、スケジュール、フォルダー監視は小さなアイコンで示されます。広い画面では一覧が選択中のワークフローの横に並びます。一覧の下の「タブ名を隠す」でアイコンだけの列に折りたたむと、各アイコンに最新の実行状態を示す小さな点が残ります。「タブ名を表示」で元に戻せ、この選択はこの画面で記憶されます。モバイルでは最初に一覧が表示され、ワークフローをタップすると開き、ヘッダーの戻るボタンかブラウザの戻るで一覧に戻ります。
- 選択中のワークフローは直近 20 回の実行をまとめて表示します：前回の実行、完了した実行の成功率、標準的な（中央値の）所要時間、次に自動で実行されるタイミング（スケジュール、次回のサービス起動、フォルダー変更、または手動のみ）。その下の棒グラフは各実行の所要時間を古い順に示し、通常の成功は中立色のまま、失敗と一部成功が目立つようにしています。棒にカーソルを合わせると詳細が、選ぶとその実行が開きます。
- 実行パラメーターのあるワークフローは、概要の下に **実行オプション** を表示します。フォームの最下部のバーに **Run** があり、実行できないときはその理由（必須項目の未入力など）が横に表示されます。フォームが長いときは、このバーが画面下部（モバイルのナビゲーションとプレーヤーの上）に留まります。実行パラメーターのないワークフローは見出しの右側に **Run** を置きます。フォームの後に最新の実行のステージとログ、トリガー、最近の実行が続きます。
