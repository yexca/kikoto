# ワークフロー

[English](../en/workflows.md) · [简体中文](../zh-Hans/workflows.md) · [繁體中文](../zh-Hant/workflows.md) · [日本語](../ja/workflows.md) · [한국어](../ko/workflows.md)

ワークフローはバックグラウンド処理を確認可能にします。

## 主要内容

- Workflows で定義とトリガーを管理し、Activity で実行状態を確認します。
- スキャン、メタデータ Sync、リモート Sync、Cache、Fetch、クリーンアップは独立した実行です。
- 消えたフォルダーは `missing`、重複コードは Review に残します。
- Fetch は canonical Work ごとに一件へ統合され、転送量・実測速度・残り時間の目安を Activity に表示します。
- 実行詳細には開始・終了時刻、所要時間、トリガー、ステップ、既定で折りたたまれた診断ログを表示します。
- 復旧を宣言したワークフローだけがチェックポイントと再試行をサポートします。
- サークルをフォロー、シリーズをフォロー、声優をフォローはプリセットワークフローです。実行オプションは **入力**（対象とカタログ更新：差分または完全）、**フィルター**（発売日範囲と作品数の上限）、**アクション**（メタデータを同期、タグテンプレート、サークルではリモートソース確認）の 3 つに分かれ、見出し右側の **Run** で実行します。トリガーポップオーバーは上の値を既定で使い、「実行オプションをカスタマイズ」を有効にすると個別設定できます。メタデータ同期には Startup トリガーがありません。メタデータ同期はメタデータのないカタログ作品（ライブラリにまだない作品を含む）を対象とし、フィルターとタグはこれらの作品に適用されます。フィルターは既定ですべてオフで、発売日範囲も作品数の上限もない場合はメタデータのないカタログ作品をすべて同期します。タグテンプレートも既定でオフで、同期した作品にタグを付けるにはオンにします。フィルターなしの自動実行を保存するときは、トリガーポップオーバーがフィルターをオンにするよう勧めます。メタデータ同期をオフにすると、サークルと声優のフォローはカタログ更新（とソース確認）だけを行います。Track と Fetch はフォローのアクションではなくなりました。自動実行は差分カタログ更新のみで、完全更新は手動に限られます。
- 声優は 1 人を選び、チェックしたリモートソースでカタログを更新します。シリーズは保存済みの作品を読み込み、カタログ更新はありません。アップグレードすると、以前に保存したフォローのトリガーは無効になり、再設定が必要と表示されます。トリガーを開いて実行オプションを確認・保存し、再度オンにしてください。メタデータ同期はライブラリにある作品を更新します。実行オプションで **作品**（すべての作品、1 つのサークル、1 人の声優）と **更新対象**（欠落・古いもの、またはすべてのメタデータ）を選び、間隔トリガーも同じ選択を保存します。
- ユーザー作成のカスタムワークフロー、DAG エディター、スラッシュコマンド、定義の実行ダイアログは削除されました。アップグレード時に既存のユーザー定義とそのトリガーは削除されますが、実行履歴は Activity に残ります。

Workflows 右上の Activity はデスクトップのパネルまたはモバイルのシートを開きます。実行中の処理を上部に表示し、その下を **Needs attention** と **History** に分けます。未解決の候補、メタデータ問題、未確認の失敗が要対応となります。記録されたメタデータ問題の解消で通知を解除し、その他の失敗はユーザーごとに確認できます。History は元の結果を保持します。メタデータには問題対応とメタデータ設定を置き、同期は既存ワークフローへのショートカットから開きます。

Activity は選択中のワークフローの実行と件数だけを表示します。Recent runs や一覧の行から同じパネル内で詳細、イベント、候補を確認できます。独立した Full Activity ページは廃止し、旧リンクと通知は対象ワークフローの Activity を開きます。
