# 個人データ

[English](../en/personal-data.md) · [简体中文](../zh-Hans/personal-data.md) · [繁體中文](../zh-Hant/personal-data.md) · [日本語](../ja/personal-data.md) · [한국어](../ko/personal-data.md)

サインインして、サイドバーの **インサイト** を開くと、聴取カレンダー、レポート、履歴を確認できます。
個人タグは **設定 → タグ** に、**データ** は **設定 → アカウント** の最後のセクションにあります。
クイックアクションからそれぞれを直接開くことができ、アバターの背後にあるアカウントメニューからはインサイトとタグを開けます。
これらには、お使いのアカウントのデータのみが表示されます。

## 個人タグ

作品、サークル、声優のタグを検索できます。使われていないタグも含まれます。名前の変更は
すべての割り当てに反映されます。統合は、割り当てを既存のタグに移し、重複を取り除いて、
古いタグを削除します。削除は、タグとその割り当てを削除しますが、作品やプロバイダーの
メタデータは削除しません。

新しいワークフローのタグの既定値には日付が含まれないため、繰り返しの実行でも同じタグが
再利用されます。既存の保存済みテンプレートは保持されます。古いスケジュールで日付付きの
タグの作成を止めたい場合は、ワークフローで `{date}` を削除してください。日付を明示した
テンプレートは引き続きサポートされます。

## インサイト

**インサイト** の上部にある切り替えで、ページが対象とする範囲を選びます。過去 30 日間、過去 12 か月間、
全期間、または 1 つの暦年です。最後の項目 **年** を開くと日付付きの聴取がある年が並び、
選んだ年が表示されます。

**聴取カレンダー** は、1 年を 1 日 1 マスで週ごとの列に並べ、聴取時間に応じて色の濃さを変えて表示し、
その年の聴取した日数、聴取時間、連続記録を示します。暦年を選んだときはその年、それ以外の範囲では
過去 1 年が対象です。日にポインターを合わせるかタップすると、その日の合計が表示されます。

暦年を選ぶと、その年の **ハイライト** から始まります。その年の聴取時間、作品数、聴取した日数、
最もよく聴いた作品・声優・サークル、最も聴いた日とその日に最もよく聴いた作品、聴取した日の最長の連続、
その年に初めて聴いた作品、1 日のうち最も聴いた時間帯です。

選択した範囲について、聴取レポートは次を表示します。

- 聴取時間、再生回数、作品数、聴取した日数。あわせて、聴取した日あたりの時間、再生あたりの
  時間、最もよく聴いた作品が占める時間の割合、範囲内で聴取のあった日の割合も表示します。
- 日、月、年ごとのグラフ（暦年は月単位、全期間では 3 年を超えると年単位に切り替わります）と、平均および
  最も聴いた期間。
- 最もよく聴いた 5 作品（10 作品まで展開可能）。それぞれに、その聴取時間と、範囲内の聴取に
  占める割合が付きます。
- リズム: 月曜から金曜までの 1 日あたりの平均聴取時間と週末の 1 日あたりの平均聴取時間、
  続いて曜日ごとの平均。12 か月間または全期間のレポートはこのためにカレンダーの日を
  読み取るため、全期間のレポートは過去 1 年について示します。**時間帯別** では、午前 0 時から順に
  1 時間ごとの聴取時間と、最も聴いた時間帯を加えて表示します。時間帯は聴取時に記録されるため、
  サーバーが時間帯を数える前の聴取は含まれません。
- **好みのプロフィール**: 聴いているものをライブラリと比べます。レーダーは、聴取時間に占める割合が
  ライブラリの作品に占める割合をどれだけ上回るかに基づいて、最大 8 個のタグを描きます。
  十分な数の作品にその値があるときは、目印が、公開年、販売数、作品の長さによって、聴いた作品を
  ライブラリの作品の中に位置づけます。トラックの中央がライブラリで、長く聴いた作品ほど重みが大きくなります。
  **あなたの評価** は、付けたすべての評価を、同じ作品の公開評価と比べます。目印の上の数行は目立つ点を
  伝え、開始済みとしてマークした作品のうち、何作品が聴き終えているか、または再聴取としてマークされているかを示します。
- **タグ・声優・サークル**: それぞれ上位 5 件（10 件まで展開可能）で、各項目から
  ライブラリ検索、声優のページ、サークルのページを開けます。**好み** は、聴取時間に占める
  割合がライブラリの作品に占める割合をどれだけ上回るかで並べ、上回るものだけを表示します。
  バーが聴取時間の割合、その上の目印がライブラリの割合です。**聴取時間** は、作品の
  聴取時間順に並べます。1 つの作品は、そのすべてのタグと声優にそのまま計上されます。

作品はライブラリに一覧される作品単位で数えます。作品のどの版を聴いても、その作品の聴取に
計上されます。

1 日は、使用するタイムゾーンの午前 0 時に始まります。初期設定の **自動** はデバイスごとに従い、
聴取は再生したデバイスの現在の日に、レポートは表示したデバイスの現在の日までに計上されます。
**設定 → アカウント → タイムゾーン** でタイムゾーンを選ぶと、すべてのデバイスで 1 つのタイムゾーンを
使います。ページの末尾には使用中のタイムゾーンが表示され、その設定へのリンクがあります。聴取は記録された時点の日に
計上されるため、タイムゾーンを変更すると以降の聴取に適用され、記録済みの日はそのまま残ります。

インポートされた合計には日付がないため、「すべて」にのみ含まれます。完全な履歴は、最後に
聴いた時刻順に並び、各作品の聴取時間、再生回数、最後に聴いた日付が付いて、ページの末尾に
折りたたまれており、開いたときに読み込まれます。
**履歴を消去** と **データ** への入口はその横にあります。
時間は実際の聴取を測定したもので、一時停止、バッファリング、シークの時間は含まれず、
速度を変更しても倍にはなりません。同時に使用する複数のプレーヤーはそれぞれ独立して数えられます。
クライアントの中断や切断により、一部の時間が報告されないことがあります。

履歴は、クリアされるか、そのアカウントまたは作品が削除されるまで、お使いのサーバーに
保持されます。90 日後のおすすめイベントのクリーンアップでは、削除されません。アップグレードでは、
残っている古い再生イベントと再開のタイムスタンプが、時間を捏造することなく保持されます。以前に
削除されたイベントは復元できません。履歴をクリアしても、マーク、プレイリスト、再開の進捗は
保持されます。アカウントのカウンターは、クリア前からの遅延した報告を拒否します。

## エクスポートとインポート

バージョン 1 の Kikoto 個人 JSON には、作品ごとの聴取マーク、個人の評価とメモ、再開情報、
累計の聴取時間、作品タグの割り当て、カスタムタグの定義、およびアイコン付きの順序付き
お気に入りプレイリストが含まれます。システムの
マーク済みのメンバーはマークから導出されます。サークルと声優のタグ定義は含まれますが、
それらのエンティティへの割り当てやその他の状態は、この形式の対象外です。

メディア、ソースの設定、エンドポイント、認証情報、プロバイダーのメタデータ、生のセッション、
日別の統計は除外されます。トラックのタイトルとトラック／ディスク番号が再開の対象を識別し、
ローカルパスとソース固有の ID はエクスポートされません。

ソース（JSON ファイル、Kikoeru アカウント、または Kikoeru データベース）を選択し、インポートの前に
**プレビュー** します。**既存のデータを保持** は、個人の状態がある作品をスキップし、
既存のプレイリストを維持します。**インポートした内容で上書き** は、ファイルの内容で、マーク、
メモ、作品タグ、一致する進捗、同名のプレイリストを置き換えます。聴取時間の合計は最大値で
マージされるため、繰り返しインポートしても二重に数えられたり、測定済みの聴取時間が減ったりすることは
ありません。

主コードで一致するのは、既存の作品と、曖昧さのない既知の別名のみです。見つからないコードは
一覧に表示され、インポートでメタデータを取得したり作品を作成したりすることはありません。
見つからない、または曖昧なトラックでは、既存の進捗がそのまま維持されます。インポートは
アトミックにコミットされます。上限: 10 MiB、20,000 作品、5,000 のタグ定義、1,000 のプレイリスト、
そして 50,000 のプレイリスト項目または作品タグの割り当て。

## Kikoeru

Kikoeru の JSON ファイルは、レビューの配列、`reviews` 配列、または API の `works` 配列を
受け付けます。1 つのアカウントのデータを使用し、必要なすべてのページを含めてください。コードには
`primaryCode` または `source_id` を使用します。数値の `work_id`/`id` は商品番号です。ID に商品タイプを
エンコードするフォーク（タイプ × 10¹² + 数字。RJ、BJ、VJ、CC がタイプ 0〜3）はデコードされます。
商品コードと無関係な ID は、先に変換する必要があります。個人の `userRating`/`user_rating` と
`review_text` に対応しており、評価 0 は未評価としてインポートされます。プロバイダーの評価は
インポートされません。

**Kikoeru アカウント** は、データを代わりに読み取ります。設定済みの Kikoeru 互換ソースを選ぶか、
サーバーの API アドレスを入力し、続けてサインイン方法を選びます。なし（サインインを無効にした
サーバー用）、トークン、または名前とパスワードのいずれかです。サーバーは `POST /api/auth/me` で
サインインし、`GET /api/review` をページ送りで読み取り、Kikoeru サーバーが提供している場合は、
お気に入りとマークのリストを含む、お客様が所有するプレイリストを読み取ります。プレイリストのない
サーバーからはレビューだけがインポートされます。結果は、ファイルと同じプレビューとインポートを
経ます。

**Kikoeru データベースファイル** は、オープンソース版 Kikoeru の SQLite データベース（最大
512 MiB）をアップロードし、指定したアカウントのレビューのみを読み取ります。アップロードには
最長 15 分かけられます。最近の書き込みを
含めるため、Kikoeru が停止中またはアイドル中にファイルをコピーしてください。そのデータベースには
プレイリストはありません。

トークン、パスワード、手動入力のアドレス、またはデータベースがブラウザーから送信される前に、
Kikoto はリスクを説明して確認を求めます。

- 認証情報は Kikoto サーバーを経由します。そのリクエストにのみ使用され、保存やログ記録は
  されませんが、サーバーの運用者がそれらを取得できる可能性があります。
- Kikoeru サーバーには、Kikoto サーバーのネットワークアドレスからのサインインとして見えます。
  サードパーティのサイトによって、アカウントがフラグ付けされたり制限されたりする場合があります。
- トークンはお客様のアカウントとして機能し、長期間有効なままになることがあります。
- Kikoeru のデータベースには、パスワードハッシュを含む、そのサーバー上のすべてのアカウントが
  含まれます。アップロードは読み取り中は一時ファイルとして保持され、その直後に削除されます。

これらのリクエストはリダイレクトを決して追跡しないため、認証情報はお客様が選んだアドレスにのみ
届きます。手動で入力するアドレスは、管理者であるか、管理者が **設定 → ライブラリ → Kikoeru
アカウントの取り込み → すべてのアカウントに LAN アドレスを許可** をオンにしていない限り、
公開アドレスである必要があります。このスイッチをオンにすると、サインインしている任意の
アカウントが、サーバーからローカルネットワーク上のデバイスへ接続させることができます。
使用可能な商品コードのない行はスキップされてカウントされ、アカウントまたはデータベースの読み取りは
同時に最大 2 件までしか実行されません。

| Kikoeru の進捗 | Kikoto のマーク |
| --- | --- |
| `marked` | 聴きたい |
| `listening` | 再生中 |
| `listened` | 完了 |
| `replay` | 再聴取 |
| `postponed` | 保留 |
| 空 / null | 未マーク |

この対応付けは、上流の [Kikoeru レビュー API](https://github.com/kikoeru-project/kikoeru-express/blob/unstable/routes/review.js) に従っています。
