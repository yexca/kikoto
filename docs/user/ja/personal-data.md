# 個人データ

[English](../en/personal-data.md) · [简体中文](../zh-Hans/personal-data.md) · [繁體中文](../zh-Hant/personal-data.md) · [日本語](../ja/personal-data.md) · [한국어](../ko/personal-data.md)

ログイン後、「設定」の「履歴」タブに再生履歴、「タグ」タブに個人タグ、Account の末尾に「データ」があります。アバターのアカウントメニューとクイック操作からはそれぞれ直接開けます。現在のアカウントのデータだけを扱います。

作品・サークル・声優の未使用タグも検索・整理できます。名前変更はすべての関連に反映され、統合は関連を移して重複を除きます。削除で作品や提供元メタデータは消えません。新規タスクの既定タグは日付を含みません。既存の定期タスクはテンプレートを保持するため、必要に応じて `{date}` を削除してください。

聴取レポートは 30 日・12 か月・すべての期間を切り替えられ、聴取時間、再生回数、日・月・年（UTC）ごとのグラフ、よく聴いた作品のカバーカードを表示します。日付のないインポート済みの合計は「すべて」にのみ含まれます。作品ごとの履歴はカードとしてその下に折りたたまれ、開いたときに読み込まれます。一時停止・バッファリング・シークを除き、倍速で時間を増やしません。複数プレイヤーは個別計測され、切断で未送信時間が残る場合があります。履歴は長期保存され、推薦イベントの 90 日後の削除とは独立しています。更新は残存イベントを保存しますが不明な時間は推計しません。履歴消去はマーク・リスト・再開位置を変更せず、アカウントの消去世代で遅延した旧リクエストを拒否します。

Kikoto JSON は作品のマーク、個人評価・メモ、再開位置、累積統計、作品タグ、カスタムタグ定義、順序付きお気に入りリストを含みます。サークル・声優タグは定義のみです。音声、接続先、認証情報、提供元メタデータ、生のセッション、日別統計は含まず、曲名とディスク・トラック番号で位置を照合します。ローカルパスは出力しません。

ファイルと形式を選び、プレビュー後に取り込みます。既定では既存作品の個人データと同名リストを保持します。上書きでは対応データと照合できた位置を置換し、累積統計は大きい値を採用するため二重計上しません。既存作品と既知の別名だけを照合し、不明コードを表示します。作品作成やメタデータ取得はせず、曖昧な曲は既存位置を保持します。処理は単一トランザクションです。

上限：10 MiB、20,000 作品、5,000 タグ、1,000 リスト、リスト項目・作品タグ関連はそれぞれ 50,000 件。Kikoeru はレビュー配列、`reviews`、API の `works` 配列に対応します。単一アカウントの必要な全ページを含めてください。`primaryCode`/`source_id` は作品コード、数値 `work_id`/`id` は商品番号で、型を ID に含める派生版（型 × 10¹² + 数字）は RJ・BJ・VJ・CC のコードに自動変換します。商品番号と無関係な DB ID は事前変換が必要です。

**Kikoeru アカウント** を選ぶと、設定済みの取り込み元または手入力した API アドレスに、サインインなし・トークン・ユーザー名とパスワードのいずれかで接続し、サーバーがレビュー、進捗、（対応していれば）プレイリストを読み取ります。**Kikoeru データベースファイル** はオープンソース版 Kikoeru の SQLite データベース（最大 512 MiB）をアップロードし、指定したユーザー名のレビューのみ読み取ります。トークン、パスワード、手入力のアドレス、データベースを送る前に、リスクを説明して確認を求めます。認証情報は Kikoto サーバーを経由しますが保存やログ記録はされず、Kikoeru からはサーバーのアドレスからのサインインに見え、データベースには全アカウントとパスワードハッシュが含まれ読み取り後すぐに削除されます。リダイレクトはたどりません。手入力のアドレスは公開アドレスのみで、管理者、または管理者が **設定 → ライブラリ → Kikoeru アカウントの取り込み** で LAN アドレスを許可した場合は例外です。

`marked` → 聴きたい、`listening` → 再生中、`listened` → 完了、`replay` → 再聴、`postponed` → 保留、空値 → 未設定。詳細は[英語の仕様](../en/personal-data.md)を参照してください。
