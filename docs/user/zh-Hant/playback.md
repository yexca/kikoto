# 回放
[English](../en/playback.md) · [簡體中文](../zh-Hans/playback.md) · [繁體中文](../zh-Hant/playback.md) · [日本語](../ja/playback.md) · [한국어](../ko/playback.md)

播放由全域瀏覽器音訊播放器處理。

## 當前行為

- 直接提供帶有面向瀏覽器的擴展的本地和快取音頻
具有 HTTP 範圍支援。這使得啟動和持續時間發現保持在
瀏覽器的本機媒體路徑，無需等待 FFprobe。
- 當直接音訊解碼失敗且檔案仍然存在時，播放器提供
僅當前曲目、當前隊列或全部的兼容性播放
未來的本地和快取播放。相容性播放和音訊
不支援的副檔名由 FFmpeg 轉換為包含時長和跳轉資訊的完整 MP3 快取。
首次播放會等待準備完成，之後重用快取；原始檔案不變。
確認遺失的檔案仍依正常來源順序回退。
- 在播放之前檢查本地和快取的影片。首先是不相容的視頻
返回其探測到的總持續時間和完整的 HLS VOD 播放清單。六秒
H.264/AAC 段獨立生成
需求，因此播放器可以請求稍後的片段，而無需每次都進行轉碼
前一段。 HLS.js 在需要時提供 MSE 播放；客戶與
原生 HLS 支援直接使用相同的播放清單。
- Generated video segments are rebuildable cache data under
`/Cache/transcodes/HLS`。他們使用單獨的 LRU 配額，預設為 5 GiB，
並因來源路徑、大小、修改時間或轉碼而失效
個人資料改變。一個段的上限為 16 MiB，並且產生嘗試
兩分鐘。中斷程序留下的陳舊部分文件將被回收。
- 追蹤的遠端和遠端預覽媒體透過配置獲取
來源策略並預設通過後端代理不變。這
代理程式保持面向瀏覽器的回應同源並轉發範圍
條件請求標頭，同時從不公開配置的來源 URL。
遠端回應不透過 FFmpeg 發送，包括客戶端發送時
`forceTranscode`；不支援的遠端媒體必須提取到本地或
即時轉換之前的快取位置可用。遠端播放是
串流且不寫入 `/Cache`；單獨的遠端來源快取
工作流程保持獨立。
- 準備完成的音訊支援總時長、HTTP Range 跳轉、續播和結束後自動播放下一首。
音訊快取位於 `/cache/transcodes/audio`，與影片共用容量配額；單次準備最多四分鐘，單檔最多 512 MiB。
HLS 視訊片段的來源版本是不可變的，且
可透過完整的 VOD 時間軸進行查找。視訊輸出限制為 720p，
在 `yuv420p` 編碼之前填入偶數尺寸，並使用
保守的雙線程輪廓。 FFmpeg 和 FFprobe 各有一個小的固定
並發限制和短的、有界的等待隊列；不能提出的要求
立即取得一個插槽會被拒絕，因此進程無法保持佔用狀態
無限期。
- Docker 映像包含 `FFmpeg` 和 `FFprobe`。其他部署必須
使兩個二進位檔案在後端進程 `PATH` 上可用。
- 點選可播放檔案佇列會自然地將可播放檔案排序在同一個佇列中
資料夾並從零開始選擇的檔案。
- 工作細節公開固定的簡歷而不是工作級別的播放。恢復已停用
沒有一個積極的未完成遊標。
- 跨導航繼續播放。
- 在匹配的作品正在播放時輸入作品詳細資訊會選擇
目前播放來源並開啟該曲目的資料夾。一個暫停的隊列，一個
不相關的播放工作，頁面開啟後開始播放保留
正常推薦目錄。手動來源或版本也發生變化
將目錄導航回傳給使用者控制。
- 桌面在首次使用後保持四個主要瀏覽工作區的安裝。
行動裝置僅保留安裝的兩個最新工作空間，以便快速保存
在舊裝置上綁定隱藏 DOM 並請求工作時返回。
- 瀏覽器佇列持久化透過伺服器身分隔離並經過驗證
使用者（或啟用實例存取時的匿名主體）。無範圍
v1隊列/進度狀態被丟棄，因為它沒有可靠的所有者；碼頭
模式和迷你位置仍然是共享的設備首選項。
- 每個使用者和規範邏輯工作系列保存一個持久遊標。它
引用目前版本/媒體項目、來源/位置上下文、位置、
持續時間、完成狀態和時間戳記。快速更新被合併並
串行發送；短暫的資料庫繁忙響應收到短暫的抖動
重試。
- 瀏覽器佇列持久性不保留每個曲目的進度。重新載入隊列
元資料從伺服器刷新，而僅適用明確 Resume
持久工作遊標的保存位置。
- 播放器底座支援折疊和展開狀態、佇列視圖、搜尋、
上一個/下一個、跳過控制和播放模式。睡眠定時器是
倒數第二個次要動作；播放速度及相容範圍分享
最終的更多菜單。
- 向后和向前搜索默认为 10 和 30 秒。設定接受
從 1 到 300 的整秒值，並將它們儲存在每個伺服器和使用者中
瀏覽器。相同的值驅動播放器按鈕、鍵盤快速鍵、
瀏覽器媒體會話操作和 Android 媒體控制。
- 緊湊播放保留行動裝置和桌面上的頁面空間，以便最終操作
沒有被覆蓋。 PWA 更新通知堆疊在 Compact Dock 上方。
- 移動完整播放使用每一側的邊到邊安全區域。底部
控制保留至少 44px 觸控高度和附加主頁指示器
分離。
- 玩家時間渲染限制為每秒約兩次更新。安卓系統
橋合併待定狀態並通常校準本地位置
五秒鐘，同時暫停、搜尋、追蹤和速度變化仍然立即發生。
本機構建僅使用 Android 媒體會話並停用背景模糊；
瀏覽器版本保留了瀏覽器媒體會話整合。
- 緊湊的元資料使曲目標題和圓圈可見，回落到
沒有可用圈子時的作品標題。兩行滾動為一體
測量組並在循環之間的原點短暫暫停，
減少運動支持。
- 緊湊的相對拖曳搜尋將全寬拖曳映射到軌道的 20%，
限制在 20 秒到 10 分鐘之間，然後將結果限制在
可播放時長。
- 佇列行在選項選單中放置上移、下移和刪除
選擇後、退出時或外部互動時關閉。滿溢
佇列標題滾動而不調整播放器大小。
- 文字歌詞包括 LRC、SRT、VTT 和純文字 sidecar。一種化合物
`Track.mp3` 首選 sidecar，例如 `Track.mp3.vtt`，然後是
相同主幹文件，然後規範化名稱匹配。
- 如果多個歌詞檔案匹配，歌詞面板會顯示明確的選擇
而不是依賴資料庫行順序。明顯通用的同目錄
諸如 `lyrics` 或 `subtitle` 之類的名稱可能會被該資料夾中的曲目共用。
- 工作細節音訊行公開相同的自動和明確的歌詞選擇
無需先播放。選擇持久性工作更新任何
立即匹配排隊的曲目；保留僅遠端預覽選項
暫時的。重複的檔案名稱包括其相對目錄路徑。
- 擴展播放器歌詞控制透過隱藏的定時行預覽循環，
和完整歌詞模式。隱藏是預設設置，可以為封面提供更多空間。
沒有符合歌詞的曲目會使控制項保持停用狀態並且不會渲染
空歌詞佔位符。預覽從以下位置取得其可見行數
可用高度並儘可能保持活動時間線居中。

經過身份驗證的用戶的明確歌詞選擇儲存在每個音訊媒體中
物品。該首選項針對歌詞媒體項目而不是具體文件
位置，因此來源替換可以選擇另一個可用位置。 `Auto`
清除覆蓋並恢復確定性匹配；無法保存的
選擇會回退而不刪除首選項。

## 遊標邊界

只有明確的 Resume 才會套用保留的位置。它針對遊標的版本
和媒體項目，嘗試儲存的位置，然後使用目前的來源優先權。
直接曲目選擇從零開始。切換或退回到另一個
活動播放期間的位置保留目前記憶體中的時間，而無需
重讀遊標。

遠端預覽回放不應保留遊標，直到遠端工作完成
已同步至本機媒體記錄。

## 首選地點

播放應該優先選擇持久的本地文件，然後是快取文件，然後是遠端串流
可用時的位置。源中斷不應破壞現有的可用資源
本機或快取播放。
