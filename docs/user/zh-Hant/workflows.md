# 工作流程

工作流程讓後端的各項操作可以被檢視。

## 使用者介面

- **操作** 列出管理員手動啟動的項目，並依用途分組：**媒體庫**（掃描本機媒體庫、重新整理本機作品檔案與同步作品中繼資料）、**目錄同步**（目錄同步預製項目）與 **遠端來源**（取得與檢查作品在來源上的存在）。沒有自訂工作流程編輯器。
- 每個操作佔一列：名稱、它自動啟動的方式、狀態與執行控制項。名稱下的一行列出它的自動啟動方式，例如 **啟動時**、**監視資料夾中** 或 **每 6 小時**，並附上下次排程執行的時間；所有觸發器都關閉時顯示 **自動執行已暫停**。只以手動執行的操作沒有這一行。狀態顯示 **從未執行**、**正在啟動**、**排隊中**、顯示進度的 **執行中**，或最近一次執行如何結束及其時間，例如 **成功** 或 **失敗**。**需要審核** 表示該次執行有等待決定的項目。選取狀態即可在活動中開啟該次執行。
- **執行** 會以預設選項啟動操作。該列會立即顯示這次執行。掃描本機媒體庫與重新整理本機作品檔案涵蓋整個媒體庫，因此在執行結束前無法再次啟動。其他操作針對一個目標，例如一個作品、一個社團、一個中繼資料範圍或一個來源，在已有執行時可以為另一個目標啟動執行。這些操作的列會跟隨正在進行的那次執行，並統計其餘的執行；新執行排在另一個執行之後時會給出提示。目標的執行仍在進行時，再次啟動同一目標不會排入第二次執行。由排程、啟動時或另一個瀏覽器發起的執行，也會以同樣的方式顯示在其操作上。需要輸入的操作，例如作品代碼或社團，會顯示 **執行…**，它會開啟其選項。
- **選項** 會在該列下方開啟一句關於該操作用途的說明與 **全部執行**、操作的執行選項（附有自己的 **執行**）以及觸發器。同一時間只會開啟一個操作。手機顯示相同的清單。
- 有執行需要處理時，操作頂部會有一行說明數量，並在活動中開啟它們。
- **活動** 是執行記錄，與操作同在 **管理** 群組。分頁可選擇清單：**全部**、**正在執行**、**需要處理**、**失敗** 與 **歷史記錄**；正在執行與需要處理會顯示其中的執行數量。選單可將清單限縮到單一工作流程，搜尋欄位則可依工作流程名稱、作品代碼、社團或來源尋找執行。每一列都會顯示狀態、執行編號、觸發方式與經過時間。選取某一列即可開啟該次執行的詳細資料：開始與結束時間、持續時間、觸發方式、步驟、候選項目、執行操作，以及收合起來的執行事件 **診斷日誌**。寬螢幕會把詳細資料顯示在清單旁；其他情況下詳細資料會取代清單，**返回執行記錄** 或頁首的返回按鈕會回到清單。`/runs` 連結與先前指向工作流程內活動的連結會開啟活動，並選取連結所指的執行。
- 活動會列出所有執行，包括有自己頁面的功能所產生的執行：翻譯在[翻譯](translation.md)頁面追蹤，轉寫則在作品的 **管理歌詞 → 轉寫** 中。關於這類執行的通知會開啟那個頁面。

## 誰可以使用工作流程

操作與活動向擁有 `workflows:run` 的帳號開放，也就是貢獻者與管理員（請見[使用者](settings.md#使用者)）。這些帳號會看到相同的定義、預設、觸發器與執行（包括其他帳號發起的執行），並可追蹤其狀態、事件與檔案進度。

- 啟動、設定或排程某個工作流程，需要其各步驟用到的全部權限：追蹤需要 `remote:track`，取得及所有以取得為基礎的批次操作需要 `remote:fetch` 和 `metadata:sync`，掃描、中繼資料類工作流程與排行榜拉取需要 `metadata:sync`，來源檢查需要 `sources:write`。沒有 `metadata:sync` 的貢獻者仍可檢視這些操作，但不能執行或自動化取得路徑。
- 修改、停用或刪除觸發器，需要與建立它相同的權限。
- 可用性監視只負責監視，且每次都會重新整理作品系列中繼資料，因此它的來源設定、監視池與檢查都需要 `metadata:sync`。被監視作品的追蹤與取得由手動啟動，並檢查各自的權限：追蹤需要 `remote:track`，取得需要 `remote:fetch` 和 `metadata:sync`，與遠端來源的批次取得相同。
- 執行的取消、重試與項目審查，可由發起該執行的帳號進行（直接發起，或作為觸發它的觸發器擁有者）。管理員可對所有執行進行這些操作。重試需要發起同樣工作所需的權限。
- 解決後會刪除、封存本機檔案或將其標記為無法使用的項目（例如取得的封存審查）需要 `downloads:manage`。恢復停滯的執行需要 `sources:write`。

## 目前行為

- **取得** 的執行選項針對單一作品代碼與一個已啟用的相容遠端來源。在 **篩選** 下，可選取要排除的副檔名，或輸入以逗號分隔的其他副檔名。預設不排除任何項目。**執行** 會開啟取得預覽；在 **發佈 Fetch** 將該次執行排入佇列之前，請先檢視檔案與目的地。切換語言版本時，排除設定同樣適用。取得為手動執行，沒有自動化觸發器。
- 本機掃描會記錄資料夾探索與本機來源存在狀態，而不必等待中繼資料提供方。中繼資料同步、來源可用性、遠端同步、快取、取得、清理、社團重新整理與遠端批次操作，各自記錄為獨立的工作流程執行。
- 對於單一無歧義的本機作品，當資料夾消失，或其儲存的路徑不再屬於偵測到的資料夾時，掃描會將舊的本機檔案位置標記為缺少。它不會刪除檔案，也不會改變取得的所有權。被移動的資料夾會在開啟時延遲建立索引；代碼出現在多個資料夾中的作品會保留所有這些資料夾，其詳細資料頁面提供整理它們的功能。
- 節點執行會顯示步驟層級的進度。
- 候選項目會提供可供審核的結果。
- 需要處理包含有未解決候選項目、需要使用者決定的已結束執行。一般的部分完成或略過結果會留在歷史記錄中，並保留其警告狀態、摘要與事件以供檢視。
- 頁首的通知中心會顯示 **動態**（你已完成或失敗的工作流程結果，例如取得），以及對工作流程操作人員顯示 **需要處理** 的執行，最新的執行中工作則位於兩者之上。取得通知會開啟本機作品詳細資料，並可為已登入的使用者獨立關閉；需要處理的翻譯會開啟翻譯頁面的 **已停止** 檢視，轉寫則開啟其作品；**開啟活動** 會開啟活動頁面。
- **拉取遠端來源排行榜**、**拉取 DLsite 排行榜**、可用性監視與 **重新整理訂閱** 在[發現](discover.md)頁面執行與設定，學習標籤名稱則自行執行；操作不列出其中任何一項。活動會列出它們的執行，其工作流程選單可將清單限縮到其中一項。無法從頁面建立、編輯或刪除操作。
- 需要處理會彙集未解決的候選項目、中繼資料問題與尚未確認的失敗。解決或忽略已記錄的問題，會清除對應的專屬中繼資料執行通知。其他失敗在未解決的候選項目與可重試的中繼資料失敗處理完之後，可以標記已處理。若一次執行剩下的中繼資料問題只是被回報為無法使用的作品（例如已下架的作品），也可以標記已處理，這些問題仍會保留在中繼資料中。這項確認是依使用者而定的。歷史記錄會保留原本的結果，包括失敗、部分完成與已取消的執行。
- 中繼資料負責待處理作品的復原與 DLsite 代理捷徑。其中的中繼資料同步捷徑會在操作中開啟 **同步作品中繼資料** 的選項。
- 內建的本機掃描與中繼資料同步支援可編輯的間隔觸發器；本機掃描也支援啟動時觸發器。本機掃描不會檢查遠端可用性，也不會同步中繼資料。手動、啟動時與間隔掃描都提供預設停用的 `後續執行`；啟用後，會在掃描結束後排入獨立的中繼資料執行。中繼資料同步沒有啟動時觸發器，因此不會與掃描的後續執行競爭。
- 本機掃描有一個啟動時觸發器與一個固定的資料夾監看器。全新安裝時兩者預設皆為關閉，媒體庫設定會提供開啟它們的選項。監看器可以暫停、繼續，或在增量與完整之間切換，但無法建立、複製、轉換、重新命名或刪除。預設為增量。監看器會登錄探索目錄，以及已辨識作品根目錄之下的每個子目錄，然後動態登錄新的目錄樹。它會在最近一次觀察到事件後等待五秒，忽略 Kikoto 的暫存、備份、垃圾桶，以及已被認領的各來源取得目錄樹，並調和受影響的作品根目錄。被移除的檔案與資料夾會變成 `missing`；資料庫記錄會保留。監看器錯誤、過大的事件批次、根目錄失效與重複的根目錄，都會自動改用完整掃描。取得會直接登錄它自己發佈的位置；手動、啟動時與間隔掃描一律檢查完整的資料樹。執行期間發生的變更最多只會產生一次後續掃描。已暫停期間的事件會被捨棄；離線期間的變更則依賴啟動時掃描。
- **重新整理本機作品檔案** 排在本機掃描之後的第二位。它會為掃描已發現的本機作品資料夾內的媒體檔案建立索引，因此開啟作品時不必即時為大型資料夾建立索引。**增量**（預設）只涵蓋檔案從未被建立索引的資料夾；**完整** 則為每個可用的本機作品重新建立索引。同一時間只會有一次執行在排隊或進行中，再次啟動會回傳目前進行中的執行。它支援會儲存模式的啟動時與間隔觸發器，且預設不附帶任何觸發器。
- **檢查作品在來源上的存在** 位於遠端來源中，排在取得之後。它會向一個遠端來源查詢媒體庫中的作品是否存在，並像檢查單一作品的可用性一樣將結果記錄到每個作品上；它不會新增作品。選項包括來源、作品（預設的 **本機媒體庫** 或 **資料庫中的全部作品**）、篩選（預設的 **無遠端來源**，針對目前沒有任何遠端來源提供的作品，或 **全部**），以及 **每次作品數**（50 到 1000，預設 100）。沒有已啟用的相容遠端來源時，其選項會顯示設定來源的提示，取代表單。每個作品在來源上查詢一次。符合的作品多於上限時，會優先檢查此來源從未檢查過的作品，其次是最久未檢查的作品，因此重複執行即可涵蓋整個媒體庫。執行會先以與來源設定中的 **檢查健康狀態** 相同的方式檢查來源，來源無法使用時不記錄任何作品就停止；部分查詢失敗時，該次執行會是部分完成。每個來源同一時間只有一個進行中的執行。它支援會儲存這些選項的啟動時與間隔觸發器，且預設不附帶任何觸發器。執行它需要管理來源的權限。
- 操作的選項以 **執行選項** 表單開頭。表單以一個列作結，其中有 `執行`，當 `執行` 無法使用時，還會顯示原因，例如缺少必填輸入。長表單捲動時，該列會固定在畫面底部，位於手機導覽列與播放器之上。選項只套用於下一次手動執行，並在選項關閉時重設。該列上的 **執行** 使用預設值：本機掃描不附後續執行、本機作品檔案為增量，而中繼資料同步為 DLsite 的所有作品，並以缺少或過期重新整理。
- **全部執行** 會開啟只含此操作執行的活動；在活動的選單中選擇 **所有工作流程**，即可再次顯示所有工作流程。執行的步驟與日誌位於活動中的詳細資料內。
- 可用性監視、**重新整理訂閱**、**拉取 DLsite 排行榜** 與 **拉取遠端來源排行榜** 在[發現](discover.md)頁面設定：監視在那裡保留其來源設定，其監視池是 **監視** 檢視，訂閱重新整理保留其排程，每個排行榜則有各自的拉取排程。活動限縮到其中一項時，會說明它在哪裡設定並連結到那裡。
- 同步社團目錄、同步系列目錄與同步聲優目錄是 **目錄同步** 操作，為依需求執行的預製工作流程。它們的執行選項分為三個區段：**輸入**（目標與目錄重新整理，增量或完整）、**篩選**（發售日期範圍與作品上限）與 **動作**（同步中繼資料、標籤範本，以及針對社團的檢查遠端來源）。在寬螢幕上，這三個區段會並排為欄。社團與系列目標最多接受 20 個以逗號分隔的 ID，其目錄會在篩選之前合併。聲優目標是一位選取的聲優；其目錄會以顯示名稱與已確認的別名，在勾選的遠端來源上重新整理。系列會讀取其已儲存的作品，沒有目錄重新整理。同步中繼資料涵蓋缺少中繼資料的目錄作品（包括尚未在媒體庫中的作品），篩選與標籤也套用於這些作品。所有篩選預設皆為關閉：沒有發售範圍或作品上限時，一次執行會同步每個缺少中繼資料的目錄作品。標籤範本預設同樣為關閉；開啟後即可為同步的作品加上標籤。關閉同步中繼資料時，社團或聲優的目錄同步只會重新整理目錄（並檢查來源）。目錄同步不會追蹤或取得；這請使用遠端來源的作品、發現中的監視檢視或作品的詳細資料頁面。
- 目錄同步預製項目沒有觸發器。若要依排程關注新作，請改為訂閱該社團、系列或聲優；預製項目的觸發器區段會連結到[發現](discover.md)。
- 中繼資料同步會重新整理媒體庫中的作品；指定作品也可以加入媒體庫尚未擁有的作品。其執行選項可選擇 **作品**（所有作品、單一社團、單一聲優，或指定作品）、**中繼資料來源** 分頁，以及 **重新整理內容**（缺少或過期，或所有中繼資料）。所有作品與指定作品預設為 DLsite，並可選擇一個已啟用且具備中繼資料能力的遠端來源。社團只顯示 DLsite。聲優只顯示遠端來源，且在設定並啟用一個之前無法使用。指定作品最多接受 100 個以空格、逗號或換行分隔的代碼，預設為所有中繼資料。使用 DLsite 時，媒體庫沒有的代碼會加入該作品及其語言版本，DLsite 未列出的代碼則計為無法使用；遠端來源只會重新整理已在媒體庫中的作品。選取 DLsite 時，執行選項也會顯示[遠端中繼資料備援](settings.md#遠端中繼資料備援)與[購買特典關聯](settings.md#購買特典)。這些選擇套用於本次執行，重試也會沿用它們。間隔觸發器會為所有作品、單一社團或單一聲優儲存相同的選項；指定作品只能依需求執行，仍保有指定作品的觸發器會在觸發時自行停用。遠端重新整理會保留手動編輯與 DLsite 的優先順序；缺少或過期會檢查所選來源的中繼資料。當沒有已設定且具備能力的已啟用遠端時，來源選擇器與備援控制項會隱藏。
- 工作流程是內建的；使用者無法自行撰寫。從舊版安裝保留下來的自訂工作流程，會在媒體庫設定期間接受檢視，其中完全符合預製項目的可以成為檢視它們的管理員的訂閱，其他的則可以匯出；請參閱[快速開始](getting-started.md)。它們先前的執行會保留在活動歷史記錄中。
- **拉取 DLsite 排行榜** 會在一次執行中拉取每個到期的 DLsite 排行榜，涵蓋它的每一種排序，**拉取遠端來源排行榜** 則每次執行拉取一個遠端來源的熱門清單；請參閱[排行榜](discover.md#排行榜)。兩者都不會把作品加入媒體庫，也不會同步其中繼資料、追蹤、取得或為其加上標籤。曾加上標籤、追蹤或取得作品的熱門收集執行仍可在活動中查看，且無法重試。
- 排隊中或進行中的取得，每個標準作品只會有一個。重複的取得請求會重用該次執行，而不會把同一個作品下載兩次，且每位提出請求的使用者都會收到共用執行的結束通知。
- 取得活動會報告位元組層級的遠端傳輸進度、觀察到的傳輸速率與預估剩餘時間。大小未知的檔案會明確標示，並在得知實際大小之前，隱藏百分比與剩餘時間的顯示。
- 取得執行的詳細資料會列出其檔案。正在下載的檔案固定在最上方，並有自己的進度列，完整清單則標示每個檔案是已完成、等待中，或是該次執行在哪裡失敗或暫停。
- 每次取得執行都以其作品命名，例如 `Fetch RJ00000001`，活動搜尋也可以用作品代碼找到取得。**取得** 分頁會列出取得歷史記錄與步驟，但沒有執行表單：取得一律從作品開始。由批次操作（包括從監視檢視啟動的批次操作）排入佇列的取得，會將該來源記錄為其觸發原因。
- 針對單一作品、社團、系列、聲優或遠端來源的執行會在標題中加上該對象，例如 `同步社團目錄：RG00000000`，活動搜尋也可以用它找到該執行。
- 掃描絕不會把它看不見之處的作品標記為缺少：未掛載的資料資料夾或離線的儲存池、比掃描深度更深的資料夾、無權讀取的資料夾，以及 NAS 系統與作業系統所新增的資源回收筒與快照。掃描未掛載的標準媒體庫會失敗且不會變更任何內容；略過離線儲存池或無法讀取的資料夾的掃描則會以部分完成結束，並指出其名稱。
- 掃描、檔案清單與資料夾監看會略過資料夾 `@eaDir`、`#recycle`、`#snapshot`、`__MACOSX`、`.Trash-*`、`$RECYCLE.BIN`、`System Volume Information` 與 `lost+found`，以及檔案 `._*`、`.DS_Store` 與 `Thumbs.db`。位於這些資料夾內的作品資料夾絕不會被發現為作品。已記錄在資源回收筒、快照、`.Trash-*`、`$RECYCLE.BIN`、`System Volume Information` 或 `lost+found` 資料夾內的作品資料夾會保持其狀態。`@eaDir` 與 `__MACOSX` 只保存中繼資料，從不保存你的檔案：記錄在其中的資料夾不是作品的資料夾，其檔案絕不會加入作品，能看見它的下一次掃描會將其標記為遺失。掃描讀取的作品資料夾中的這些資料夾與檔案不是作品的檔案，媒體庫中列出的這類檔案會被掃描標記為遺失。
- 當 FFprobe 無法讀取某個媒體檔案（例如已損毀的檔案）時，Kikoto 會針對該檔案的目前版本記錄這一情況，並停止在背景探測它。逾時或被中斷的探測不會記錄任何內容，掃描發現檔案變更後會再次探測。
- 位於未掛載磁碟上的作品仍保留在媒體庫中。它們的卡片顯示 **本機 · 離線**，作品的本機檔案會說明磁碟未掛載。在磁碟重新掛載之前，這些檔案無法播放、下載、編輯或刪除，**管理檔案** 會把這樣的資料夾顯示為離線，且不會從中取用任何檔案。磁碟恢復後，無需掃描，檔案即可重新使用。

## 限制

- 重試與檢查點復原只適用於明確宣告其工作可復原的工作流程系列；任意失敗的節點無法單獨繼續。
- 工作程序在 Kikoto 程序內執行，因此排隊中的工作只有在該程序執行時才會有進展。不支援分散式或多執行個體執行。
- 正常的服務停止會把執行中且可復原的工作放回佇列，而不會耗用其重試額度。當機、強制終止或租約逾期後的復原，受各工作的重試額度所限制。手動的過期執行復原，會將被中斷的不可復原工作標記為失敗，以供檢視。
