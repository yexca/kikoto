# 工作流程
[English](../en/workflows.md) · [簡體中文](../zh-Hans/workflows.md) · [繁體中文](../zh-Hant/workflows.md) · [日本語](../ja/workflows.md) · [한국어](../ko/workflows.md)

工作流程使後端操作變得可檢查。

## 使用者介面

- 工作流程：內建定義（含預製的關注工作流程）及其觸發器在
選定的定義中管理，不再提供自訂工作流程編輯器。
- 活動：互斥的運作、審核、失敗和已完成視圖。

## 當前行為

- 關注社團、關注系列、關注聲優是預製工作流程。目標、篩選、動作、Fetch 上限和標籤模板直接顯示在工作流程標題下方的執行選項中，點擊標題右側的 **Run** 即可執行；觸發器彈出框預設使用上方的值，啟用「自訂執行選項」後可單獨覆寫。元資料同步沒有 Startup 觸發器。僅同步中繼資料不需要來源；Track 和 Fetch 需要已啟用的相容遠端來源，Fetch 還需要下載管理權限並給出明確的檔案數、大小和剩餘空間上限。「僅新作品」會略過媒體庫中已有的作品，標籤模板留空則不加標籤。自動執行只支援已儲存或增量的社團目錄重新整理，完整重新整理僅限手動。

- 本地掃描記錄資料夾發現和本地來源存在，無需等待
對於元資料提供者。元資料同步、來源可用性、遠端同步、
快取、取得、清理、循環刷新和批次遠端操作單獨記錄
工作流程運作。
- 對於明確的本機工作，掃描會標記舊的本機檔案位置遺失
當資料夾消失或其儲存的路徑不再屬於
  detected folder. It does not delete files or change Fetch ownership. A moved
資料夾開啟時會延遲索引；重複程式碼資料夾保留在「審閱」中。
- 節點運行公開步驟級進度。
- 候選人公開可審查的結果。
- 審核包含終端運行，其中未解決的候選者需要用戶
決定。常規部分或跳過的結果保留在“已完成”中並保留
它們的警告狀態、摘要和供檢查的事件。
- 標題通知中心結合已完成或失敗的審閱項目
獲取結果。獲取通知打開本地工作詳細信息，可以
為登入用戶獨立解除。
- 定義列以固定順序列出內建工作流程，預製的關注工作流程排在收集器之後；
頁面上無法新增、編輯或刪除定義。
- 內建本地掃描、元資料同步、遠端流行、DLsite流行
工作流程支援可編輯的間隔觸發器；本地掃描和兩個熱門
收集器也支援啟動觸發器。元資料同步沒有啟動觸發器，
避免和掃描後續執行競爭。本地掃描船
使用預設啟動觸發器，並且不檢查遠端可用性或
同步元資料。手動、啟動和間隔掃描會暴露
預設停用 `Follow-up run`；啟用它排隊一個獨立的
掃描完成後運行元資料。
- 本地掃描還附帶一個固定的、啟用的資料夾觀察器。可以暫停，
已恢復，或在增量和完整之間切換，但無法創建，
複製、轉換、重新命名或刪除。增量是預設值。這
觀察者註冊發現目錄和下面的每個後代目錄
一個已識別的工作根目錄，然後動態註冊新的目錄樹。它
在最近觀察到的事件後等待五秒，忽略 Kikoto 的
暫存、備份、垃圾和按源獲取樹，並協調
影響工作根源。刪除的檔案和資料夾變成`missing`；資料庫
記錄被保留。觀察者錯誤、事件批次過大、根
失效和重複根自動使用完整掃描。拿來
直接註冊自己發布的位置；手動、啟動和間隔
掃描總是檢查完整的資料樹。主動運行期間的變化
最多產生一次後續掃描。暫停的事件被丟棄；離線
更改依賴預設的啟動掃描。
- 遠端和DLsite流行的集合表面編輯標籤模板
目前值預覽、完整的工作流程特定變數清單以及
當呈現的標籤超過 40 個字元時明確警告。手動運行
根據要求擴展模板；自動觸發器將其存儲不變並且
在調度時將其擴展。遠端自動收集僅跟踪，因此
無法繞過取得大小和磁碟保留保護措施。
- 每個工作流程的標題右側都有 `Run`。有執行參數的工作流程會在標題正下方的執行選項中
直接顯示輸入、標籤預覽，無需開啟對話框；選項只套用於下一次手動執行。本地掃描在此顯示
後續同步選項，沒有執行參數的內建工作流程只顯示執行操作。可用性監視在相同位置顯示已儲存的
設定，`Run` 會先儲存未儲存的變更再排入檢查。
- 使用者自建的自訂工作流程、DAG 編輯器、斜線指令與定義執行對話框已移除。
升級時會刪除既有的使用者定義及其觸發器，其執行紀錄仍保留在 Activity 歷史中。
- DLsite熱門合輯支援24小時、7天、30天、全年語音
排名。近期可限於30天內發布的作品；
年度運行選擇一個明確的年份並預設為包含以下內容的模板
`{year}`。運行同步元資料並附加預覽的使用者標籤，無需
替換現有的用戶標籤。
- 排隊或正在運行的 Fetch 對於每個規範工作都是唯一的。重複獲取
請求重複使用運行的內容，而不是下載相同的作品兩次，並且每次
請求用戶收到共享運作的終端通知。
- Fetch 的 Activity 顯示位元組層級的遠端傳輸進度、實測傳輸速度與預估剩餘時間。
  尺寸未知的檔案會明確標示，在實際尺寸確定前不顯示百分比與剩餘時間。

## 當前限制

- 重試和檢查點恢復僅適用於明確
宣布他們的工作可以恢復；任意失敗的節點無法在
隔離.
- 工作人員在 Kikoto 進程內運行，因此排隊的作業只有在
該進程正在運行。分散式或多執行個體執行不是
支持。
- 重新啟動和過期租約恢復受每個作業的重試預算的限制。
手動陳舊運行恢復標記已中斷的不可恢復工作失敗
檢查。

Workflows 右上角的 Activity 開啟桌面面板或手機底部面板。執行中的工作顯示在上方，下方分為 **Needs attention** 和 **History**。待處理候選項、中繼資料問題與未確認失敗進入前者；已解決的中繼資料執行提示會解除，其他失敗可由各使用者確認。History 保留原始執行狀態。中繼資料集中處理作品問題與中繼資料設定，並提供同步捷徑。

Activity 僅顯示目前工作流程的工作與計數，切換流程會更新清單。每筆紀錄顯示狀態、執行編號、觸發方式與耗時。點擊 Recent runs 或紀錄即可在同一面板查看開始與結束時間、耗時、步驟、候選項，以及預設收合的診斷日誌。獨立 Full Activity 頁面已移除，舊連結與通知會開啟所屬流程的 Activity。
