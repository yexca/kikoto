# 設定
[English](../en/settings.md) · [簡體中文](../zh-Hans/settings.md) · [繁體中文](../zh-Hant/settings.md) · [日本語](../ja/settings.md) · [한국어](../ko/settings.md)

設定公開每個使用者的帳戶控制和瀏覽器本地外觀以及
播放首選項。實例和使用者管理仍處於維護階段。

## 目前設定

- 更新經過驗證的使用者的顯示名稱。
- 驗證目前密碼後更改帳戶管理使用者的密碼
密碼並確認更換。
- 保持使用者名稱和角色可見但唯讀。
- 淺色、深色和系統外觀首選項。
- Anthropic、OpenAI、Apple 和 Google Material Design 風格偏好。
- 原色、石墨色、鈷色和虹膜顏色偏好。
- 向後和向前搜尋間隔。它們預設為 10 和 30 秒，
分別接受從 1 到 300 的整秒值。

## 帳戶邊界

更改密碼會保留目前會話並撤銷使用者的其他會話
會議。從維護中重置管理員密碼會撤銷每個
目標使用者的會話。角色、啟用狀態、使用者名稱和使用者生命週期
管理不是自助帳號設定。

配置的 root 帳戶無法在「設定」中變更其密碼。它是
憑證由`KIKOTO_ROOT_PASSWORD`管理；改變那個環境
值並重新啟動 Kikoto 會替換儲存的 root 密碼並撤銷其
現有會話。其他超級管理員仍然受帳戶管理，並且可以
正常更改自己的密碼。

演示模式使帳戶支援的設定保持唯讀狀態。外觀及播放
控制項仍然可用，因為主題模式、樣式、顏色和搜尋間隔
是瀏覽器本機首選項，不會修改演示伺服器資料。回放
首選項由伺服器身份和經過身份驗證的使用者隔離，或由
啟用匿名存取時的匿名主體。

## 維護組織

維護分頁採單行橫向排列，窄螢幕可橫向捲動。已移除 Overview；來源管理員預設進入 Library，僅有使用者管理權限時進入 Users。舊 Paths、Access 連結分別轉到 Library、Users。

- 維護以簡潔的管理描述打開，而不是
重複可編輯的配置值作為摘要統計資料。詳細資料選項卡
僅保留操作指標，例如來源健康狀況、推薦
遙測和託管快取使用情況。
- Library 整合本地掃描設定、遠端來源和唯讀儲存路徑。
- 生產和開發中的超級管理員可在 Users 內管理執行個體存取權限。
  Anonymous Library browsing and playback default to disabled; changing the
開關應用於生產訪問邊界並建立審核條目。
開發仍然以 root 身份驗證每個請求，因此設定仍然保留
在那裡可見和可編輯，無需建立匿名開發會話。
- 每個啟用的遠端來源都有明確的運作狀況檢查操作。結果是
透過自動探測器使用的相同來源健康狀態持續存在。
- 遠端來源預設為相容的公共儲存主機。來源
配置可以啟用**限制出站主機**以僅允許API，
公共站點、後備以及精確或 `*.example.invalid` 的可編輯列表
公共主機模式。
- 目錄規則和推薦偏好已移至 Settings，依帳號儲存。推薦分頁中摺疊的 **我的推薦活動** 只統計目前使用者過去 30 天的資料。
- 遠端來源以精簡清單呈現健康狀態、主機、健康檢查與立即儲存的啟用開關。**新增來源** 只需輸入一個位址：Kikoto 會依序探測原位址、其來源網域與常見的 `api.` 子網域，自動填入 API URL、公開網站與名稱；未偵測到時會展開 **連線詳細資料** 供手動填寫。
- Cache & Fetch 只保留設定：播放快取策略、傳輸安全與摺疊的下載節奏，變更後才可儲存。每個檔案的遠端媒體上限預設 100 GB，失敗或取消的 Fetch 暫存保留 7 天，轉碼快取上限預設 5 GB。快取內容改在 **清理** 分頁管理。
- Library 中的儲存路徑預設摺疊，是唯讀的，顯示已解析的資料根、快取根、預設值
快取/保存預覽，以及按來源儲存預覽。遠端來源配置
顯示相同的已解決範例，而不是公開路徑範本編輯器。



## 清理

**清理** 是設定中位於 Cache & Fetch 之後的管理員分頁（`/settings?tab=cleanup`）；快取部分需要 `downloads:manage`，資料庫部分需要 `sources:write`。頁面包含轉碼快取與託管媒體快取的用量與清理，以及資料庫記錄清理：磁碟上已確認不存在的作品資料夾與本機檔案（連同因此變空的曲目項目與本機可用狀態）、孤立中繼資料快照、未使用的來源標籤、過期工作階段、已關閉通知、超過 90 天的工作流程歷史與推薦訊號、不再使用的推薦快照。個人標籤、含審閱、Fetch 記錄或中繼資料問題的執行，以及每個工作流程的最新執行都會保留；清理需要確認並寫入稽核記錄，不會刪除媒體檔案。資料資料夾遺失或為空時會暫停路徑檢查。**沒有任何來源的作品** 連到中繼資料的 **無可用來源** 檢視；**壓縮資料庫** 會把閒置頁還給磁碟。

## 中繼資料

側邊欄的 **中繼資料** 位於 **工作流程** 下方。橫向分類為 **全部**、**需要注意**、**中繼資料問題** 和 **無可用來源**。全部包含所有已儲存的作品系列，包括沒有待處理問題的記錄；其他分類依注意原因篩選。各分類共用搜尋、分頁、封面、選取和受影響版本詳情。

右上角的 **中繼資料設定** 在對話框中開啟，關閉後保留清單與篩選條件。**中繼資料同步** 前往現有的同步工作流程，選擇範圍後再執行。

選取作品後點擊**重試中繼資料**，按鈕顯示適用數量；也可在詳情中重試指定版本，包括先前被回報為不可用的作品。失敗時保留既有資料與人工覆寫內容。**檢查來源**只處理所選無來源作品；**刪除本地資訊**僅在「無可用來源」篩選中提供，需要確認，伺服器重新檢查來源狀態並保留媒體檔案。

Activity 和 Workflows 保留原有功能。待處理按鈕會開啟作品維護並篩選該次執行尚未解決的中繼資料問題，可顯示全部待處理作品以取消執行篩選。復原不會修改其他使用者的 Activity 審核。中繼資料處理需要 `metadata:sync`；來源檢查、刪除以及來源和語言設定需要 `sources:write`。**中繼資料設定** 對話框管理語言優先順序、來源請求語言與目錄新鮮度。同步捷徑開啟既有 Workflows，不重複工作流程設定。舊 Maintenance 連結會重新導向此頁。

中繼資料頁面的正式位址為 `/metadata`。舊 `/work-management` 連結仍可使用，並保留篩選或設定情境。首次同步失敗及存在待處理中繼資料問題的結果入口會開啟問題清單；沒有工作流程權限的使用者進入不限定執行的清單。執行診斷仍可在 Workflows 的 Activity 中查看。

Settings 現在僅有 Account、Playback 和 Recommendation。Playback 內的目錄偏好與推薦設定按帳號儲存於伺服器，跨裝置共用；未自訂時沿用現有執行個體預設值。儲存推薦設定會更新目前頁面的推薦工作階段，其他已開啟頁面保留原快照。Maintenance 僅保留 Library、Cache & Fetch、Users，全站推薦統計位於 Library 的摺疊區域。外觀設定僅保留右上角入口，地球圖示表示跟隨瀏覽器或裝置語言。Demo 模式不能修改帳號偏好。
