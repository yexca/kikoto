# Speech transcription

Speech recognition services and the durable transcription tasks that write fallback lyrics.

The `asr_providers` setting stores administrator-configured speech recognition services that speak the OpenAI-compatible transcription protocol: OpenAI, a local deployment, a Kikoto Helper, or a custom service. A local deployment or Kikoto Helper on the server's own machine stores only a port; its origin is the server's host gateway and a request-body address is discarded. Another machine and the custom service store an origin without a path. Each service declares an external or private boundary and the same independent receive maximum as an LLM provider; changing the preset, location, port or origin clears the key and discovered models. A service offers up to 32 enabled models with one default, and a transcription records the model it requested; its configuration digest is built like an LLM provider digest. Discovery from the OpenAI preset suggests only Whisper models, the models that return segment timestamps. Discovery from a Kikoto Helper reads its installed models and their names from `/kikoto/v1/info`, together with the languages each model hears, one code, `multilingual` or a list, and the `translation` direction of a model that writes its target language from source speech, all stored as lyrics language tokens. A helper model is declared: with a direction it translates, and otherwise it transcribes the languages it hears, any language when it is multilingual or names none. A translation token outside the lyrics languages is stored empty and matches no request, and a heard language outside them is left out. Every other model, from another service's discovery or entered by hand, has unknown capability. The configuration digest of a transcription includes what the service declares for its model, so a fetch that changes a model's direction or languages stops its queued transcriptions as `provider_changed`. A [helper rejection](llm-translation.md#llm-translation) for a model that is not ready, cannot start, ran out of memory or does not write the requested language fails the chunk as `service_not_ready`, `service_start_failed`, `service_out_of_memory` or `unsupported_language_pair`. Keys stay server-side, and saves advance a revision.

`asr_transcription` is the durable task, checkpoint and result of one transcription of one local audio track. It records the requester, the audio item and the local location read, the active work folder holding that file, the service, model and a digest of its configuration, the audio language spoken in the track, the declared lyrics language (empty for every language), and the file version of the audio. A request is refused as `asr_language_unsupported` unless the model writes the lyrics language from the audio language: a translating model only its discovered direction, a transcribing model only a language it hears, and a model of unknown capability any lyrics language from a chosen audio language. Detected speech, an empty audio language, writes only fallback lyrics, and never with a translating model. One active task exists per audio item; a repeated request joins it. The job decodes the file with ffmpeg into 16 kHz mono PCM chunks of at most five minutes, cut at the quietest 300 ms of a chunk's last minute, and sends each as WAV with `response_format=verbose_json`, the audio language as `language`, and, when the languages differ, the lyrics language as `target_language`. Before each chunk it rechecks the requester's permissions, the service digest, the [LLM content policy](llm-translation.md#llm-translation) for the work, and the audio location and file version. After decoding and immediately before upload, the job rechecks permissions, service configuration and content policy. The chunk's state is `requesting` while it is sent. When the service reports the language it wrote, the job compares its base language with the lyrics language's, so `zh` or `chinese` matches `zh-cn`, and a mismatch fails the task as `output_language_mismatch` without keeping that chunk; otherwise its segments are clamped to the chunk, offset onto the track's timeline, and committed as cues with the next offset before the job continues or yields the executor. A task found `requesting` after a restart fails as `upstream_result_unknown`, so only an explicit retry resends that chunk.

A finished task stores its WebVTT text, at most 2 MiB, as `ready`. Acceptance moves it to `publishing`, stages the file on the work folder's storage pool, adds it to the language's lyrics folder under the track's path inside the work folder (`lyrics_kikoto/<language folder>/<track path>.vtt`, then numbered names when a different file holds that name), indexes the work folder, and assigns the file to the track in the task's language with origin `transcription` before recording `accepted`. An interrupted publication stays `publishing` and completes on the next acceptance; a file already published with the same content counts as published. A rejected task drops its text. Demo lists fixed example services for inspection and refuses speech recognition configuration and transcription.
