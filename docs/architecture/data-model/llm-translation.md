# LLM translation

LLM provider and content-policy settings, translation previews and accepted translations.

The `llm_providers` setting stores administrator-configured origins and the OpenAI-compatible, native Anthropic, Ollama or Kikoto Helper protocol. Each endpoint declares an external or private data boundary and an independent `maxContentClass` receive maximum, defaulting to `safe`. API keys stay server-side; changing origin, preset or Ollama location clears the old key and discovered models. A provider offers up to 32 `enabledModels` in display order, one of them the `defaultModel`; discovered models are only suggestions. Provider saves advance a revision. A translation names one enabled model or takes the default, and its task and preview keep the resolved model. Their configuration digest covers the connection, data boundary, receive maximum, request settings and that model, but not the name, revision, default or other enabled models, so only a change that affects where or how the request goes, or removing its model, invalidates queued work and cached tag names. Same-machine Ollama derives its origin on the server and discards a request-body address. A Kikoto Helper provider has a `scope`: on the server's own machine it stores only a `port` and derives its origin from the host gateway the same way; on another machine it stores an origin. Its model discovery reads the helper's `/kikoto/v1/info`, which names the one translation model the helper runs and its language `pairs`; a helper without an installed model is refused as `service_model_not_installed`, and one that reports `agreement_required` for its model is refused as `service_agreement_required`. The discovered model records those pairs as language tokens; `any`, an absent field and every other provider's models leave a model unrestricted. A restricted model translates only a declared direction from the language of the work's original edition, and an unknown original language matches every declared source. `GET /api/llm/translation-models?workId=` names each restricted model's targets for that work as `modelTargets`. A synchronous translation or a queued batch whose direction the model does not declare is refused as `llm_unsupported_language_pair` before any task is queued or request sent, and a queued task whose model no longer declares it stops as `unsupported_language_pair` without a request. Its translation sends each request's fields to `/kikoto/v1/translate` with the target language and the language of the work's original edition when known, and the helper formats prompts and batches lines for its model. A helper rejection that retrying unchanged does not fix names its cause from the error's `code` and optional `reason`, never its message: `unsupported_language_pair`; `service_not_ready` for a model that is not installed or not found; `service_out_of_memory` for a `start_failed` whose reason is `out_of_memory`, where the installed model ran out of video or system memory while loading; `service_agreement_required` for `abliterated_agreement_required`, a model whose risk notice is not accepted in the helper; and `service_start_failed` for any other start failure. A synchronous translation reports the same causes prefixed with `llm_`, and a queued task fails with them and can be retried from its run once the helper is fixed. All LLM requests use the shared outbound policy, including the configured private-origin exception, DNS pinning and refusal of redirects. Discovery has a 20-second timeout. Each translation request, including the wait for response headers, is bounded by the provider's `requestTimeoutSeconds`, 30 to 3600 seconds and 10 minutes when unset. An Ollama request sends a JSON Schema `format` that fixes the supplied keys, requires non-empty strings and sets each array's `minItems` and `maxItems` to its input length. An Ollama provider may also set `ollamaContextLength`, sent as `options.num_ctx` (512 to 1048576), and `ollamaDisableThinking`, sent as `think: false`. The server validates the decoded result either way. Two operations may run concurrently, responses are limited to 2 MiB and encoded request bodies to 128 KiB.

The `llm_content_policy` setting stores a revision, stable tag IDs with explicit actions, literal keyword rules, remote-lyrics opt-in and the default-off `llmTranslationTextOnly` option. Validation rejects the whole invalid or excessive configuration. Keyword rules require explicit unique identities and field scopes; tag rule identity is `tag:<id>`. Matching never recovers an action by keyword spelling. The [content safety policy](../../user/en/settings.md#content-safety-policy) defines metadata and translation-text assessment scopes and precedence. `contentpolicy.Assess` always evaluates metadata for ASR, while LLM composition selects `AssessText` only when the translation option is enabled. Text assessment records `mode: translation_text`, its checked fields and applicable keyword-rule count; these travel with prechecks and durable previews. Translation checks use the complete selected source before chunking or per-user tag candidate reuse at preparation, precheck, send and acceptance boundaries. The shared receive check refuses unknown, blocked and invalid classes and maxima independently of the service data boundary. An omitted receive maximum defaults to `safe` when creating a service; a partial update keeps the saved maximum. Service configuration and normalized policy digests bind pending sends and previews, including changes to assessment mode. The absent or false translation option has the same digest representation. Declared boundaries and maxima are routing policy, not a provider compliance or account safety guarantee.

The `llm_service_notice` setting records the accepted version of the external service notice, the administrator who accepted it and when. LLM provider, ASR service and content policy saves and model discovery are refused until the current version is accepted; deleting a service and using a configured one are not.

`llm_translation_preview` retains source and translated text, user, work, target language, fields, expiry and digests of source input, policy revision and provider configuration. It contains no API key. No request creates a preview: Translate with AI applies its results through [acceptance](translate-with-ai.md#translate-with-ai). Acceptance checks current permissions and re-evaluates policy and source hashes in a transaction; reviewed tokens cannot apply twice or belong to another user or work. Rejection and invalidation retain review status. Accepted fields live in `work_llm_translation` separately from original snapshots and manual overrides. Source-field changes retire the corresponding translation, and `work_llm_translation_review` retains values for replacement, revocation and restoration against matching source input. Ordinary metadata sync preserves accepted values.

Tag candidates in `metadata_tag_llm_candidate` reuse the same concept, target
language, source text, author and configuration/policy digests across works.
They have no presentation effect. Confirmed names live in
`metadata_tag_llm_name` with source text, provider, model and author. Known
manual, provider and matching accepted names are reused. Confirmation changes
shared language names without creating tags or changing work membership.
Manual, dictionary and provider names precede LLM names. Risk evidence retains
base IDs, hidden tags and every concept in a merge component independently of
displayed names.

`llm_lyrics_asset` keeps the confirmed result, original lyrics location, audio item, target language and source hash before publication. The audio item must have an available local file; the deepest active work folder holding that file is the destination, and a request naming another folder is refused. Publication follows [speech transcription](speech-transcription.md#speech-transcription): the file is staged on the work folder's storage pool and added to the target language's lyrics folder under the track's path with the source file's extension (`<language folder>/<track path><extension>`, then numbered names when a different file holds that name), the work folder is indexed, and the file is assigned to the track in the target language with origin `translation`. The original lyrics file is never changed. Failed publication stays `publishing` and completes from the retained result without another model request; a file already published with the same content counts as published. Only an explicitly selected file is read; remote reads require opt-in and remote-fetch permission. Templates preserve timing and order for LRC, WebVTT, SRT, standard ASS Dialogue and plain text. Input and output are each bounded to 128 KiB, 4,000 source lines and 4,096 bytes per text line. Chunked requests check complete sending text first.

`llm_translation_task` rows belong to `llm_translation` workflow runs, which translated one work for review on its work page. Nothing queues such a run. Its job ends a queued or retried run without a request or a preview: the task becomes `invalid` with `translation_replaced`, the run fails, and a retry of it is refused. Runs expose fixed states and sanitized diagnostics, never credentials, origins, paths or full source text. Demo lists fixed example providers for inspection and refuses LLM configuration and translation. Its translation model list offers those examples, and a work's translation plan reports what the work lacks with every category permitted; the request itself is refused.
